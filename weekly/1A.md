### Why This Course is Challenging

There isn't a follow-up class to this one. If you want to build and publish Flutter apps, this is it. That means I have to cover everything you need to actually ship an app, including things like splash screens and app icons. You can't publish to an app store without those, and if I skipped them you'd finish this class still unable to release anything.

**The goal:** give you everything you need to publish an app.

**GitHub participation matters.** In the lead-up to Projects 1 and 2 especially, we cover the exact pieces you need. The participation repos give you code you can adapt straight into your projects.

### AI Policy

The syllabus covers this, but I want to be clear about the philosophy.

**Projects 1 and 2:** you can use AI tools for reviewing your code, debugging, planning, and deepening your understanding. AI should not be writing your code. These projects are about demonstrating that you understand the fundamentals.

**Project 3:** I open the door to using AI for coding, including agentic tools, as long as you disclose it. By then you should have the fundamentals and can use AI as a productivity tool.

**Why this policy?**

AI is everywhere now, and companies use these tools at increasing rates. Academically they can be excellent for learning if used properly, and they can just as easily become a crutch.

I've seen a sharp increase in AI-generated code and a sharp decrease in student understanding of that code. Industry contacts tell me the tools are only good if you can vet the output. A developer's job is often code-reviewing AI-generated code, and to do that you have to understand the code yourself. That only happens if you spend the time learning how it works.

Ask yourself: "how am I improving my understanding by using this tool?" Having AI explain a difficult concept or find a bug can help. It shouldn't replace learning to read documentation.

**The key rule: disclosure is required.** Using AI to write code without disclosing it is a breach of academic integrity.

## I. Multiplatform Development

### The Problem

Different platforms traditionally require different languages:

- **iOS:** Swift or Objective-C
- **Android:** Kotlin or Java
- **Web:** JavaScript or TypeScript

Building the same app for several platforms means writing it several times.

### The Promise

Write once, deploy everywhere. One codebase that compiles to multiple platforms.

### Why Flutter?

Flutter is the most widely used cross-platform mobile framework.

![Flutter usage statistics](https://people.rit.edu/~jxtadm/presentations/igme-340/week1/flutter-usage.png)

Why we use it here:

- Single codebase for iOS, Android, web, and desktop
- Truly compiled, with no JavaScript bridge like React Native has
- **Hot reload**, so you see changes instantly
- Strong community and Google backing
- The Flame engine for game development, which we use for Project 3

### Three Things, Three Names

These get mixed up constantly, so it's worth separating them now:

| Name | What it is |
|------|-----------|
| **Dart** | The programming language |
| **Flutter** | The framework you build apps in |
| **Material Design** | Google's UI design system, which Flutter uses by default |

Each has its own documentation site. When you're searching for help, knowing which one you need saves a lot of time.

### Course Platform Focus: Android

**Why Android?**

- Works on both PC and Mac. iOS development requires a Mac.
- Free testing on personal devices or emulators
- No paid developer account needed

**About iOS:** Flutter code runs on iOS too, but building and testing requires a Mac, and putting an app on a physical iPhone requires a $99/year Apple developer account. We focus on Android so everyone can participate equally.

You don't need any paid accounts for this course.

Start early anyway, because the earlier you hit a problem the easier it is for me to help.

### Figure out which situation you're in

| Your setup | What to expect |
|---|---|
| **Own laptop**, 16 GB+ RAM, Apple Silicon or a modern Windows machine | Follow Lab 00. You should be fine. |
| **Own laptop**, Intel Mac or under 16 GB RAM | Doable. The Android emulator will be slow, so plan on targeting Chrome instead. Talk to me. |
| **Lab machine only** | Read the [lab machine setup guide](../reference/setup/flutter-lab-machines.md) before you start. There's a specific trap here, see below. |
| **No machine sorted yet** | Come talk to me this week. Don't wait. |

### If you're on a lab machine

Do **not** install Flutter to your network `Z:` drive. It does not work reliably. Install to a local drive, for example `D:\flutter`, and set your PATH to that.

### A cheap Android phone is a real upgrade

Not required, and there's no penalty for using an emulator all semester. But an unlocked budget Android phone runs about $80 to $100, and running your app on actual hardware is both faster than an emulator and considerably more satisfying.

To use one, put it in developer mode: **Settings → About phone → tap the build number seven times.** That unlocks USB debugging, and once it's plugged in your phone shows up as a deployment target.

### The backup that always works

If your emulator won't cooperate, you can target **Chrome** instead and everything in this course still works. Keep that in your back pocket.

**Tell me early if you're stuck.** Week one is easy to fix. Week ten is not.

## III. First Dart

We're writing Dart on day one. Open [DartPad](https://dartpad.dev), no setup needed.

### Hello World

```dart
void main() {
  print('Hello 340');
}
```

Every Dart program starts with `void main()`. If you've written C or Java, this looks familiar. Every Flutter app has one too.

### Basic Types

```dart
void main() {
  int lives = 3;
  double health = 87.5;
  String player = 'Mario';
  bool isAlive = true;

  print(lives);
  print(health);
  print(player);
  print(isAlive);
}
```

Dart is typed. Unlike JavaScript, you declare what a variable holds.

**Differences from JavaScript worth noting:**

- Only two number types: `int` and `double`. No `float`, no `long`.
- `String` with a capital S
- Semicolons are required

### String Interpolation

Use `$` for a plain variable and `${}` when you need an expression:

```dart
print('$player has $lives lives');
print('Health next tick: ${health - 10}');
print('Uppercase: ${player.toUpperCase()}');
```

No concatenation needed.

This one is worth remembering, because you'll type it inside nearly every piece of text your apps display:

```dart
Text('$player has $lives lives')
```

That's a real Flutter widget. You already know how the inside of it works.

### Saving Your DartPad Work

**DartPad has no save button.** When you finish an exercise, select your code, copy it, paste it into a text editor, and save it as a `.dart` file. That's what you submit.

If you already have Flutter installed locally, you can use VS Code instead. Same Dart, different environment.
