## I. Multiplatform Development

### The Problem
Different platforms traditionally require different languages:
- **iOS:** Swift/Objective-C
- **Android:** Kotlin/Java
- **Web:** JavaScript/TypeScript

Building the same app for multiple platforms means writing it multiple times... or does it?

### The Promise
Write once, deploy everywhere. A single codebase that compiles to multiple platforms.

### Why Flutter?

Flutter is the most popular cross-platform mobile framework:

![Flutter usage statistics](https://people.rit.edu/~jxtadm/presentations/igme-340/week1/flutter-usage.png)

**Why we chose Flutter for this course:**
- Single codebase for iOS, Android, Web, and Desktop
- Truly compiled (no JavaScript bridge like React Native)
- Hot reload for rapid development - see changes instantly
- Strong community and Google backing
- Flame engine for game development (we'll use this for Project 3!)

### Course Platform Focus: Android

**Why Android?**
- Works on both PC and Mac (iOS development requires a Mac)
- Free testing on personal devices or emulators
- No paid developer account needed

**About iOS:** Flutter code works on iOS too, but building/testing requires a Mac and optionally a $99/year developer account. We'll focus on Android so everyone can participate equally.

**Good news:** You don't need any paid accounts for this course!

## II. Variables & Types

Every Dart program starts with `void main()`. Unlike JavaScript, Dart requires type declarations.

### Basic Types

```dart
void main() {
  int myNumber = 42;
  double myDecimal = 3.14;
  String myName = "JP";
  bool isAwesome = true;

  print(myNumber);
  print(myDecimal);
  print(myName);
  print(isAwesome);
}
```

**Key differences from JavaScript:**
- No `float` - use `double` for decimals
- `String` with capital S
- Semicolons are required!

### String Interpolation

Use `$` for simple variables, `${}` for expressions:

```dart
print("Hello $myName");
print("The number is $myNumber");
print("Uppercase: ${myName.toUpperCase()}");
print("Math: ${myNumber + 10}");
```

No string concatenation needed!

### The `var` Keyword

```dart
var score = 100;  // Dart infers this is an int
print(score);

// This would cause an error:
// score = "hello";  // Can't assign String to int!
```

Once `var` sets the type, it's locked. This is different from JavaScript!

### `const` and `final`

Both are immutable (can't change after set), but there's a difference:

```dart
const pi = 3.14159;           // Must be known at compile time
final timestamp = DateTime.now();  // Can be set at runtime

// This would cause an error:
// pi = 3.0;  // Can't reassign const!
```

**Rule of thumb:** Use `const` when the value will never change and is known before the app runs. Use `final` when the value is set once at runtime. Flutter uses `const` everywhere for performance.

## III. Lists

Lists are like JavaScript arrays - ordered collections with square brackets.

```dart
void main() {
  var fruits = ['apple', 'banana', 'cherry'];
  print(fruits);        // [apple, banana, cherry]
  print(fruits[0]);     // apple (zero-indexed)
  print(fruits.length); // 3

  fruits.add('date');
  print(fruits);        // [apple, banana, cherry, date]
}
```

### Typed Lists

```dart
List<String> veggies = ['carrot', 'broccoli'];
```

`List<String>` means only strings are allowed. You'll see `List<Widget>` constantly in Flutter.

### Looping Through Lists

```dart
for (var fruit in fruits) {
  print(fruit);
}
```

## IV. Maps

Maps are like JavaScript objects - key-value pairs with curly braces.

```dart
void main() {
  var player = {
    'name': 'Mario',
    'lives': 3,
    'score': 1000,
  };

  print(player);           // {name: Mario, lives: 3, score: 1000}
  print(player['name']);   // Mario
  print(player['score']);  // 1000

  player['lives'] = 2;     // Modify existing
  player['coins'] = 50;    // Add new key
  print(player);           // {name: Mario, lives: 2, score: 1000, coins: 50}
}
```

**Why this matters:** When you call an API in Project 2, JSON data comes back as Maps.

## V. Functions

### Basic Function

Unlike JavaScript, we declare the return type:

```dart
int add(int a, int b) {
  return a + b;
}

void main() {
  var result = add(5, 3);
  print(result);  // 8
}
```

`int add` means the function returns an int. `void` means no return value.

### Arrow Functions

For one-liners, use arrow syntax (same concept as JavaScript):

```dart
int multiply(int a, int b) => a * b;

void main() {
  print(multiply(4, 7));  // 28
}
```

### Named Parameters - THE BIG ONE

This is crucial for Flutter! Curly braces make parameters **named**:

```dart
void greet({String? name, String? message}) {
  print('$message, $name!');
}

void main() {
  greet(name: 'JP', message: 'Hello');
  greet(message: 'Hey', name: 'Class');  // Order doesn't matter!
}
```

**Why this is huge:** You specify which parameter is which by name. Order doesn't matter!

### The `required` Keyword

Make a named parameter mandatory:

```dart
void greet({required String name, String? message}) {
  print('$message, $name!');
}

void main() {
  // greet(message: 'Hello');  // ERROR! name is required
  greet(name: 'JP', message: 'Hello');  // Works!
}
```

### Why Named Parameters Matter

This is what Flutter code looks like:

```dart
Container(
  width: 100,
  height: 200,
  color: Colors.blue,
)
```

All named parameters! Now you understand the syntax.

## VI. Classes (Quick Intro)

Flutter widgets are classes. Here's the basic pattern:

```dart
class Player {
  String name;
  int score;

  Player(this.name, this.score);  // Shorthand constructor

  void addPoints(int points) {
    score = score + points;
  }
}

void main() {
  var p1 = Player('Mario', 100);
  print(p1.name);   // Mario
  print(p1.score);  // 100

  p1.addPoints(50);
  print(p1.score);  // 150
}
```

`this.name` in the constructor is shorthand - it automatically assigns the parameter to the field.

When you see `Text('Hello')` in Flutter, that's calling a constructor!

## VII. Key Takeaways

1. **Dart is typed** - `int`, `double`, `String`, `bool`
2. **`var` locks the type** - once set, can't change to different type
3. **`const`/`final` are immutable** - const at compile time, final at runtime
4. **Named parameters `{}`** - you'll use this every day in Flutter
5. **Classes use `this.` shorthand** in constructors
