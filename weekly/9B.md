## What We Covered in Class

In this class, we learned how to navigate between multiple pages in a Flutter app using two different approaches: **MaterialPageRoute** (the traditional way) and **Named Routes** (a cleaner, more maintainable approach). We built upon our clicker game by connecting the main game page, store page, active abilities page, and details page together with proper navigation.

### Part 1: Basic Navigation with MaterialPageRoute

We started by learning how to use `Navigator.push()` and `Navigator.pop()` to move between pages in our app. Flutter automatically manages a navigation "stack" (like a stack of plates) where pages are added on top and removed from the top.

**Key Points:**
- `Navigator.push()` adds a new page to the stack
- `Navigator.pop()` removes the current page from the stack
- Flutter automatically provides a back button in the AppBar when you push a page
- `Navigator.pushReplacement()` replaces the current page instead of stacking (no automatic back button)

### Part 2: Named Routes

Instead of having to reference the actual widget class every time we navigate, we learned how to set up named routes in `main.dart`. This makes navigation cleaner and easier to maintain.

**What We Did:**
- Set up a routes map in `MaterialApp` with string names for each page
- Converted all navigation to use `Navigator.pushNamed()` with route names like `'/active'` and `'/available'`
- Simplified our navigation code significantly

### Part 3: Passing Data Between Pages

We learned how to send data TO pages when navigating, and how to receive data BACK from pages when they close.

**Key Points:**
- Use the `arguments` parameter in `pushNamed()` to pass data (can be an int, Map, or any object)
- Use `ModalRoute.of(context)?.settings.arguments` to receive data in the destination page
- Use `Navigator.pop(context, returnValue)` to send data back when closing a page
- Use `await Navigator.pushNamed()` to wait for and receive returned data

### Part 4: Making the Store Functional

We implemented the buy and remove logic for abilities in the game, using ternary operators to conditionally enable/disable buttons based on whether the player has enough money.

**Key Points:**
- Ternary operator syntax: `condition ? valueIfTrue : valueIfFalse`
- Setting `onPressed: null` disables and grays out a button
- Always call `setState(() {})` after modifying state to update the UI

### Part 5: The State Management Problem

At the end of class, we discovered that when we navigate between pages, they don't automatically refresh to show updated money/modifier values. This is because each page maintains its own state, and popping back to a page doesn't trigger a rebuild. This sets up the need for state management solutions (like Provider) which we'll cover in the next class.

## Key Concepts & Terminology

| Term | Definition |
|------|------------|
| **Navigator** | Flutter's built-in routing and navigation manager that maintains a stack of pages |
| **Route** | Represents a screen or page in your app |
| **MaterialPageRoute** | A route that transitions to a new page with a platform-appropriate animation |
| **Navigation Stack** | The list of pages currently in memory, organized like a stack of plates (LIFO - Last In First Out) |
| **Named Routes** | Routes identified by string names (like '/home' or '/store') instead of widget classes |
| **Arguments** | Data passed between pages during navigation |
| **Ternary Operator** | A shorthand if/else: `condition ? valueIfTrue : valueIfFalse` |
| **setState()** | Method that tells Flutter to rebuild the widget with updated values |

## Part 2: Named Routes (Cleaner Approach)

### STEP 8: The Problem with Current Approach

**Think about it:** Having to remember the page class names (like `AvailableAbilitiesPage()`) every time we navigate is kind of a drag, right? What if we could give pages simple string names instead?

**That's what Named Routes do!** We can define all our routes in one place in `main.dart` and reference them by name (like `'/store'` or `'/active'`).

### STEP 9: Set Up Named Routes in main.dart

In `main.dart`, replace your current MaterialApp setup:

```dart
// OLD WAY - comment this out:
// return MaterialApp(
//   home: MainPage(),
// );

// NEW WAY - use named routes:
return MaterialApp(
  initialRoute: '/',
  routes: {
    '/': (context) => MainPage(),
    '/active': (context) => ActiveAbilitiesPage(),
    '/available': (context) => AvailableAbilitiesPage(),
    '/details': (context) => DetailsPage(),  // We'll use this later
  },
);
```

**What this does:** Creates a map of route names to pages. Now we can reference pages by string names instead of class names.

### STEP 10: Convert game.dart to Use Named Routes

In `game.dart`, replace your navigation code:

```dart
// For the Active list button (Icons.list):
ElevatedButton(
  onPressed: () {
    Navigator.pushNamed(context, '/active');
  },
  child: Icon(Icons.list),
)

// For the Store button (Icons.store):
ElevatedButton(
  onPressed: () {
    Navigator.pushNamed(context, '/available');
  },
  child: Icon(Icons.store),
)
```

**Much cleaner!** We went from 6+ lines to just 1 line per navigation.

**Test:** Save and run - buttons should still work, back button still works. Everything operates the same, just cleaner code!

```dart
Card(

        '/details',
```

```dart
    trailing: ElevatedButton(...),
  )

```

**Key Points:**
- Made onTap `async` so we can use `await`
- `await Navigator.pushNamed()` waits for the page to pop and return data
- The returned value is captured in `message`
- Display it using a SnackBar

## Part 5: Making the Store Functional

### STEP 20: Implement Buy Button Logic

In `available.dart`, replace the buy button's empty `onPressed`:

```dart

  onPressed: abilitiesList[index]['cost'] > money
    ? null  // null disables the button (grays it out)
    : () {
        // Pull current item data
        final currentItem = abilitiesList[index];
        final int cost = currentItem['cost'];
        final int value = currentItem['value'];

        // Deduct money
        money -= cost;

        // Move from store to active list
        activeAbilitiesList.add(currentItem);
        abilitiesList.removeAt(index);

        // Update modifier
        if (currentItem['effect'] == '+') {
          countModifier += value;
        } else {  // multiply effect
          countModifier *= value;
        }

        // Update UI
        setState(() {});
      },

```

**Key concept:** The ternary operator `condition ? value1 : value2` checks if cost > money. If true, returns `null` (disables button). If false, returns the function to execute.

**What this does:**
- Boolean check: if cost > money, return null (disables and grays out button)
- Otherwise, return the function to execute
- Subtract cost from money
- Add item to activeAbilitiesList
- Remove item from abilitiesList
- Update countModifier based on effect type (+ or ×)
- Call setState to update the list display

**Test:**

2. Click the image multiple times to get money
3. Some buttons should become available (those you can afford)
4. Buy an ability - money decreases, ability disappears from store

### STEP 21: Implement Remove/Refund Logic

In `active.dart`, implement the remove button:

```dart
  onPressed: () {
    // Pull current item data
    final currentItem = activeAbilitiesList[index];
    final int value = currentItem['value'];
    final int cost = currentItem['cost'];

    // Move from active back to available
    abilitiesList.add(currentItem);
    activeAbilitiesList.remove(currentItem);

    // Refund money
    money += cost;

    // Reverse the modifier effect
    switch (currentItem['effect']) {
      case '+':
        countModifier -= value;
        break;
      case '×':
        countModifier = countModifier ~/ value;  // ~/ is integer division
        break;
    }

    // Update UI
    setState(() {});
  },
```

## The State Management Problem (Preview for Next Class)

### STEP 22: The Issue We Discovered

Try this sequence:
1. Start fresh, click to get $20
2. Buy abilities (now you have $5 left)
3. Navigate to active list (shows $5 ✓)
4. Pop back to game page (still shows $20 ✗)

**What's wrong?**
- The money variable IS updated in `globals.dart`
- But the game page widget doesn't rebuild when we pop back to it
- Each page has its own state, and they don't automatically sync

**Why does clicking fix it?**
- Clicking the coin calls `setState()`, which rebuilds the widget
- Now it reads the updated money value from globals

**The Solution (Next Class):**
We'll learn about **state management** using the Provider package, which allows all pages to automatically react to changes in shared data. We'll also explore **go_router** for more advanced navigation patterns.

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| "Context not found" error when navigating | Make sure you're inside a widget's build method where `context` is available |
| Button doesn't navigate | Check that you wrapped the logic in `onPressed: () { ... }` not just `onPressed: Navigator...` |
| Can't receive arguments / receiving null | Make sure you cast the arguments: `as int` or `as Map` |
| Changes not appearing on screen | Did you call `setState(() {})`? This is required after modifying variables |
| Back button not appearing | If using `pushReplacement`, it won't show. Use regular `push` instead |
| Button stays enabled when it shouldn't | Check your ternary condition: `cost > money ? null : () { ... }` |

## Key Syntax to Remember

### Basic Navigation
```dart
// Push a page (adds to stack)
Navigator.push(context, MaterialPageRoute(builder: (context) => MyPage()));

// Pop a page (removes from stack)
Navigator.pop(context);

// Replace current page (no back button)
Navigator.pushReplacement(context, MaterialPageRoute(builder: (context) => MyPage()));
```

### Named Routes Setup (in main.dart)
```dart
MaterialApp(
  initialRoute: '/',
  routes: {
    '/': (context) => HomePage(),
    '/other': (context) => OtherPage(),
  },
);
```

### Named Routes Navigation
```dart
// Push with name
Navigator.pushNamed(context, '/other');

// Push with arguments
Navigator.pushNamed(context, '/other', arguments: someData);

// Pop is the same
Navigator.pop(context);
```

### Passing and Receiving Data
```dart
// Sending (can be int, Map, String, etc.)
Navigator.pushNamed(context, '/details', arguments: {'id': 5, 'name': 'Thing'});

// Receiving
final Map args = ModalRoute.of(context)?.settings.arguments as Map;
int id = args['id'];
String name = args['name'];
```

### Returning Data from a Page
```dart
// In the closing page:
Navigator.pop(context, "some return value");

// In the calling page:
String result = await Navigator.pushNamed(context, '/details') as String;
```

### Ternary Operator for Conditional Button
```dart
ElevatedButton(
  onPressed: condition ? null : () { /* do something */ },
  child: Text("Click Me"),
)
// If condition is true, button is disabled (null)
// If condition is false, button is enabled (function is provided)
```

## Key Takeaways

1. **Navigation is managed by Flutter's Navigator** - It uses a stack (LIFO) where pages are pushed and popped
2. **Named routes simplify navigation** - Instead of referencing widget classes, use string names defined in one place
3. **Data can flow both directions** - Send data TO pages with `arguments`, receive data FROM pages with `pop(returnValue)` and `await`
4. **setState() is critical** - If you modify state variables, you MUST call `setState()` to see changes on screen
5. **Pages don't auto-sync** - This is the state management problem we'll solve next class with Provider

## Summary of Navigation Concepts

### Basic Navigation
1. **Navigator.push()** with MaterialPageRoute - Adds page to stack
2. **Navigator.pop()** - Removes page from stack
3. **Navigator.pushReplacement()** - Replaces current page (no back button)
4. **Automatic back buttons** - Flutter provides them for free

### Named Routes
5. **initialRoute** - Starting page for app
6. **routes map** - Define all routes in one place in main.dart
7. **Navigator.pushNamed()** - Navigate using route names (cleaner code)
8. **pushReplacementNamed()** - Named version of pushReplacement

### Data Passing
9. **arguments parameter** - Pass data TO pages (can be int, map, etc.)
10. **ModalRoute.of(context)?.settings.arguments** - Receive arguments
11. **Return value from pop()** - Send data back FROM pages
12. **await Navigator.push()** - Wait for returned data

### Other Concepts
13. **Ternary operator** - `condition ? true : false` for inline if/else
14. **setState() necessity** - Required for UI updates
15. **Navigator stack** - Pages stack on top of each other
16. **State management problem** - Pages don't auto-sync (next class: Provider)
