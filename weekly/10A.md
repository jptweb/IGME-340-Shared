## Part 1: Installing & Setting Up GoRouter

### Why GoRouter?

Named routes work fine, but GoRouter gives us:
- **URL-style paths** (`/store` instead of separate named route dictionary)
- **Easier parameter passing** (built into the path)
- **Better for web** (if you ever deploy to web)
- **Maintained by the Flutter team** (1.47M downloads, very popular)

Think of it as "Named Routes 2.0" - all the benefits, cleaner syntax.

### Step 1: Install GoRouter

**Stop your app if it's running** (hot reload won't pick up new packages properly)

```bash
flutter pub add go_router
```

Wait for it to finish installing.

### Step 2: Import GoRouter in main.dart

At the top of `main.dart`, add:

```dart
import 'package:go_router/go_router.dart';
```

### Step 3: Create Your Router Configuration

**Delete or comment out your entire `routes` map** from last week. We're replacing it.

Add this BEFORE your `main()` function (at the file's global level):

```dart
final _router = GoRouter(
  initialLocation: '/',
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) => const MainPage(),
    ),
    GoRoute(
      path: '/active',
      builder: (context, state) => const ActiveAbilitiesPage(),
    ),
    GoRoute(
      path: '/available',
      builder: (context, state) => const AvailableAbilitiesPage(),
    ),
  ],
);
```

**What changed?**
- Each route is a `GoRoute` (not a string key in a map)
- `path` uses URL-style slashes
- `builder` returns the widget for that path
- `initialLocation` replaces the `initialRoute` property
- No more separate `routes` map in MaterialApp!

### Step 4: Use MaterialApp.router Instead of MaterialApp

Replace your current MaterialApp with:

```dart
void main() {
  runApp(const MainApp());
}

class MainApp extends StatelessWidget {
  const MainApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      routerConfig: _router,
    );
  }
}
```

**Key Changes:**
- `MaterialApp.router` (not `MaterialApp`)
- `routerConfig: _router` (points to our GoRouter)
- No more `routes` or `initialRoute` properties

**Save everything and try running.** Your app should work exactly like before, just with GoRouter under the hood.

## Part 3: Passing Parameters with GoRouter

Now for the cool part - the details page that needs to know WHICH ability was clicked.

### Step 8: Update the ListTile in available.dart to Build the URL

**In your ListView.builder's ListTile**, change the `onTap`:

```dart
onTap: () {
  context.go('/details/$index');
}
```

**What's happening?**
- We're building a URL like `/details/0`, `/details/1`, etc.
- The `$index` gets inserted into the path
- This is like putting parameters right in the URL (very web-like!)

**Try clicking an ability now.** You'll get an error: **"No route exists with details/2"**

**This is perfect!** We built the URL, but haven't told GoRouter what to do with it yet. Let's fix that.

### Step 9: Add the Details Route with Parameter

Back in `main.dart`, add this route to your `_router`'s routes list:

```dart
GoRoute(
  path: '/details/:idx',
  builder: (context, state) {
    final idx = int.parse(state.pathParameters['idx']!);
    return DetailsPage(index: idx);
  },
),
```

**Let's break this down:**
- `'/details/:idx'` - The `:idx` is a **path parameter placeholder**
- When user goes to `/details/2`, the `2` becomes available as `'idx'`
- `state.pathParameters['idx']` - Extracts the parameter from the URL
- `int.parse()` - Converts the string "2" to integer 2
- `!` - Tells Dart "this definitely exists, don't worry"

### Step 10: Update details.dart to Receive the Index

The details page needs to be set up to receive that index. Update the class:

```dart
class DetailsPage extends StatelessWidget {
  final int index;

  const DetailsPage({required this.index});

  @override
  Widget build(BuildContext context) {
    String abilityName = abilitiesList[index]["name"];
    int abilityCost = abilitiesList[index]["cost"];
    
    return Scaffold(
      appBar: AppBar(title: Text('Details')),
      body: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            Text(
              abilityName,
              style: const TextStyle(fontSize: 24, fontWeight: FontWeight.bold),
            ),
            const SizedBox(height: 20),
            Text('Cost: \$$abilityCost'),
            const SizedBox(height: 40),
            ElevatedButton(
              onPressed: () => context.go('/'),
              child: const Text('Back to Game'),
            ),
          ],
        ),
      ),
    );
  }
}
```

**What changed?**
- Added `final int index;` property
- Constructor takes `{required this.index}`
- Uses `abilitiesList[index]` to get the data (from globals for now)
- Back button uses `context.go('/')` (GoRouter style)

**Don't forget to import GoRouter at the top of details.dart:**

```dart
import 'package:go_router/go_router.dart';
```

**Test it now!** Click abilities and see their details. Beautiful URLs, clean code.

## Part 4: The State Management Problem

Before we fix it, let's understand the problem.

**Try this:**
1. Click to earn some money
2. Go to the store and buy an ability
3. Go back to the main page

**Question:** Did your click value increase? Did your money decrease?

With GoRouter, it actually might work! But that's because GoRouter is reading from the same global variables. The problem is:
- **Globals are messy** - Hard to track, hard to maintain
- **setState() is scattered everywhere** - Easy to forget
- **Pages don't auto-update** - If money changes, other pages don't know

**The solution:** Provider - a proper state management system.

## Part 5: Setting Up Provider

### What is Provider?

Think of it as a **centralized data manager** that:
- Holds all your app's shared data in one place
- Notifies pages when data changes (auto-updates!)
- Eliminates the need for setState()
- Is way more scalable than globals

**It's the most popular state management solution** (3.9M downloads).

### Step 11: Install Provider

**Stop your app again**, then:

```bash
flutter pub add provider
```

### Step 12: Create game_provider.dart

Create a new file called `game_provider.dart` in your `lib` folder.

**Copy ALL the content from your globals.dart** and transform it into this:

```dart
import 'package:flutter/material.dart';
import 'dart:async';

class GameProvider with ChangeNotifier {
  // All your data from globals.dart goes here
  int money = 1000;
  int countModifier = 1;
  
  List<Map> abilitiesList = [
    {"name": "Better Click", "cost": 10, "effect": "plus", "value": 1},
    {"name": "Automation", "cost": 100, "effect": "plus", "value": 5},
    {"name": "Money Time", "cost": 500, "effect": "multiplier", "value": 2},
  ];
  
  List<Map> activeAbilitiesList = [];
  
  Timer? gameTimer;
  
  GameProvider() {
    _initGameLoop();
  }
  
  void _initGameLoop() {
    gameTimer = Timer.periodic(const Duration(seconds: 1), (timer) {
      money += activeAbilitiesList.length * 2;
      notifyListeners(); // This is the magic line!
    });
  }
  
  @override
  void dispose() {
    gameTimer?.cancel();
    super.dispose();
  }
  
  // Utility functions (we'll add these next)
}
```

**Key Points:**
- `with ChangeNotifier` - Gives this class notification powers
- `notifyListeners()` - Replaces setState() - tells all listeners "hey, data changed!"
- Everything from globals is now in one organized class

### Step 13: Add Utility Functions to GameProvider

Add these methods inside your `GameProvider` class (after the variables, before the closing brace):

```dart
  void updateMoney(int amount) {
    money += amount;
    notifyListeners();
  }
  
  void updateClickModifier(Map cItem) {
    switch(cItem['effect']) {
      case 'plus':
        countModifier += cItem['value'] as int;
        break;
      case 'multiplier':
        money *= cItem['value'] as int;
        break;
    }
    notifyListeners();
  }
  
  void moveAvailableToActive(Map cItem) {
    activeAbilitiesList.add(cItem);
    abilitiesList.remove(cItem);
    notifyListeners();
  }
  
  void moveActiveToAvailable(Map cItem) {
    abilitiesList.add(cItem);
    activeAbilitiesList.remove(cItem);
    notifyListeners();
  }
```

**Why these functions?**
- They encapsulate the logic for common operations
- Each one calls `notifyListeners()` - this is crucial!
- Much cleaner than having this logic scattered in pages
- We can reuse these anywhere

## Part 6: Wiring Up Provider

### Step 14: Wrap Your App with Provider

In `main.dart`, import Provider and your GameProvider:

```dart
import 'package:provider/provider.dart';
import 'game_provider.dart';
```

**Replace your entire `main()` function and `MainApp` class:**

```dart
void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => GameProvider(),
      child: const MainApp(),
    ),
  );
}

class MainApp extends StatelessWidget {
  const MainApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      routerConfig: _router,
    );
  }
}
```

**What happened?**
- `ChangeNotifierProvider` wraps the entire app
- `create: (context) => GameProvider()` - Creates ONE instance for the whole app
- Every widget can now access this GameProvider
- When GameProvider calls `notifyListeners()`, any watching widgets rebuild

**This is the foundation.** Now let's use it in pages.

## Part 7: Converting Pages to Use Provider

Here's where it all comes together. We'll show you the pattern once, then you'll apply it everywhere.

### Step 15: Convert game.dart to Use Provider

**Add imports at the top:**

```dart
import 'package:provider/provider.dart';
import 'game_provider.dart';
```

**In your build method, add this line at the very top:**

```dart
@override
Widget build(BuildContext context) {
  var gameProvider = context.watch<GameProvider>();
  
  // Rest of your build code...
}
```

**What does `context.watch<GameProvider>()` do?**
- Gets the GameProvider instance
- "Watches" it for changes
- When `notifyListeners()` is called, this widget rebuilds
- No more setState needed!

**Update your money display:**

```dart
// OLD WAY (delete this):
Text('\$$money'),

// NEW WAY:
Text('\$${gameProvider.money}'),
```

**Update your click modifier display:**

```dart
Text('Click Value: ${gameProvider.countModifier}'),
```

**Update your click button:**

```dart
InkWell(
  onTap: () {
    gameProvider.updateMoney(gameProvider.countModifier);
  },
  child: // ... your click widget
)
```

**Notice what's GONE:**
- ❌ No more `setState()`
- ❌ No more importing globals
- ✅ Just call methods on gameProvider
- ✅ Everything auto-updates!

**Test it:** Click to earn money. The number should update. Magic!

## Key Concepts Recap

### GoRouter
- ✅ Cleaner than named routes
- ✅ URL-style paths (`/store` instead of strings in a map)
- ✅ Path parameters (`/details/:idx`) for passing data
- ✅ Simple navigation with `context.go()`
- ✅ No more managing navigation stack manually

### Provider
- ✅ Centralized state management
- ✅ `ChangeNotifier` for notification capability
- ✅ `notifyListeners()` replaces setState()
- ✅ `context.watch<T>()` listens for changes and auto-rebuilds
- ✅ `context.read<T>()` for one-time access in callbacks
- ✅ One source of truth for your data

### Why These Matter
- **Scales beautifully** - Works for 2 pages or 200 pages
- **Industry standard** - These are professional patterns
- **Easier debugging** - All state changes in one place
- **Better performance** - Only rebuilds what needs to rebuild
- **Project 2 ready** - You're prepared for the bigger project!

## Common Issues & Fixes

### "No route exists with /details/2"
**Fix:** Make sure you added the GoRoute with path `/details/:idx` in main.dart

### "The getter 'money' was called on null"
**Fix:** Did you wrap your app with `ChangeNotifierProvider` in main()?

### "setState() called after dispose()"
**Fix:** You probably have both Provider AND setState() calls. Remove setState - let Provider handle it!

### Changes don't appear on other pages
**Fix:** Did you call `notifyListeners()` after modifying data in GameProvider?

### "context.watch must be called inside build method"
**Fix:** Use `context.read<GameProvider>()` in callbacks (like onPressed), not context.watch
