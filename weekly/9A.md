## II. Images That Only Download Once

`Image.network` keeps the photo in memory while your app is running. Close the app and that memory is gone, so the next launch downloads it all over again. With no internet, you get nothing.

`CachedNetworkImage` saves the downloaded file on the device. The next time, it loads from there, even offline. That's less waiting, less of the user's data plan, and a scrolling list of images that doesn't download the same thing twice.

### Step 2: Add a CachedNetworkImage

Uncomment the first import:

```dart
import 'package:cached_network_image/cached_network_image.dart';
```

**Where:** `TODO Step 2`, in the third spot of the Row. Replace the `SizedBox` with:

```dart
CachedNetworkImage(
  imageUrl: myImage,
  width: 110,
  height: 110,
  fit: BoxFit.cover,
),
```

It takes the same `width`, `height`, and `fit` as `Image.network`. The only rename is `imageUrl`.

### Step 3: Prove it with airplane mode

All three spots look the same right now. To see the difference, take the internet away:

1. Run the app once with the internet on, so every image downloads.
2. On the emulator, swipe down from the top and turn on **Airplane mode**.
3. **Stop the app completely** and run it again.

The plain `Image.network` turns into a red error box, and the `Container` loses its photo. Your `CachedNetworkImage` still shows the photo, loaded from the device.

**Turn airplane mode back off** before you go on. If the emulator's internet doesn't come back, cold boot it: Device Manager, the ⋮ menu next to your emulator, **Cold Boot Now**.

### Step 4: Show something while it loads, or if it fails

That red box is what a failed image looks like in debug mode. Your user would see a blank space, or worse. Add a `placeholder` and an `errorWidget` under `fit:` in your `CachedNetworkImage`:

```dart
fit: BoxFit.cover,   // already there
placeholder: (context, url) => CircularProgressIndicator(),
errorWidget: (context, url, error) => Icon(Icons.error),
```

`Image.network` has the same safety net, called `errorBuilder`:

```dart
child: Image.network(
  myImage,
  fit: BoxFit.cover,
  errorBuilder: (context, error, stackTrace) => Icon(Icons.error),
),
```

This one matters for Project 2. Plenty of APIs send back image links that are broken or missing (some OMDb posters come back as just `"N/A"`). Without `errorBuilder`, one bad link puts an error in the middle of your results.

### Step 5: The cached version of a Container background

**Where:** `TODO Step 5`, inside the `Container`'s `DecorationImage`. Swap `NetworkImage` for the cached version:

```dart
image: CachedNetworkImageProvider(myImage),
```

`CachedNetworkImage` is a widget. A `Container`'s background isn't a widget, it's an image *provider*, so it takes `CachedNetworkImageProvider` instead. Same caching either way.

Why bother with the `Container` version at all? Because the image is the background, you get everything else a `Container` does: borders, rounded corners, a circle shape, and a `child` on top of the photo (that's the "Hello"). One thing that trips people up: `BoxDecoration`'s `image:` wants a `DecorationImage`, not a `NetworkImage`, so the provider always goes inside one.

## III. Saving Data with SharedPreferences

Apps need to remember things after they close: a setting, a name, the last thing you searched for. `SharedPreferences` saves small pieces of data on the device as key/value pairs. Think of a Map that survives closing the app. If you've used `localStorage` in JavaScript, it's the same idea.

It's for small things. Don't try to save a whole list of API results in it.

### Step 6: Import it and declare the variable

Uncomment the second import:

```dart
import 'package:shared_preferences/shared_preferences.dart';
```

**Where:** `TODO Step 6`, under the two controllers.

```dart
final emailController = TextEditingController();   // already there

late SharedPreferences myPrefs;
```

`late` tells Dart "this gets a value before I use it, just not right now." We can't give it a value on this line, because getting it takes a moment.

### Step 7: Get it ready when the screen starts

**Where:** `TODO Step 7`, under `myPrefs`.

```dart
late SharedPreferences myPrefs;   // already there

@override
void initState() {
  super.initState();
  init();
}

Future<void> init() async {
  myPrefs = await SharedPreferences.getInstance();
}
```

`initState()` runs once, when the screen is first created. It can't be `async`, so it calls `init()`, which can. You've seen this setup before (7B used `initState` to fetch data). Same pattern.

### Step 8: Save

**Where:** `TODO Step 8`, under `init()`.

```dart
Future<void> saveText() async {
  await myPrefs.setString('name', nameController.text);
  await myPrefs.setString('email', emailController.text);
}
```

Then call it from the **Save** button's `onPressed`, replacing its TODO:

```dart
onPressed: () {
  saveText();
},
```

`'name'` and `'email'` are the keys. You pick them, and you have to spell them exactly the same way when you load. `setString` has siblings for other types: `setInt`, `setBool`, `setDouble`, and `setStringList`.

### Step 9: Load

**Where:** `TODO Step 9`, under `saveText()`.

```dart
Future<void> loadText() async {
  String name = myPrefs.getString('name') ?? '';
  String email = myPrefs.getString('email') ?? '';

  setState(() {
    nameController.text = name;
    emailController.text = email;
  });
}
```

And call it from the **Load** button:

```dart
onPressed: () {
  loadText();
},
```

`getString` gives back `null` if nothing was ever saved under that key. The `?? ''` says "if it's null, use an empty string instead." Always give a default when you load.

**Test it:** type a name and email, press **Save**, delete both fields by hand, then press **Load**. They come back.

### Step 10: Close the app for real

That test never left the app. Here's the real one:

1. Type something new and press **Save**.
2. **Stop the app completely** (the red square in VS Code).
3. Run it again. The fields are empty.
4. Press **Load**. Your data is still there.

The data lives on the device now, not in your app's memory.

### Step 11: Load it when the app starts

Nobody wants to press Load. Add one line to `init()`, after `getInstance()`:

```dart
Future<void> init() async {   // already there
  myPrefs = await SharedPreferences.getInstance();   // already there
  await loadText();
}
```

Stop the app and run it again. The fields fill themselves in.

This is exactly what Project 2 asks for: close the app, open it again, and the last search term is back in the search field. The `await` matters. `myPrefs` has to be ready before `loadText()` reads from it.

### About that `setState`

Setting `.text` on a controller is enough to update its field by itself, because the controller tells its `TextField` when it changes. So for these two fields, `setState()` isn't doing the work. It earns its place when you load into a **plain variable** that `build()` reads, like the value a dropdown has selected. Change that variable without `setState()` and the screen won't update. You'll hit this in Project 2 if you restore a dropdown.

**Debugging tip:** set a breakpoint in `loadText()` and look at `myPrefs` in the debugger. Everything saved so far is in there.

## IV. Opening Links with url_launcher

`url_launcher` opens things outside your app: a web page, the phone dialer, an email, a text message.

### Step 12: Open a web page

Uncomment the third import:

```dart
import 'package:url_launcher/url_launcher.dart';
```

**Where:** `TODO Step 12`, under `loadText()`.

```dart
String myURL = "https://www.rit.edu";

Future<void> openURL() async {
  Uri url = Uri.parse(myURL);

  if (!await launchUrl(url, mode: LaunchMode.inAppBrowserView)) {
    throw 'Could not launch $url';
  }
}
```

Then call it from the **Open RIT** button:

```dart
onPressed: () {
  openURL();
},
```

- `launchUrl` takes a `Uri`, not a `String`, just like `http.get` in 7B. `Uri.parse` converts it.
- `launchUrl` gives back `true` if it opened, `false` if nothing on the device could open it. The `if (!await ...)` catches the `false`.

> **First time on a fresh emulator?** Chrome may show a "Make Chrome your own" screen instead of the page. Tap **Use without an account**. It only happens once.

### Step 13: Try the other launch modes

Change `inAppBrowserView` to each of these and press the button again:

| Mode | What you get on Android |
|---|---|
| `inAppBrowserView` | A Chrome tab that slides up over your app, with an **X** and the address bar. Close it and you're back. |
| `inAppWebView` | Just the web page, inside your app. No X and no address bar, so the user has to use Back to get out. |
| `externalApplication` | The full Chrome app. Your app goes to the background. |
| `platformDefault` | Lets the phone pick. For web links on Android, that's the same Chrome tab as `inAppBrowserView`. |

`inAppBrowserView` is the friendliest for most links, because the user can always see how to get back.

### Step 14: Other kinds of links

Change the value of `myURL` and press the button again:

```dart
String myURL = "tel:+15854752411";
```

| Try this for `myURL` | What opens |
|---|---|
| `"tel:+15854752411"` | The phone dialer, with the number filled in |
| `"mailto:someone@example.com?subject=Hi"` | A new email, with the subject filled in |
| `"sms:+15855551234"` | A new text message |

On a fresh emulator the email link may open a Gmail welcome screen first. That's normal.

> **Android note:** you don't need to touch `AndroidManifest.xml` for any of this. You only need to add `<queries>` entries there if you use `canLaunchUrl()` to check a link before opening it. See the [url_launcher docs](https://pub.dev/packages/url_launcher) if you go that route.

## V. If There's Time: Saving Several Things at Once

`SharedPreferences` only stores simple types: Strings, numbers, true/false, and lists of Strings. You can't hand it a Map. But you can turn a Map into a String with `jsonEncode`, save that, and turn it back with `jsonDecode` when you load. (In JavaScript terms: `JSON.stringify` and `JSON.parse`.)

You'll need `import 'dart:convert';`. When `jsonEncode` turns red, use **Cmd+.** (Mac) or **Ctrl+.** (Windows) to add it.

### Step 15: Save both fields as one JSON string

Replace the inside of `saveText()`:

```dart
Future<void> saveText() async {
  Map<String, dynamic> profile = {
    'name': nameController.text,
    'email': emailController.text,
  };
  await myPrefs.setString('profile', jsonEncode(profile));
}
```

### Step 16: Load it back

Replace the inside of `loadText()`:

```dart
Future<void> loadText() async {
  String? saved = myPrefs.getString('profile');
  if (saved == null) return;

  Map<String, dynamic> profile = jsonDecode(saved);
  setState(() {
    nameController.text = profile['name'] ?? '';
    emailController.text = profile['email'] ?? '';
  });
}
```

Press **Save** once before you test. Everything you saved earlier is under the old `'name'` and `'email'` keys, which this version doesn't read.

`String?` with the question mark means "this might be null." If nothing was saved yet, we stop right there instead of trying to decode nothing.

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| `MissingPluginException` | Stop the app completely and run it again. This happens after adding a package with Android code. |
| `LateInitializationError: Field 'myPrefs' has not been initialized` | `init()` never ran or hadn't finished. Check that `initState()` calls `init()`, and that `init()` has the `await`. |
| Saved data doesn't come back | Check that the key is spelled the same in save and load (`'name'` is not `'Name'`). |
| No photos, or a red box where one should be | The emulator lost its internet. Turn airplane mode off. Still nothing? Cold boot the emulator. |
| The cached image doesn't survive airplane mode | You're running in Chrome. Caching only works on the emulator or a real device. |
| A link opens a "Make Chrome your own" screen | Tap **Use without an account**. Chrome's first-time setup, only once. |
| `Could not launch` | Check the link. Web addresses need the `https://` at the front. |
| `jsonEncode` is red | Add `import 'dart:convert';` (Cmd+. or Ctrl+. does it for you). |

## Key Terms

| Term | Meaning |
|------|---------|
| Caching | Saving downloaded data on the device so you don't download it again |
| Persistent storage | Data that's still there after the app closes |
| Key/value store | Storage where you save and look up each value by a name (its key) |
| `Uri` | A link in the form Dart's network and launcher functions expect |
| Launch mode | Where a link opens: a tab inside your app, or another app entirely |
| JSON encoding | Turning a Map into a String so it can be saved |
| JSON decoding | Turning that String back into a Map |
