# Week 3B - Flutter Buttons and Themes

## What We Covered in Class

### Flutter Button Types
We explored the three main button widgets in Flutter and how they differ primarily in their visual styling.

**Key Points:**
- ElevatedButton: Has background color and shadow effect
- OutlinedButton: Has border but no fill color
- TextButton: No border or background, just text
- All buttons require `onPressed` callback and child widget
- Buttons can call existing methods like `_incrementCounter`

### Inline Styling for Widgets
We learned how to apply styles directly to individual widgets, similar to inline CSS in web development.

**What We Did:**
- Used `ElevatedButton.styleFrom()` to customize button appearance
- Applied `TextStyle` to modify text properties
- Added shadows, custom fonts, and colors to buttons
- Created icon buttons with `ElevatedButton.icon()`

### Flutter Theme System
We dove deep into Flutter's global theming system, which is like CSS but applied throughout the entire app.

**Key Points:**
- `ColorScheme.fromSeed()` generates 47 color variations from one base color
- Light and dark themes can be defined separately
- Theme properties cascade down to all widgets
- Access theme colors with `Theme.of(context).colorScheme`
- ThemeData controls app-wide styling

## Key Concepts & Terminology

| Term | Definition |
|------|------------|
| ColorScheme | Set of 47 color roles generated from a seed color |
| ThemeData | Configuration object containing all theme properties for the app |
| styleFrom() | Method to create a style based on existing theme with modifications |
| Theme.of(context) | Way to access the current theme in any widget |
| bodyMedium | Default text style applied to Text widgets |
| displayLarge | Text theme role for large headlines |
| Hot Reload | Quick update without losing app state (can fail with large font changes) |
| BuildContext | Widget's location in the widget tree, needed for theme access |

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| Hot reload crashes with large fonts | Stop and restart the app completely |
| Theme not applying to widgets | Ensure widget is inside a context that has access to theme |
| Button text not visible | Check foreground and background color contrast |
| Can't find theme properties | Use `Theme.of(context)` to access current theme |
| App size too large after build | Run `flutter clean` before submitting |

## Code/Commands from Class

```dart
// Basic button examples
ElevatedButton(
  onPressed: () {},
  child: Text("Elevated Button"),
),

OutlinedButton(
  onPressed: () {},
  child: Text("Outlined Button"),
),

TextButton(
  onPressed: () {},
  child: Text("Text Button"),
),

// Styled button example
ElevatedButton(
  onPressed: _incrementCounter,
  style: ElevatedButton.styleFrom(
    backgroundColor: Colors.grey,
    foregroundColor: Colors.yellow,
    overlayColor: Colors.red,
    textStyle: TextStyle(
      fontFamily: "Courier",
      fontSize: 22,
      fontWeight: FontWeight.bold,
    ),
  ),
  child: Text("Styled Button"),
),

// Theme setup example
MaterialApp(
  theme: ThemeData(
    colorScheme: ColorScheme.fromSeed(seedColor: Colors.green),
    textTheme: TextTheme(
      bodyMedium: TextStyle(
        color: Colors.purple,
        fontSize: 30,
      ),
    ),
    elevatedButtonTheme: ElevatedButtonThemeData(
      style: ElevatedButton.styleFrom(
        backgroundColor: Colors.grey,
      ),
    ),
  ),
  darkTheme: ThemeData(
    colorScheme: ColorScheme.fromSeed(seedColor: Colors.red),
  ),
  themeMode: ThemeMode.system, // or .light or .dark
)

// Accessing theme colors
Container(
  color: Theme.of(context).colorScheme.primary,
)
```

## Key Takeaways

1. **Themes vs Inline Styles** - Use themes for consistency across your app, inline styles only for one-off customizations
2. **ColorScheme Magic** - One seed color creates a complete, harmonious color palette automatically
3. **Context Matters** - Widgets need proper BuildContext to access themes (watch out for the home widget pitfall)
