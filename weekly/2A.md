# Week 2A - VS Code Setup & Flutter Basics

## What We Covered in Class

### Development Environment Setup
We focused on getting everyone's Flutter development environment working properly in VS Code. This is critical - if your environment isn't set up correctly, nothing else will work.

**Key Setup Points:**
- Installed Flutter extension for VS Code (mandatory)
- Created our first Flutter project using Command Palette (`Cmd/Ctrl + Shift + P`)
- **Critical:** Never use spaces in Flutter project paths - use underscores instead

### First Flutter Application
We created and ran the default Flutter counter application:
1. Created new Flutter project using "Application" template (has lots of comments/examples)
2. Selected target device (Android emulator, Chrome, or physical device)
3. Ran the application with debugging enabled
4. Explored the counter app functionality

### Understanding Flutter Architecture
**Widget Tree Exploration:**
- Used Widget Inspector to visualize app structure
- Learned "Everything in Flutter is a widget"
- Explored hierarchy: MyApp → MaterialApp → HomePage → Scaffold → Body/AppBar/FloatingActionButton

**Code Concepts Covered:**
- `StatelessWidget` vs `StatefulWidget` (static vs interactive)

### Development Features
**Hot Reload Magic:**
- Changed colors and icons with instant updates
- Demonstrated state persistence during hot reload
- Explained when to use Hot Restart vs full restart

**Project Management:**
- 2251 NOTE: I didn't cover this! we will need to cover this 2B!!!:
- Project starts at ~1MB, grows to 450+ MB after building
- **For submissions:** Always run `flutter clean` first to remove build files
- Rebuild with `flutter pub get` after cleaning

### Important Files
- `pubspec.yaml` - Dependencies and asset declarations go here
- `main.dart` - Your application code lives in the lib folder
- `.gitignore` - Already configured for Flutter projects

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| "Waiting for device" | Check device selection in bottom-right of VS Code |
| Path errors | Remove all spaces from folder names |
| Emulator too slow | Use Chrome as target instead |
| Images not showing | Check `pubspec.yaml` asset declarations |
| Hot reload not working | Try Hot Restart, or stop and restart completely |
| Project too large to submit | Run `flutter clean` before zipping |

## Key Takeaways

1. **Path hygiene is critical** - No spaces ever in Flutter project paths
2. **Everything is a widget** - This is fundamental to Flutter's architecture  
3. **Hot reload saves time** - But know when to restart instead
4. **Clean before submitting** - Always run `flutter clean` for assignments
5. **Chrome is your backup** - If emulator issues arise, Chrome always works
