## I. Development Environment Setup

### VS Code Extensions (Required)

1. **Flutter Extension** - This is mandatory!
   - Open VS Code Extensions (`Cmd/Ctrl + Shift + X`)
   - Search "Flutter" and install the official Flutter extension
   - This also installs the Dart extension automatically

2. **Verify Installation**
   - Open Terminal in VS Code
   - Run `flutter doctor`
   - You should see checkmarks for Flutter and at least one target platform (Chrome always works)

### Creating Your First Project

**Use Command Palette (Cmd/Ctrl + Shift + P):**
1. Type "Flutter: New Project"
2. Select "Application" (includes helpful comments and examples)
3. Choose a folder location
4. Name your project (e.g., `my_first_app`)

**Critical Path Rule:**
- **NEVER use spaces in project paths** - use underscores
- `/Users/me/flutter_projects/my_app` - Good
- `/Users/me/flutter projects/my app` - Will cause errors!

## II. Running Your First Application

### Selecting a Target Device

Look at the bottom-right of VS Code to see available devices:
- **Chrome** - Always works, fastest to test
- **Android Emulator** - Full mobile experience
- **Physical Device** - Real device connected via USB

### Running the App

1. Open `lib/main.dart`
2. Click "Run and Debug" in the sidebar (or press `F5`)
3. Select your target device
4. Wait for the app to build and launch

The default counter app demonstrates:
- Basic Flutter structure
- `StatefulWidget` with state management
- Button interaction with `setState()`

## III. Understanding Flutter Architecture

### Everything is a Widget

This is the fundamental concept in Flutter. Every visual element is a widget:
- The entire app? Widget (`MaterialApp`)
- The screen structure? Widget (`Scaffold`)
- A button? Widget (`FloatingActionButton`)
- Text? Widget (`Text`)
- Even spacing? Widget (`SizedBox`)

### The Widget Tree

Widgets nest inside each other, forming a tree:

```
MyApp
└── MaterialApp
    └── MyHomePage
        └── Scaffold
            ├── AppBar
            │   └── Text ("Flutter Demo")
            └── Center
                └── Column
                    └── Text (counter value)
```

### Using Widget Inspector

The Widget Inspector lets you explore this tree visually:

1. Run your app in debug mode
2. Click the "Open Widget Inspector" icon (or `Cmd/Ctrl + Shift + I`)
3. Click on widgets to see their properties
4. Select "Select Widget Mode" to click on UI elements and jump to their code

**Why this matters:** When something doesn't look right, the Widget Inspector helps you find which widget to fix.

## IV. Hot Reload

One of Flutter's best features - instant UI updates while your app runs!

### Try It

1. Run the counter app
2. In `main.dart`, find `primarySwatch: Colors.blue`
3. Change it to `Colors.green`
4. Save the file (`Cmd/Ctrl + S`)
5. Watch the app update instantly!

### Hot Reload vs Hot Restart

| Feature | Hot Reload | Hot Restart |
|---------|------------|-------------|
| Speed | ~1 second | ~3-5 seconds |
| State preserved? | Yes (counter value stays) | No (resets to initial state) |
| When to use | UI changes, styling | State/logic changes |
| Shortcut | `Cmd/Ctrl + S` (save) | `Cmd/Ctrl + Shift + F5` |

**When Hot Reload Doesn't Work:**
- Changes to `main()` function
- Changes to global variables
- Adding new packages
- Significant state logic changes

Use Hot Restart in these cases.

## V. Project Management

### Understanding Project Size

Your Flutter project starts small but grows significantly after building:

| Stage | Size |
|-------|------|
| New project | ~1 MB |
| After first build | ~450+ MB |
| After `flutter clean` | ~1 MB |

The growth comes from compiled code, cached dependencies, and platform-specific build files.

### The `flutter clean` Command

**Before submitting any assignment:**
```bash
flutter clean
```

This removes build artifacts and returns your project to ~1 MB.

**To rebuild after cleaning:**
```bash
flutter pub get
```

This downloads dependencies again (they're not stored in git anyway).

### Important Project Files

| File/Folder | Purpose |
|-------------|---------|
| `lib/main.dart` | Your application code |
| `pubspec.yaml` | Dependencies and asset declarations |
| `pubspec.lock` | Locked dependency versions |
| `build/` | Compiled output (deleted by `flutter clean`) |
| `.gitignore` | Already configured for Flutter |

## VI. Key Concepts Summary

| Term | Definition |
|------|------------|
| Widget | A UI component - everything visible is a widget |
| Widget Tree | Hierarchical structure of nested widgets |
| StatelessWidget | Widget that doesn't change after being built |
| StatefulWidget | Widget that can change and rebuild |
| Hot Reload | Instant UI update while preserving state |
| Hot Restart | Full app restart without recompiling |
| `flutter clean` | Removes build files, shrinks project size |

## VII. Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| "Waiting for device" | Check device selection in bottom-right of VS Code |
| Path errors | Remove all spaces from folder names |
| Emulator too slow | Use Chrome as target instead |
| Hot reload not working | Try Hot Restart, or stop and rebuild completely |
| Project too large to submit | Run `flutter clean` before zipping |
| "Unable to find bundled SDK" | Restart VS Code, re-run `flutter doctor` |
