## I. String Interpolation

A quick recap from last class, because it comes up in everything else.

```dart
void main() {
  String player = 'Mario';
  int lives = 3;

  print('$player has $lives lives');
  print('Uppercase: ${player.toUpperCase()}');
  print('Next tick: ${lives - 1}');
}
```

**What's happening:**

- `$variableName` drops a variable straight into a string
- `${expression}` handles anything more complicated: a method call, arithmetic, a map lookup

**Rule of thumb:** if it's just a variable name, use `$`. The moment you need a dot or an operator, you need the curly braces.

## II. Named and Required Parameters

This is the most important part of the class. Flutter is built on this feature, and once it clicks, Flutter code stops looking strange.

### Start with a normal function

```dart
int add(int a, int b) {
  return a + b;
}

void main() {
  print(add(5, 3));  // 8
}
```

Unlike JavaScript, we declare the return type. `int add` means it hands back an int.

These are **positional** parameters. You pass them in order, and you pass all of them:

```dart
// print(add(5));  // Error. Both are required, in order.
```

### Now make them named

Wrap the parameters in curly braces:

```dart
void greet({String? name, String? message}) {
  print('$message, $name!');
}

void main() {
  greet(name: 'JP', message: 'Hello');
}
```

At the call site you write the parameter name, a colon, then the value.

### Order stops mattering

```dart
greet(message: 'Hey', name: 'Class');   // Same result
```

That's the whole point. A widget can accept thirty optional properties, and you pass only the four you care about, in whatever order makes sense to you.

### The `required` keyword

Named parameters are optional by default. Add `required` when the function can't work without one:

```dart
void greet({required String name, String? message}) {
  print('$message, $name!');
}

void main() {
  // greet(message: 'Hello');   // Error. name is required.
  greet(name: 'JP', message: 'Hello');
}
```

Notice the `?` disappeared from `name`. Something that's required can't also be allowed to be missing.

### Why this matters

Here's real Flutter code:

```dart
Container(
  width: 100,
  height: 200,
  color: Colors.blue,
)
```

Named parameters, all of them. `Container` accepts a long list of properties and you're using three. That pattern holds for every widget in the framework.

## III. Null Safety

Dart will not let a variable be null unless you say it can. This trips people up coming from JavaScript, and it's behind a large share of the errors you'll see.

### The default

```dart
void main() {
  String name = 'JP';
  // name = null;   // Error. String can't be null.
}
```

### Opting in with `?`

```dart
void main() {
  String? name = 'JP';
  name = null;      // Fine now
  print(name);      // null
}
```

The question mark means "this is allowed to be null." That's the entire feature.

### The part that actually bites

```dart
String? maybe;
// print(maybe.length);   // Error. maybe might be null.
```

Dart won't let you reach into something that might not be there. Two ways out:

```dart
print(maybe?.length);        // null-aware: gives you null instead of crashing
print(maybe?.length ?? 0);   // ?? supplies a fallback value
```

**What's happening:**

- `?.` means "only if this isn't null, otherwise give me null"
- `??` means "use this other value if the left side is null"

You'll use both heavily once we start pulling data from web APIs in Project 2, because API data arrives as maybe-it's-there.

**When you hit a red squiggle in Flutter and can't work out why, check nullability first.** It's the most common cause.

## IV. `const` and `final`

Both mean "this can't be reassigned." The difference is *when* the value gets locked in.

```dart
void main() {
  const maxHealth = 100;
  final startedAt = DateTime.now();

  print(maxHealth);
  print(startedAt);

  // maxHealth = 50;   // Error. Can't reassign.
}
```

**`const`** means the value is known before your app ever runs. A character that always has 200 hit points is a `const`.

**`final`** means the value gets set once while the app is running, and then it's locked. Data coming back from a web API is `final`. You don't know it yet, but once it arrives it isn't changing.

Here's the distinction in one line:

```dart
// const now = DateTime.now();   // Error. Can't know this at compile time.
final now = DateTime.now();      // Fine.
```

### Why Flutter cares so much

Flutter rebuilds your interface constantly as things change. A widget marked `const` is one Flutter knows cannot have changed, so it skips rebuilding it. That's a real performance win, which is why you'll see this suggestion over and over:

```
Use 'const' with the constructor to improve performance.
```

That's not an error. It's the linter telling you about a free optimization. Take it when you can.

## V. Reading Real Flutter Code

You haven't written any Flutter yet. Read this anyway:

```dart
const Text(
  'Hello 340',
  style: TextStyle(fontSize: 24, color: Colors.blue),
)
```

You can now name every piece:

- `const` - a compile-time constant, so Flutter can skip rebuilding it
- `'Hello 340'` - a positional parameter, the text itself
- `style:` - a named parameter
- `TextStyle(...)` - another constructor call, itself using named parameters
- `fontSize:` and `color:` - more named parameters
- The nesting - widgets take other widgets

That's the shape of everything you'll write this semester.

## VII. Key Takeaways

1. **`$` for a variable, `${}` for an expression**
2. **Curly braces in a function signature make parameters named.** Order stops mattering, and this is how every Flutter widget works
3. **`required` makes a named parameter mandatory** and drops the `?`
4. **`?` allows null, `?.` reaches in safely, `??` supplies a fallback**
5. **`const` is locked at compile time, `final` is locked at runtime.** Flutter skips rebuilding `const` widgets
