### The Current Flutter Setup Flow

Flutter's installation docs have evolved. Here's the current approach:

2. **Set up Android** (for mobile development)
   - [docs.flutter.dev/platform-integration/android/setup](https://docs.flutter.dev/platform-integration/android/setup)
   - Android Studio is already installed on lab machines!

3. **Web fallback** (if Android gives trouble)

   - Just needs Chrome - works immediately

### Lab Machine Setup (In-Class Walkthrough)

On the lab machines (Windows), we'll follow the same VS Code install method, but with one critical difference: **where you install Flutter matters!**

#### How Lab Machines Work
- Lab machines use **Deep Freeze** - most of C:\ gets wiped on reboot
- BUT your profile in **D:\Profiles** persists all semester
- So we install Flutter there, not in C:\

#### Installation Steps

**Step 1: Install the Flutter Extension**
- Open VS Code
- Click the **Extensions** icon in the left sidebar (or `Ctrl + Shift + X`)
- Search for **"Flutter"**
- Install the one by **Dart Code** (it's the official one, should be the top result)
- This also installs the Dart extension automatically

**Step 2: Download the Flutter SDK**
- Open Command Palette: `Ctrl + Shift + P`
- Type **"Flutter: New Project"** and select it
- VS Code will notice you don't have the SDK and offer to **download it automatically**
- **CRITICAL - Choose the right install location!**
  - On lab machines, use: `D:\Profiles\YOUR_USERNAME\flutter`
  - Or: `D:\Profiles\YOUR_USERNAME\development\flutter`
  - **NOT** anywhere in `C:\` (Deep Freeze will wipe it!)
- Click **"Clone Flutter"**
- When prompted, click **"Add SDK to PATH"**
- Wait for the download to complete (this takes a few minutes)

**Step 3: Create Your First Project**
- Open Command Palette again: `Ctrl + Shift + P`
- Type **"Flutter: New Project"** and select it
- Select **"Application"** (not "Empty Application" - we want the full counter app!)
- Choose a location for your project:
  - On lab machines: `D:\Profiles\YOUR_USERNAME\flutter_projects\`
  - **Remember: no spaces in the path!**
- Enter a project name (e.g., `hello_world`) - use lowercase with underscores, no spaces
- Wait for the project to be created

**Step 4: Run Flutter Doctor**
- Open a new terminal in VS Code: `` Ctrl + ` `` (backtick)
- Run: `flutter doctor`
- This checks your setup and shows what's working and what's missing
- You'll likely see some ❌ marks - that's expected, we'll fix them!

**Step 5: Connect to Android Studio** (already installed on lab machines)
- `flutter doctor` will show Android toolchain issues
- Accept Android licenses: `flutter doctor --android-licenses` (type `y` to accept each)
- Run `flutter doctor` again to confirm it's resolved
- Set up an emulator via Android Studio's Device Manager (we'll do this together)

**Step 6: Run on Chrome** (everyone does this!)
- Chrome works immediately as a target device
- No extra setup needed!
- Good enough for the first few weeks while we troubleshoot Android

#### Next Time You Log In
When you come back to class next week (or use a different lab machine), your Flutter install in D:\Profiles should still be there. If `flutter doctor` stops working, the PATH environment variable may have been lost - we can fix that together. Generally it works if installed in the right place.

### Why We Don't Write Our Own Install Guide

- Flutter docs change frequently - our instructions would go stale
- **Learning to follow official documentation is a job skill**
- You'll set up dev environments on co-ops and jobs - practice now!

### THE #1 SETUP KILLER: Spaces in Paths

**This causes more problems than anything else.** Flutter does NOT handle spaces in file paths well.

This applies to BOTH:
1. Where you install the Flutter SDK
2. Where you create your projects

**Bad:**
```
C:\Users\John Smith\flutter           ❌
C:\Program Files\flutter              ❌
C:\Users\abc1234\flutter projects\    ❌
```

**Good:**
```
C:\flutter                            ✓
C:\dev\flutter                        ✓
C:\Users\abc1234\flutter_projects\    ✓
```

**If your Windows username has a space:** Install Flutter somewhere like `C:\flutter` instead of in your user folder.

## IV. Understanding Flutter Architecture

> **In class:** I'll demo this on the Android emulator. Watch and follow along visually - you'll explore this hands-on in 2B.

### Everything is a Widget

This is the fundamental concept in Flutter. Every visual element is a widget:
- The entire app? Widget (`MaterialApp`)
- The screen structure? Widget (`Scaffold`)
- A button? Widget (`FloatingActionButton`)
- Text? Widget (`Text`)
- Even spacing? Widget (`SizedBox`)

### The Widget Tree

Widgets nest inside each other, forming a tree:

```
MyApp
└── MaterialApp
    └── MyHomePage
        └── Scaffold
            ├── AppBar
            │   └── Text ("Flutter Demo")
            └── Center
                └── Column
                    └── Text (counter value)
```

### Using Widget Inspector

The Widget Inspector lets you explore this tree visually:

1. Run your app in debug mode
2. Click the "Open Widget Inspector" icon (or `Cmd/Ctrl + Shift + I`)
3. Click on widgets to see their properties
4. Select "Select Widget Mode" to click on UI elements and jump to their code

**Why this matters:** When something doesn't look right, the Widget Inspector helps you find which widget to fix.

## V. Hot Reload

> **In class:** Watch this demo - it's one of Flutter's coolest features. You'll use it constantly once you start coding.

One of Flutter's best features - instant UI updates while your app runs!

### Try It

1. Run the counter app
2. In `main.dart`, find `primarySwatch: Colors.blue`
3. Change it to `Colors.green`
4. Save the file (`Cmd/Ctrl + S`)
5. Watch the app update instantly!

### Hot Reload vs Hot Restart

| Feature | Hot Reload | Hot Restart |
|---------|------------|-------------|
| Speed | ~1 second | ~3-5 seconds |
| State preserved? | Yes (counter value stays) | No (resets to initial state) |
| When to use | UI changes, styling | State/logic changes |
| Shortcut | `Cmd/Ctrl + S` (save) | `Cmd/Ctrl + Shift + F5` |

**When Hot Reload Doesn't Work:**
- Changes to `main()` function
- Changes to global variables
- Adding new packages
- Significant state logic changes

Use Hot Restart in these cases.

## VI. Project Management

> **In class:** Quick overview - reference this when submitting assignments.

### Understanding Project Size

Your Flutter project starts small but grows significantly after building:

| Stage | Size |
|-------|------|
| New project | ~1 MB |
| After first build | ~450+ MB |
| After `flutter clean` | ~1 MB |

The growth comes from compiled code, cached dependencies, and platform-specific build files.

### The `flutter clean` Command

**Before submitting any assignment:**
```bash
flutter clean
```

This removes build artifacts and returns your project to ~1 MB.

**To rebuild after cleaning:**
```bash
flutter pub get
```

This downloads dependencies again (they're not stored in git anyway).

### Important Project Files

| File/Folder | Purpose |
|-------------|---------|
| `lib/main.dart` | Your application code |
| `pubspec.yaml` | Dependencies and asset declarations |
| `pubspec.lock` | Locked dependency versions |
| `build/` | Compiled output (deleted by `flutter clean`) |
| `.gitignore` | Already configured for Flutter |

## VII. Key Concepts Summary

| Term | Definition |
|------|------------|
| Widget | A UI component - everything visible is a widget |
| Widget Tree | Hierarchical structure of nested widgets |
| StatelessWidget | Widget that doesn't change after being built |
| StatefulWidget | Widget that can change and rebuild |
| Hot Reload | Instant UI update while preserving state |
| Hot Restart | Full app restart without recompiling |
| `flutter clean` | Removes build files, shrinks project size |

## IX. Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| "Waiting for device" | Check device selection in bottom-right of VS Code |
| Path errors | Remove all spaces from folder names |
| Emulator too slow | Use Chrome as target instead |
| Hot reload not working | Try Hot Restart, or stop and rebuild completely |
| Project too large to submit | Run `flutter clean` before zipping |
| "Unable to find bundled SDK" | Restart VS Code, re-run `flutter doctor` |
