## I. Responsive Design in Flutter

### The Connection to Collection If

Remember last class's Collection If?

```dart
children: [
  if (_image != null)
    Image.file(_image!)
  else
    const Text('No image selected'),
]
```

Responsive design is the same idea - **conditionally render widgets based on a condition**. The difference? The condition is *screen size* instead of app state.

```dart
children: [
  if (screenWidth < 600)
    MobileLayout()
  else
    TabletLayout(),
]
```

### Flutter's Tools for Responsive Design

Flutter gives us two main tools (similar to CSS media queries):

| Tool | What it measures | Use when... |
|------|------------------|-------------|
| **MediaQuery.sizeOf()** | Entire screen/window size | Making app-level layout decisions |
| **LayoutBuilder** | Parent widget's constraints | Building reusable responsive components |

---

## II. MediaQuery - Quick Demo

### Getting Screen Size

```dart
@override
Widget build(BuildContext context) {
  // Get the screen size
  final size = MediaQuery.sizeOf(context);
  final width = size.width;
  final height = size.height;

  return Scaffold(
    body: Center(
      child: Text('Width: $width, Height: $height'),
    ),
  );
}
```

### Common Breakpoints

Material Design suggests:
- **< 600px** - Phone (use bottom navigation)
- **≥ 600px** - Tablet (use navigation rail or side panel)
- **≥ 1200px** - Desktop (use full side navigation)

## III. LayoutBuilder (Same Idea, Different Scope)

LayoutBuilder works the same way but measures the **parent widget's constraints** instead of the whole screen. It's useful when a widget might be placed in different-sized containers:

```dart
// Imagine this widget is inside a sidebar that can be resized
Expanded(
  child: LayoutBuilder(
    builder: (context, constraints) {
      if (constraints.maxWidth < 200) {
        return Icon(Icons.menu);  // Just show icon when narrow
      } else {
        return Row(children: [Icon(Icons.menu), Text('Menu')]);  // Icon + text when wider
      }
    },
  ),
)
```

**When to use which?**
- **MediaQuery** - "How big is the whole screen/window?"
- **LayoutBuilder** - "How much space does my parent give me?"

We won't build a LayoutBuilder example today, but it's the same concept - just scoped to the parent widget instead of the entire screen. See the [reference guide](../reference/responsive-design/mediaquery-layoutbuilder.md) for more patterns.

### 🎯 Why Does This Update? (StatelessWidget Magic)

Notice `ResponsiveDemo` is a **StatelessWidget** - there's no `setState()`. So why does resizing the window update the UI?

**The answer: InheritedWidget mechanism**

When you resize the window:
1. The OS notifies Flutter of the new dimensions
2. Flutter updates the `MediaQuery` data at the root of the widget tree
3. Any widget that calls `MediaQuery.sizeOf(context)` gets automatically rebuilt

This is NOT `setState()` - it's the **InheritedWidget** pattern. Widgets that depend on `MediaQuery` are registered as "dependents" and Flutter knows to rebuild them when `MediaQuery` changes.

**Key distinction:**
- `setState()` = internal state change triggers rebuild
- `InheritedWidget` change (like MediaQuery) = external data change triggers rebuild of dependents

Both cause rebuilds, but through different mechanisms!

### Try It!

Run in Chrome (or as a Mac app) and resize the window:
- **< 600px wide** → Shows mobile layout (Column, stacked)
- **≥ 600px wide** → Shows tablet layout (Row, side-by-side)

The layout switches instantly as you resize!

**Sound familiar?** You already did something similar with GridView earlier in the semester - changing column count based on orientation. That was responsive design too! MediaQuery just gives you more control.

## V. Publishing Overview (Brief)

We won't do a hands-on tutorial, but here's what publishing involves for different platforms:

### Mobile (App Stores)

**Google Play Store (Android):**
- $25 one-time developer fee
- `flutter build appbundle` → upload to Play Console
- Review typically takes a few hours to a few days

**Apple App Store (iOS):**
- $99/year Apple Developer Program
- `flutter build ios` → archive via Xcode → App Store Connect
- Stricter review process, can take longer

### Web (Easiest!)

- `flutter build web` generates static files
- Host anywhere: GitHub Pages, Firebase Hosting, Netlify, Vercel
- No app store approval needed - just deploy!

### Desktop

- **Mac**: Distribute directly (with notarization) or via Mac App Store
- **Windows**: Distribute directly or via Microsoft Store
- **Linux**: Snap Store, Flathub, or direct distribution

Desktop distribution is generally simpler than mobile app stores - you can often just share the built executable.

### Key Takeaways

- Mobile stores require **app icons** and **splash screens** (you did this in 13B!)
- You need **screenshots** for different device sizes
- Write a good **description** with keywords
- **Privacy policy** is required if you collect any data
- Plan for **review time** before any deadline (mobile stores only)

## VI. Flutter Alternatives (Why Flutter?)

Now that we've spent a semester with Flutter, it's worth mentioning what else is out there for cross-platform mobile development.

### React Native

**What it is:** Cross-platform framework using JavaScript/React (from Meta/Facebook)

**Pros:**
- You already know React from web classes!
- Large community and ecosystem
- Hot reload like Flutter

**Cons:**
- **Not truly native rendering** - uses a JavaScript bridge to native components, which can cause performance overhead
- UI can feel slightly less smooth than Flutter
- No equivalent to Flame for game development
- Debugging the bridge can be tricky

### Other Options

| Framework | Language | Notes |
|-----------|----------|-------|
| **React Native** | JavaScript/React | Most popular alternative, bridge-based |
| **Kotlin Multiplatform** | Kotlin | Shared logic, native UI per platform |
| **.NET MAUI** | C# | Microsoft's cross-platform solution |
| **Native (Swift/Kotlin)** | Swift/Kotlin | Best performance, but two codebases |

### Why We Chose Flutter

- **Truly compiled** - Dart compiles to native ARM code, no bridge overhead
- **Consistent UI** - Same pixels on every platform (no "looks different on iOS vs Android")
- **Flame engine** - Real game development capability
- **Growing fast** - 46% adoption rate among cross-platform developers
- **One codebase** - iOS, Android, Web, Desktop from the same code

Flutter's not perfect (Dart is less common than JavaScript), but for learning mobile development fundamentals and building performant apps, it's a solid choice.
