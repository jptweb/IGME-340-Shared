## Custom Fonts in Flutter

- Not all Google Fonts work seamlessly (e.g., [Bitcount](https://fonts.google.com/specimen/Bitcount) fails)

### Manual Font Installation

For the most reliable font integration, we use [manual font installation](../reference/styling/text-fonts.md#custom-fonts).

**Directory Structure:**
```
your_project/
  ├── assets/
  │   └── fonts/
  │       └── YourFont.ttf
  ├── lib/
  └── pubspec.yaml
```

**Key Points:**
- Assets folder must be at root level (NOT inside lib)
- Download .ttf files from [fonts.google.com](https://fonts.google.com)
- Only the .ttf file is needed from downloaded font packages

### Configuring pubspec.yaml

```yaml
flutter:
  fonts:
    - family: Lobster
      fonts:
        - asset: assets/fonts/Lobster-Regular.ttf
    - family: Sacramento  
      fonts:
        - asset: assets/fonts/Sacramento-Regular.ttf
        - asset: assets/fonts/Sacramento-Bold.ttf
          weight: 700
```

**WARNING:** YAML files require exact indentation - use tabs, not spaces!

### Using Fonts in Your App

**Inline Method (Not Recommended):**
```dart
Text(
  'Your text here',
  style: TextStyle(
    fontFamily: 'Lobster',
    fontSize: 30,
  ),
)
```

**Theme Method (Best Practice):**
```dart
MaterialApp(
  theme: ThemeData(
    textTheme: TextTheme(
      bodyMedium: TextStyle(
        fontFamily: 'Lobster',
        fontSize: 15,
      ),
      headlineMedium: TextStyle(
        fontFamily: 'Lobster',
        fontSize: 20,
        fontWeight: FontWeight.bold,
      ),
    ),
  ),
)

// Using themed text:
Text(
  'Your text',
  style: Theme.of(context).textTheme.headlineMedium,
)
```

## Making Widgets Clickable

### InkWell Widget
[InkWell](../reference/widgets/inkwell-gesturedetector.md#inkwell) provides basic tap detection with Material ripple effect:

```dart
InkWell(
  onTap: () {
    // Handle tap
  },
  child: Container(
    // Your content
  ),
)
```

### GestureDetector Widget
[GestureDetector](../reference/widgets/inkwell-gesturedetector.md#gesturedetector) offers more gesture options:

```dart
GestureDetector(
  onTap: () { },
  onDoubleTap: () { },
  onLongPress: () { },
  onPanUpdate: (details) { },
  onScaleUpdate: (details) { },
  child: Container(
    // Your content
  ),
)
```

### Adding Ripple Effect to InkWell
To get the ripple animation, wrap InkWell in Material:

```dart
Material(
  color: Colors.purple[50],  // Color goes here
  child: InkWell(
    onTap: () { },
    child: Container(
      // No color here - it blocks the ripple
      child: Text('Clickable'),
    ),
  ),
)
```

## Dialog Boxes

See the complete [Dialog & Alerts reference guide](../reference/navigation/dialogs-alerts.md) for more examples.

### Basic Alert Dialog

```dart
showDialog(
  context: context,
  builder: (context) {
    return AlertDialog(
      title: Text('Alert Title'),
      content: Text('Alert message here'),
      actions: [
        ElevatedButton(
          onPressed: () {
            Navigator.pop(context);
          },
          child: Text('OK'),
        ),
      ],
    );
  },
)
```

> **💡 Pro Tip: Understanding Context**
> 
> The `context: context` might look confusing! The first `context` is the parameter name for showDialog, while the second is the BuildContext from your widget. The builder's `(context)` creates a new local context for the dialog. Think of it as telling Flutter: "Show this dialog in my app's current context, and here's how to build it with its own context."
> 
> This is similar to how JavaScript closures work - the dialog needs to know where it belongs in the widget tree!

### Controlling Dialog Dismissal

Add `barrierDismissible: false` to prevent outside taps:

```dart
showDialog(
  context: context,
  barrierDismissible: false,  // Can't tap outside
  builder: (context) {
    return AlertDialog(
      // ... dialog content ...
      actions: [
        ElevatedButton(
          onPressed: () => Navigator.pop(context),
          child: Text('Close'),  // Must provide exit!
        ),
      ],
    );
  },
)
```

### iOS Style Dialogs

> **📱 Platform Styling Note:**
> 
> Use `CupertinoAlertDialog` for iOS-styled dialogs. These work on all platforms but maintain the iOS aesthetic. Import `'package:flutter/cupertino.dart'` to use Cupertino widgets.
> 
> This is great for apps targeting iOS users or when you prefer Apple's design language!

## Key Concepts & Terminology

| Term | Definition |
|------|------------|
| pub.dev | Official repository for Flutter/Dart packages |
| TTF | TrueType Font - standard font file format |
| [fontFamily](../reference/styling/text-fonts.md#using-custom-fonts) | Property to specify custom font in TextStyle |
| [InkWell](../reference/widgets/inkwell-gesturedetector.md#inkwell) | Widget that adds tap detection with ripple effect |
| [GestureDetector](../reference/widgets/inkwell-gesturedetector.md#gesturedetector) | Widget for detecting various user gestures |
| [showDialog](../reference/navigation/dialogs-alerts.md) | Function to display overlay dialogs |
| Navigator.pop() | Removes top item from navigation stack (dismisses dialog) |
| barrierDismissible | Controls whether tapping outside dialog dismisses it |
| BuildContext | Object that knows where a widget is in the widget tree |
| Cupertino widgets | iOS-styled Flutter widgets |

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| [Font not showing](../reference/styling/text-fonts.md#troubleshooting) | Check pubspec.yaml indentation, verify font family name matches exactly |
| Assets not found | Ensure assets folder is at root level, not inside lib |

## Key Takeaways

1. **Theme-based styling beats inline styling** - Define fonts and styles in your app theme for consistency
2. **Package compatibility matters** - Always check when a package was last updated before using it
3. **Navigation stack concept** - Dialogs are pushed onto and popped from a stack, just like pages
4. **User experience with dialogs** - Never trap users without an exit option
