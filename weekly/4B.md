## Custom Fonts in Flutter

### Using Google Fonts Package
The [Google Fonts package](../reference/styling/text-fonts.md#google-fonts-package) (`pub.dev/packages/google_fonts`) has had challenges in previous semesters. While basic functionality works, there are limitations:

- Not all Google Fonts work seamlessly (e.g., [Bitcount](https://fonts.google.com/specimen/Bitcount) fails)
- Variable fonts may have compatibility issues
- Some fonts might not be included in the Flutter package

### Manual Font Installation

For the most reliable font integration, we use [manual font installation](../reference/styling/text-fonts.md#custom-fonts).

**Directory Structure:**
```
your_project/
  ├── assets/
  │   └── fonts/
  │       └── YourFont.ttf
  ├── lib/
  └── pubspec.yaml
```

**Key Points:**
- Assets folder must be at root level (NOT inside lib)
- Download .ttf files from [fonts.google.com](https://fonts.google.com)
- Only the .ttf file is needed from downloaded font packages

### Configuring pubspec.yaml

```yaml
flutter:
  fonts:
    - family: Lobster
      fonts:
        - asset: assets/fonts/Lobster-Regular.ttf
    - family: Sacramento  
      fonts:
        - asset: assets/fonts/Sacramento-Regular.ttf
        - asset: assets/fonts/Sacramento-Bold.ttf
          weight: 700
```

**WARNING:** YAML files require exact indentation. Use spaces, never tabs. YAML does not allow tabs at all.

### Using Fonts in Your App

**Inline Method (Not Recommended):**
```dart
Text(
  'Your text here',
  style: TextStyle(
    fontFamily: 'Lobster',
    fontSize: 30,
  ),
)
```

**Theme Method (Best Practice):**
```dart
MaterialApp(
  theme: ThemeData(
    textTheme: TextTheme(
      bodyMedium: TextStyle(
        fontFamily: 'Lobster',
        fontSize: 15,
      ),
      headlineMedium: TextStyle(
        fontFamily: 'Lobster',
        fontSize: 20,
        fontWeight: FontWeight.bold,
      ),
    ),
  ),
)

// Using themed text:
Text(
  'Your text',
  style: Theme.of(context).textTheme.headlineMedium,
)
```

## Making Widgets Clickable

### InkWell Widget
[InkWell](../reference/widgets/inkwell-gesturedetector.md#inkwell) provides basic tap detection. Wrap any widget to make it tappable:

```dart
InkWell(
  onTap: () {
    print('Container tapped!');
  },
  child: Container(
    width: 200,
    height: 100,
    color: Colors.amber,
    alignment: Alignment.center,
    child: Text('Tap Me'),
  ),
)
```

### GestureDetector Widget
[GestureDetector](../reference/widgets/inkwell-gesturedetector.md#gesturedetector) offers more gesture options beyond simple taps:

```dart
GestureDetector(
  onTap: () {
    print('Tapped!');
  },
  onDoubleTap: () {
    print('Double tapped!');
  },
  onLongPress: () {
    print('Long pressed!');
  },
  child: Container(
    width: 200,
    height: 100,
    color: Colors.orange,
    alignment: Alignment.center,
    child: Text('Try Different Gestures'),
  ),
)
```

**When to use which:**
- **InkWell** - Simple taps, want ripple effect
- **GestureDetector** - Need advanced gestures (drag, scale, pan)

### Adding Ripple Effect to InkWell
By default, if your Container has a color, it blocks the ripple animation. Fix this by wrapping InkWell in Material and moving the color:

```dart
Material(
  color: Colors.teal,  // Color goes HERE (not on Container)
  child: InkWell(
    onTap: () {
      print('Tapped with ripple!');
    },
    child: Container(
      width: 200,
      height: 100,
      // NO color here - it would block the ripple
      alignment: Alignment.center,
      child: Text('Has Ripple Effect'),
    ),
  ),
)
```

## Dialog Boxes

See the complete [Dialog & Alerts reference guide](../reference/navigation/dialogs-alerts.md) for more examples.

### Basic Alert Dialog

`showDialog` is not a widget. It's a function you **call** when something happens, like a button press. That means it goes **inside a button's `onPressed`**, not in a `children` list with your other widgets.

In the starter, find the **Show Alert Dialog** button at the bottom of `main.dart` and replace its `debugPrint` line with the `showDialog` call:

```dart
ElevatedButton(
  onPressed: () {
    showDialog(
      context: context,
      builder: (context) {
        return AlertDialog(
          title: Text('Alert Title'),
          content: Text('Alert message here'),
          actions: [
            ElevatedButton(
              onPressed: () {
                Navigator.pop(context);
              },
              child: Text('OK'),
            ),
          ],
        );
      },
    );
  },
  child: const Text('Show Alert Dialog'),
),
```

What's happening:
- The outer `ElevatedButton` is already in the starter. Only the `showDialog(...)` part is new.
- `showDialog(...)` ends with `);`, a **semicolon** instead of a comma. It's a statement inside a function, not a widget in a list.
- The `ElevatedButton` inside `actions` is the dialog's own **OK** button. `Navigator.pop(context)` closes the dialog.

> **⚠️ Seeing "The element type 'Future<dynamic>' can't be assigned to the list type 'Widget'"?**
>
> Your `showDialog` code landed in a `children` list instead of inside `onPressed`. `showDialog` hands back a `Future`, not a widget, so Dart won't let it sit in a list of widgets. Move it inside the button's `onPressed`.

> **💡 Pro Tip: Understanding Context**
> 
> The `context: context` might look confusing! The first `context` is the parameter name for showDialog, while the second is the BuildContext from your widget. The builder's `(context)` creates a new local context for the dialog. Think of it as telling Flutter: "Show this dialog in my app's current context, and here's how to build it with its own context."
> 
> This is similar to how JavaScript closures work - the dialog needs to know where it belongs in the widget tree!

### Moving the Dialog to a Method

The dialog code makes `build` long and hard to read. Move it into its own method so the button stays short, and so you can show the same dialog from more than one place.

The method goes inside `_MyHomePageState`, next to `build` (not inside it):

```dart
class _MyHomePageState extends State<MyHomePage> {
  // ...loremText stays here...

  void showMyAlertDialog() {
    showDialog(
      context: context,
      builder: (context) {
        return AlertDialog(
          // ...same title, content, and actions as above...
        );
      },
    );
  }

  @override
  Widget build(BuildContext context) {
    // ...
```

Then the button just calls it:

```dart
ElevatedButton(
  onPressed: () {
    showMyAlertDialog();
  },
  child: const Text('Show Alert Dialog'),
),
```

What's happening:
- `context` works inside the method without being passed in, because every `State` class has its own `context`.
- VS Code can do the move for you. Select the whole `showDialog(...);` statement, then right-click → **Refactor** → **Extract Method**. If it adds a `BuildContext context` parameter, that works too: call it with `showMyAlertDialog(context);`.

### Controlling Dialog Dismissal

Add `barrierDismissible: false` to the same `showDialog` call to stop taps outside the dialog from closing it:

```dart
showDialog(
  context: context,
  barrierDismissible: false,  // Can't tap outside
  builder: (context) {
    return AlertDialog(
      // ... dialog content ...
      actions: [
        ElevatedButton(
          onPressed: () => Navigator.pop(context),
          child: Text('Close'),  // Must provide exit!
        ),
      ],
    );
  },
);
```

With this on, the button in `actions` is the only way out, so always include one.

### iOS Style Dialogs (Optional)

> **📱 Note:** CupertinoAlertDialog is **not required** for Project 1. This is just for reference if you want that iOS look.

First, add the import at the top of your file:
```dart
import 'package:flutter/cupertino.dart';
```

Then swap `AlertDialog` for `CupertinoAlertDialog` inside your `showDialog` call:

```dart
showDialog(
  context: context,
  builder: (context) {
    return CupertinoAlertDialog(
      title: Text('iOS Style Alert'),
      content: Text('This looks like an iPhone dialog!'),
      actions: [
        CupertinoDialogAction(
          onPressed: () => Navigator.pop(context),
          child: Text('Cancel'),
        ),
        CupertinoDialogAction(
          isDefaultAction: true,
          onPressed: () {
            Navigator.pop(context);
            print('User confirmed!');
          },
          child: Text('OK'),
        ),
      ],
    );
  },
);
```

**Key differences from AlertDialog:**
- Uses `CupertinoDialogAction` instead of buttons
- `isDefaultAction: true` makes the button bold (iOS convention)
- Works on Android too - it's just styled like iOS

## Key Concepts & Terminology

| Term | Definition |
|------|------------|
| pub.dev | Official repository for Flutter/Dart packages |
| TTF | TrueType Font - standard font file format |
| [fontFamily](../reference/styling/text-fonts.md#using-custom-fonts) | Property to specify custom font in TextStyle |
| [InkWell](../reference/widgets/inkwell-gesturedetector.md#inkwell) | Widget that adds tap detection with ripple effect |
| [GestureDetector](../reference/widgets/inkwell-gesturedetector.md#gesturedetector) | Widget for detecting various user gestures |
| [showDialog](../reference/navigation/dialogs-alerts.md) | Function to display overlay dialogs |
| Navigator.pop() | Removes top item from navigation stack (dismisses dialog) |
| barrierDismissible | Controls whether tapping outside dialog dismisses it |
| BuildContext | Object that knows where a widget is in the widget tree |
| Cupertino widgets | iOS-styled Flutter widgets |

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| [Font not showing](../reference/styling/text-fonts.md#troubleshooting) | Check pubspec.yaml indentation, verify font family name matches exactly |
| Assets not found | Ensure assets folder is at root level, not inside lib |
| Google Fonts package breaks build | Run `flutter pub remove google_fonts`, use [manual installation](../reference/styling/text-fonts.md#custom-fonts) |
| `The element type 'Future<dynamic>' can't be assigned to the list type 'Widget'` | `showDialog` was pasted into a `children` list. Move it inside the button's `onPressed` ([see above](#basic-alert-dialog)) |

| [No ripple effect on InkWell](../reference/widgets/inkwell-gesturedetector.md#inkwell-ripple-effect) | Wrap in Material widget, move color from Container to Material |

## Key Takeaways

1. **Theme-based styling beats inline styling** - Define fonts and styles in your app theme for consistency
2. **Package compatibility matters** - Always check when a package was last updated before using it
3. **Navigation stack concept** - Dialogs are pushed onto and popped from a stack, just like pages
4. **User experience with dialogs** - Never trap users without an exit option
