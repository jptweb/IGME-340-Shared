## PART 1: Provider Setup

### Understanding Provider in Flame Games

**Key Concept:** Provider is a state management solution that makes data accessible throughout your app. We'll use it to:
- Store music/SFX volume settings
- Track game score
- Manage audio player instances globally

**Important Note for Students Using Provider Already:** The Flame-specific setup is slightly different due to `GameWidget.controlled` - pay close attention to Step 3!

### STEP 2: Build the GameProvider Class

**Action:** Create a ChangeNotifier to hold all game state

**Code: game_provider.dart**

> **COPY-PASTE FRIENDLY:** This is a complete provider class - students can copy this

```dart
import 'package:flutter/material.dart';

class GameProvider extends ChangeNotifier {
  // Private variables for settings
  double _musicVolume = 1.0;
  double _sfxVolume = 1.0;
  int _score = 0;
  int _lastScore = 0;
  bool _inGame = false;

  // Getters to access private variables
  double get musicVolume => _musicVolume;
  double get sfxVolume => _sfxVolume;
  int get score => _score;
  int get lastScore => _lastScore;
  bool get inGame => _inGame;

  // Setters with notifyListeners
  void setMusicVolume(double value) {
    _musicVolume = value;
    notifyListeners();
  }

  void setSfxVolume(double value) {
    _sfxVolume = value;
    notifyListeners();
  }

  void incrementScore(int value) {
    _score += value;
    notifyListeners();
  }

  void setLastScore(int value) {
    _lastScore = value;
    notifyListeners();
  }
}
```

**Key Points:**
- **ChangeNotifier** - Base class that allows widgets to listen for updates
- **Private variables** (`_musicVolume`) - Encapsulation, accessed via getters
- **notifyListeners()** - Tells listening widgets to rebuild when state changes
- **Getters** - Clean way to access private data without exposing setters

**Why Private Variables?**
Using `_privateVariable` with getters prevents external code from directly modifying state. All changes go through methods that call `notifyListeners()`.

### STEP 3: Wrap App with ChangeNotifierProvider

**⚠️ CRITICAL STEP - Read Carefully!**

**Action:** Make GameProvider available throughout the app

**Code Changes in main.dart:**

**Add import:**
```dart

import 'game_provider.dart';
```

**Replace the `runApp()` call:**

**OLD CODE (comment this out):**
```dart
runApp(const MainApp());
```

**NEW CODE:**
```dart
runApp(
  ChangeNotifierProvider(
    create: (context) => GameProvider(),
    child: const MainApp(),
  ),
);
```

**What This Does:**
- `ChangeNotifierProvider` wraps the entire app
- `create: (context) => GameProvider()` - Creates a single instance of GameProvider
- This instance is now accessible anywhere in the widget tree using `Provider.of<GameProvider>(context)`

### STEP 4: Access Provider in Main Overlay (Update Score Display)

**Action:** Display the actual score from Provider instead of hardcoded "0"

**Code Changes in overlay_main.dart:**

**Add imports:**
```dart
import 'package:provider/provider.dart';
import 'game_provider.dart';
```

**Add at top of `mainOverlay` function:**
```dart
Widget mainOverlay(BuildContext context, game) {
  // Watch the provider - this widget rebuilds when state changes
  final gameProvider = context.watch<GameProvider>();

  return Align(
    // ... rest of overlay
  );
}
```

**Update the score Text widget** so it reads from the provider:
```dart
Text(
  "Score: ${gameProvider.score}",
  style: TextStyle(
    color: Colors.white,
    fontSize: 30,
  ),
),
```

**`context.watch` vs `context.read`:**

| Use | When |
|-----|------|
| `context.watch<T>()` | Displaying provider data — widget rebuilds on `notifyListeners()` |
| `context.read<T>()` | Just calling a method (e.g. inside `onTap`) — no rebuild |

These are the modern shortcuts for `Provider.of<T>(context)` (`listen: true` / `false`).

**Quick Test:**
To verify the connection is working, temporarily change the initial score in `game_provider.dart`:
```dart
int _score = 10;  // Changed from 0 to 10
```

Now run the app and check the main overlay - it should display "Score: 10" instead of "Score: 0". This confirms the UI is reading from the provider! Change it back to `0` after testing. (NOTE: hot reload may not work to show new score, reset app)

## PART 2: Audio Implementation

### Understanding Audio in Flame

> **Note (last-minute change):** Earlier versions of this tutorial used the `audioplayers` package directly. We've switched to **`flame_audio`**, which is a thin wrapper around `audioplayers` made by the same team (BlueFire). It handles the annoying Android audio-focus setup for us, so background music and sound effects mix without any extra configuration. If you're curious what's happening underneath, the `audioplayers` package on pub.dev is exactly what `flame_audio` calls into — feel free to explore it.

**What `flame_audio` gives us:**
- `FlameAudio.bgm.play(...)` — looping background music, with Android focus handled automatically
- `FlameAudio.play(...)` — fire-and-forget sound effects
- Files automatically load from `assets/audio/`, so we just pass `"shot.wav"` instead of `"audio/shot.wav"`

**What We'll Build:**
- Background music that loops continuously
- Sound effect when tapping the screen
- Volume controls connected to our Provider sliders

### STEP 8: Add Play Functions to GameProvider

**Action:** Add two simple methods to the provider that wrap `FlameAudio`.

**Code Changes in game_provider.dart:**

**Add import at top:**
```dart
import 'package:flame_audio/flame_audio.dart';
```

**Add these methods anywhere inside the `GameProvider` class (e.g. after the setters):**
```dart
// Play background music (loops automatically)
Future<void> playBgm(String url) async {
  //WARNING! Notice how the one uses FlameAudio.bgm.play()
  //As opposed to the SFX which just uses FlameAudio.play()!
  //Subtle difference that I forgot well doing the demo!
  await FlameAudio.bgm.play(url, volume: _musicVolume);
}

// Play sound effect (one-shot)
Future<void> playSfx(String url) async {
  await FlameAudio.play(url, volume: _sfxVolume);
}
```

**Understanding the Code:**

- **`FlameAudio.bgm`** is a singleton background-music player. Calling `.play()` automatically sets it to loop and configures Android audio focus so it won't be interrupted by sound effects later.
- **`FlameAudio.play()`** spawns a one-shot sound effect. Each call passes the current `_sfxVolume`, so the next tap always uses the latest slider value.
- **No `AssetSource(...)` wrapping needed** — `flame_audio` looks in `assets/audio/` by default, so we just pass `"retro_bgm.wav"`.
- **No `dispose()` override needed** — `FlameAudio` manages player lifetimes internally.

### STEP 9: Access Provider in Game & Play Background Music

**Action:** Add the provider to game.dart and start music when the game loads.

**Code Changes in game.dart:**

**Add imports:**
```dart
import 'package:flame_audio/flame_audio.dart';
import 'package:provider/provider.dart';
import 'game_provider.dart';
```

**Add a provider field to the `OverlayTutorial` class:**
```dart
class OverlayTutorial extends FlameGame with TapCallbacks {
  final BuildContext context;
  late final GameProvider gameProvider;  // Add this

  OverlayTutorial(this.context);

  // ... rest of class
}
```

**Update `onLoad` to grab the provider, preload audio, and start music:**
```dart
@override
Future<void> onLoad() async {
  // Grab the provider - use read() since the game itself doesn't rebuild
  gameProvider = context.read<GameProvider>();

  // Preload audio so the first tap doesn't hitch, then start music
  await FlameAudio.audioCache.loadAll(['retro_bgm.wav', 'shot.wav']);
  gameProvider.playBgm('retro_bgm.wav');

  await images.loadAll(["asteroid.png"]);

  for (int i = 0; i < 10; i++) {
    add(Asteroid());
  }
}
```

**Why preload?** The first time you play a sound, Flutter has to read it from disk — that can cause a tiny stutter. `audioCache.loadAll(...)` reads them up front so playback is instant.

**Why `context.read` and not `context.watch`?** This is important. The `context` we're using here belongs to **MainApp** (we passed it into the game's constructor). If we used `context.watch<GameProvider>()`, MainApp would register itself as a listener of the provider, and every `notifyListeners()` call would rebuild MainApp — which would tear down and recreate the `GameWidget` on every tap. That used to be a notorious bug with `Provider.of(context, listen: true)` (the old default), and the workaround was switching to `GameWidget.controlled(gameFactory: () => ...)`. The modern `context.read` / `context.watch` split makes this almost impossible to do by accident: you have to type `watch` to opt into rebuilds. We just want a reference to the provider here, not to rebuild on its changes, so `read` is correct.

**Understanding `late final`:**
- **`late`** — tells Dart "this will be initialized later, not in the constructor"
- **`final`** — once set, it can't be changed
- We initialize it in `onLoad()`, which runs after the constructor

**Test It:**
Run the app. You should hear background music start playing immediately.

### STEP 10: Add Sound Effect on Tap

Now we want each tap to do two things: **increment the score** by 1, and **play `shot.wav`**. Find the existing (empty) `onTapUp` method in `game.dart` and add those two lines so it looks like this:

```dart
@override
void onTapUp(TapUpEvent event) {
  super.onTapUp(event);

  // Increment score
  gameProvider.incrementScore(1);

  // Play sound effect
  gameProvider.playSfx('shot.wav');
}
```

**What Happens:**
1. User taps the screen
2. `onTapUp` is called
3. Score increases by 1 → `notifyListeners()` → main overlay rebuilds
4. `shot.wav` plays alongside the background music

**Test It:**
Run the app and tap the screen. You should hear the shot sound, see the score go up, and the music should keep playing. Two pieces are quietly working together here: `flame_audio` is handling Android audio focus so SFX don't interrupt the music, and `context.read` (from Step 9) is keeping MainApp out of the provider's listener list so the GameWidget isn't getting torn down on every tap.

### STEP 11: Connect Volume Sliders to Audio Players

**Action:** Make the settings sliders actually control volume

**Currently:** Sliders update Provider values but don't affect what you hear.

**Goal:** Make the music slider change BGM volume in real-time. SFX volume already works because `playSfx` reads `_sfxVolume` on every tap.

**Code Changes in game_provider.dart:**

**Add one line to `setMusicVolume`** so the running BGM player updates live:

```dart
void setMusicVolume(double value) {
  _musicVolume = value;
  FlameAudio.bgm.audioPlayer.setVolume(value);  // <-- new
  notifyListeners();
}
```

`FlameAudio.bgm.audioPlayer` exposes the underlying `audioplayers` instance — that's how you reach in to change volume on already-playing music without restarting it.

`setSfxVolume` doesn't need any change. Each call to `FlameAudio.play(url, volume: _sfxVolume)` creates a fresh one-shot player using whatever value is currently in `_sfxVolume`, so the next tap will already use the new volume.

**Test It:**
1. Run the app
2. Start the game (background music plays)
3. Go to settings
4. Move the music slider - volume should change immediately
5. Move the SFX slider to minimum
6. Tap the screen - you should see score increase but hear no sound
7. Move SFX slider back up, tap again - sound returns

### Key Concepts Covered:

**Provider Patterns:**

| Concept | Code | Purpose |
|---------|------|---------|
| **Setup** | `ChangeNotifierProvider(create: (context) => GameProvider())` | Makes provider available app-wide |
| **Access (rebuild)** | `context.watch<GameProvider>()` | Get provider and rebuild on changes |
| **Access (no rebuild)** | `context.read<GameProvider>()` | Get provider just to call methods |
| **Update** | `gameProvider.setMusicVolume(0.5)` | Update state and notify listeners |
| **State** | `notifyListeners()` | Tell listening widgets to rebuild |

**Audio (`flame_audio`):**

| Feature | Code | Notes |
|---------|------|-------|
| **Play music** | `FlameAudio.bgm.play('retro_bgm.wav')` | Loops automatically; handles Android focus |
| **Play SFX** | `FlameAudio.play('shot.wav', volume: v)` | Fire-and-forget one-shot |
| **Preload** | `FlameAudio.audioCache.loadAll([...])` | Avoids first-play hitch |
| **Music volume** | `FlameAudio.bgm.audioPlayer.setVolume(v)` | Reaches into underlying player |
| **Asset path** | `'shot.wav'` | Auto-prefixed with `assets/audio/` |

---

### Important Notes:

**`context.read` vs `context.watch`:**
Use `read` when you just want a reference to the provider (e.g. inside `onLoad` or an `onPressed` callback). Use `watch` when the widget should rebuild on state changes (e.g. displaying the score). Mixing these up — especially `watch`-ing from a `BuildContext` that lives high up in the tree — can cause widgets like `GameWidget` to be torn down on every state change. If that ever happens to you, the workaround is `GameWidget.controlled(gameFactory: () => ...)`, but the better fix is making sure no parent of `GameWidget` is `watch`-ing the provider.

**Volume Range:**
- Sliders: 0.0 to 1.0 (doubles) — this is what `setVolume()` and `FlameAudio.play(volume:)` expect.

---

### Troubleshooting:

| Problem | Solution |
|---------|----------|
| Overlays disappear / GameWidget restarts on tap | A parent of `GameWidget` is `watch`-ing the provider. Switch to `context.read` in `onLoad`, or wrap with `GameWidget.controlled(gameFactory: () => ...)` |
| Score doesn't update | Check `gameProvider.incrementScore(1)` is called in `onTapUp` |
| No sound plays | Check audio files are in `assets/audio/` and registered in `pubspec.yaml` |
| Music slider doesn't change volume | Check `FlameAudio.bgm.audioPlayer.setVolume(value)` is called in `setMusicVolume` |
| File-not-found on `playSfx` | Use just the filename (`'shot.wav'`) — `flame_audio` adds `assets/audio/` for you |
