## Part 1: Provider Setup

We'll use Provider to hold the music volume, SFX volume, and score in one place that both the overlays and the game can reach.

**Already using Provider?** The one Flame-specific catch is in Step 9: the game grabs the provider with `context.read`, not `context.watch`. Step 9 explains why.

---

### Step 1: Create the Provider File

`provider` is already installed in your starter. In your own projects, you'd add it with `flutter pub add provider`.

Create a new file, `lib/game_provider.dart`.

---

### Step 2: Build the GameProvider Class

This is the whole class, so go ahead and paste it into `game_provider.dart`.

```dart
import 'package:flutter/material.dart';

class GameProvider extends ChangeNotifier {
  // Private variables for settings
  double _musicVolume = 1.0;
  double _sfxVolume = 1.0;
  int _score = 0;
  int _lastScore = 0;
  bool _inGame = false;

  // Getters to access private variables
  double get musicVolume => _musicVolume;
  double get sfxVolume => _sfxVolume;
  int get score => _score;
  int get lastScore => _lastScore;
  bool get inGame => _inGame;

  // Setters with notifyListeners
  void setMusicVolume(double value) {
    _musicVolume = value;
    notifyListeners();
  }

  void setSfxVolume(double value) {
    _sfxVolume = value;
    notifyListeners();
  }

  void incrementScore(int value) {
    _score += value;
    notifyListeners();
  }

  void setLastScore(int value) {
    _lastScore = value;
    notifyListeners();
  }
}
```

The variables are private (`_score`) and read through getters, so nothing outside the class can change them directly. Every change goes through a method that calls `notifyListeners()`, which tells any widget watching the provider to rebuild.

---

### Step 3: Wrap App with ChangeNotifierProvider

In `main.dart`, add the imports:
```dart
import 'package:provider/provider.dart';
import 'game_provider.dart';
```

Then replace the `runApp()` call. Old (comment this out):
```dart
runApp(const MainApp());
```

New:
```dart
runApp(
  ChangeNotifierProvider(
    create: (context) => GameProvider(),
    child: const MainApp(),
  ),
);
```

This creates one `GameProvider` for the whole app. Anything below it in the widget tree can now reach it.

---

### Step 4: Access Provider in Main Overlay (Update Score Display)

In `overlay_main.dart`, add the imports:
```dart
import 'package:provider/provider.dart';
import 'game_provider.dart';
```

Add this line at the top of the `mainOverlay` function:
```dart
Widget mainOverlay(BuildContext context, game) {
  // Watch the provider - this widget rebuilds when state changes
  final gameProvider = context.watch<GameProvider>();

  return Align(
    // ... rest of overlay
  );
}
```

Then update the score Text widget so it reads from the provider:
```dart
Text(
  "Score: ${gameProvider.score}",
  style: TextStyle(
    color: Colors.white,
    fontSize: 30,
  ),
),
```

**`context.watch` vs `context.read`:**

| Use | When |
|-----|------|
| `context.watch<T>()` | Displaying provider data. The widget rebuilds on `notifyListeners()` |
| `context.read<T>()` | Just calling a method (e.g. inside `onTap`). No rebuild |

These are the modern shortcuts for `Provider.of<T>(context)` (`listen: true` / `false`).

**Quick test:** temporarily change the starting score in `game_provider.dart`:
```dart
int _score = 10;  // Changed from 0 to 10
```

Run the app. The main overlay should say "Score: 10", which means the UI is reading from the provider. Change it back to `0` after. (NOTE: hot reload may not work to show new score, reset app)

### Step 5: Connect Provider to Settings Sliders

In `overlay_settings.dart`, add the imports:
```dart
import 'package:provider/provider.dart';
import 'game_provider.dart';
```

Add this line at the top of the `settingsOverlay` function:
```dart
Widget settingsOverlay(BuildContext context, game) {
  final gameProvider = context.watch<GameProvider>();

  return Center(
    // ... rest of overlay
  );
}
```

Update the Music Volume slider to read and write through the provider:
```dart
Slider(
  value: gameProvider.musicVolume,                       // current value
  min: 0.0,                                              // volume is 0.0 - 1.0
  max: 1.0,
  divisions: 5,
  label: gameProvider.musicVolume.toStringAsFixed(1),    // "0.5" not "0.5000…"
  onChanged: (value) => gameProvider.setMusicVolume(value),
),
```

Do the same for the SFX Volume slider, swapping `musicVolume` → `sfxVolume` and `setMusicVolume` → `setSfxVolume`.

The range is 0.0 to 1.0 instead of 0 to 100 because that's what audio volume APIs expect, including the `setVolume()` call in Step 11.

**Test it:** open settings and move the sliders. They should move smoothly and keep their values when you close and reopen settings.

## Part 2: Audio

We use the **`flame_audio`** package, a thin wrapper around `audioplayers` made by the same team (BlueFire). Earlier versions of this lesson used `audioplayers` directly. `flame_audio` handles the Android audio-focus setup for us, so music and sound effects play together without extra configuration. It gives us two calls:
- `FlameAudio.bgm.play(...)`: looping background music
- `FlameAudio.play(...)`: one-shot sound effects

Both look in `assets/audio/` on their own, so you pass `"shot.wav"`, not `"audio/shot.wav"`.

---

### Step 6: flame_audio Is Already Installed

Nothing to install today: `flame_audio` is already in your `pubspec.yaml`. In your own projects, you'd add it with `flutter pub add flame_audio`, then stop and restart your app, since new packages need a full restart (hot reload won't work).

---

### Step 7: Audio Files Are Already in Place

Both audio files are already in your project's `assets/audio/` folder, and your `pubspec.yaml` already registers that folder:
```yaml
flutter:
  assets:
    - assets/images/
    - assets/audio/    # Audio files go here
```

In your own projects, you'd add the files and that `assets/audio/` line yourself, then run `flutter pub get` (or VS Code will prompt you).

The two files are `retro_bgm.wav` (background music) and `shot.wav` (the tap sound). For your own games, there are free sound sources under [Additional Resources](#additional-resources) at the bottom.

---

### Step 8: Add Play Functions to GameProvider

In `game_provider.dart`, add the import at the top:
```dart
import 'package:flame_audio/flame_audio.dart';
```

Add these two methods anywhere inside the `GameProvider` class (after the setters works):
```dart
// Play background music (loops automatically)
Future<void> playBgm(String url) async {
  //WARNING! Notice how the one uses FlameAudio.bgm.play()
  //As opposed to the SFX which just uses FlameAudio.play()!
  //Subtle difference that I forgot well doing the demo!
  await FlameAudio.bgm.play(url, volume: _musicVolume);
}

// Play sound effect (one-shot)
Future<void> playSfx(String url) async {
  await FlameAudio.play(url, volume: _sfxVolume);
}
```

`FlameAudio.bgm` is a single background-music player that loops on its own. `FlameAudio.play()` starts a new one-shot sound each time, using the current `_sfxVolume`. You don't need a `dispose()` override: `FlameAudio` cleans up its own players.

---

### Step 9: Access Provider in Game & Play Background Music

In `game.dart`, add the imports:
```dart
import 'package:flame_audio/flame_audio.dart';
import 'package:provider/provider.dart';
import 'game_provider.dart';
```

Add a provider field to the `OverlayTutorial` class:
```dart
class OverlayTutorial extends FlameGame with TapCallbacks {
  final BuildContext context;
  late final GameProvider gameProvider;  // Add this

  OverlayTutorial(this.context);

  // ... rest of class
}
```

`late` means it gets its value after the constructor runs (in `onLoad`), and `final` means it can't change after that.

Update `onLoad` to grab the provider, preload the audio, and start the music:
```dart
@override
Future<void> onLoad() async {
  // Grab the provider - use read() since the game itself doesn't rebuild
  gameProvider = context.read<GameProvider>();

  // Preload audio so the first tap doesn't hitch, then start music
  await FlameAudio.audioCache.loadAll(['retro_bgm.wav', 'shot.wav']);
  gameProvider.playBgm('retro_bgm.wav');

  await images.loadAll(["asteroid.png"]);

  for (int i = 0; i < 10; i++) {
    add(Asteroid());
  }
}
```

Preloading reads the files from disk up front, so the first sound doesn't stutter.

**Why `context.read` and not `context.watch`?** This `context` belongs to **MainApp**, since we passed it into the game's constructor. `watch` would make MainApp rebuild on every `notifyListeners()`, and rebuilding MainApp tears down and recreates the `GameWidget` on every tap. We only need a reference to the provider here, so `read` is the right call.

**Test it:** run the app. Background music should start right away.

---

### Step 10: Add Sound Effect on Tap

Each tap should do two things: add 1 to the score and play `shot.wav`. Find the existing (empty) `onTapUp` method in `game.dart` and add those two lines:

```dart
@override
void onTapUp(TapUpEvent event) {
  super.onTapUp(event);

  // Increment score
  gameProvider.incrementScore(1);

  // Play sound effect
  gameProvider.playSfx('shot.wav');
}
```

**Test it:** tap the screen. You should hear the shot, see the score go up, and the music should keep playing. If the overlays disappear or the game restarts on every tap, check that Step 9 uses `read`.

---

### Step 11: Connect Volume Sliders to Audio Players

The sliders update the provider, but the music doesn't listen yet. In `game_provider.dart`, add one line to `setMusicVolume` so the music player updates live:

```dart
void setMusicVolume(double value) {
  _musicVolume = value;
  FlameAudio.bgm.audioPlayer.setVolume(value);  // <-- new
  notifyListeners();
}
```

`FlameAudio.bgm.audioPlayer` is the underlying `audioplayers` player, which lets you change the volume of music that's already playing.

`setSfxVolume` doesn't need a change. Every `playSfx` call already passes the current `_sfxVolume`, so the next tap uses the new value.

**Test it:**
1. Run the app
2. Start the game (background music plays)
3. Go to settings
4. Move the music slider - volume should change immediately
5. Move the SFX slider to minimum
6. Tap the screen - you should see score increase but hear no sound
7. Move SFX slider back up, tap again - sound returns

## Quick Reference

**Provider:**

| Concept | Code | Purpose |
|---------|------|---------|
| **Setup** | `ChangeNotifierProvider(create: (context) => GameProvider())` | Makes provider available app-wide |
| **Access (rebuild)** | `context.watch<GameProvider>()` | Get provider and rebuild on changes |
| **Access (no rebuild)** | `context.read<GameProvider>()` | Get provider just to call methods |
| **Update** | `gameProvider.setMusicVolume(0.5)` | Update state and notify listeners |
| **State** | `notifyListeners()` | Tell listening widgets to rebuild |

**Audio (`flame_audio`):**

| Feature | Code | Notes |
|---------|------|-------|
| **Play music** | `FlameAudio.bgm.play('retro_bgm.wav')` | Loops automatically; handles Android focus |
| **Play SFX** | `FlameAudio.play('shot.wav', volume: v)` | Fire-and-forget one-shot |
| **Preload** | `FlameAudio.audioCache.loadAll([...])` | Avoids first-play hitch |
| **Music volume** | `FlameAudio.bgm.audioPlayer.setVolume(v)` | Reaches into underlying player |
| **Asset path** | `'shot.wav'` | Auto-prefixed with `assets/audio/` |

---

### Troubleshooting

| Problem | Solution |
|---------|----------|
| Overlays disappear / GameWidget restarts on tap | A parent of `GameWidget` is `watch`-ing the provider. Switch to `context.read` in `onLoad`, or wrap with `GameWidget.controlled(gameFactory: () => ...)` |
| Score doesn't update | Check `gameProvider.incrementScore(1)` is called in `onTapUp` |
| No sound plays | Check audio files are in `assets/audio/` and registered in `pubspec.yaml` |
| Music slider doesn't change volume | Check `FlameAudio.bgm.audioPlayer.setVolume(value)` is called in `setMusicVolume` |
| File-not-found on `playSfx` | Use just the filename (`'shot.wav'`). `flame_audio` adds `assets/audio/` for you |
