### DropdownButton Widget
We started with dropdown menus - a common UI element for giving users a predefined list of options. Unlike web development, Flutter's dropdowns require more setup but offer more control.

**Key Points:**
- DropdownButton requires a list of DropdownMenuItem widgets
- Each item needs both a `value` (for your code) and `child` (what users see)
- The selected value must match one of the item values exactly
- **Critical:** Always wrap `onChanged` in `setState()` or the UI won't update

**Two Approaches We Learned:**

1. **Explicit DropdownMenuItems** (more control):
```dart
var armorList = [
  DropdownMenuItem(value: 'leather', child: Text('Leather Armor')),
  DropdownMenuItem(value: 'chain', child: Text('Chain Mail')),
  // ... more items
];
```

2. **Using .map() with string lists** (cleaner for simple cases):

> Flashback to IGME-330. Remember we used Map to append list items to a
> list in html? We may have combined this with AJAX. Similar idea; a
> clean alternative to long for loops. It takes a while to get used to
> the syntax; but with some practice it should start to make sense. Even
> if you struggle to write these from scratch you want to have a good
> understanding of what it is doing. This is a common practice you will
> see if you get into full stack development and are using popular
> frameworks such as React.

```dart
List<String> weaponList = ['dagger', 'sword', 'mace', 'spear'];

// In the DropdownButton:
items: weaponList.map((String item) {
  return DropdownMenuItem(value: item, child: Text(item));
}).toList(),  // Don't forget .toList()!
```

### Android Emulator Keyboard Note

**The Issue:** Newer Android emulators (12+) don't automatically show the virtual keyboard - just a small circle button appears instead. This differs from older videos/tutorials.

**Quick Fix:** Tap the circle → "Show virtual keyboard" (must do each time)

**Permanent Fix - You need BOTH settings (I THINK??):**

**Step 1:** Settings → System → Keyboard → Physical keyboard
- Toggle ON "Show virtual keyboard"

**Step 2:** Settings → System → Keyboard → On-screen keyboard → Gboard → Write in text fields
- Check "Show on-screen keyboard"
- Uncheck the stylus options if checked

**Why Both? (I think)** Android has split keyboard settings across multiple menus (physical vs virtual), and both need to be configured for the keyboard to appear automatically like on a real phone.


**Why It Matters:** You need to see the virtual keyboard to understand what users experience with different keyboard types (numeric, email, etc.), even though typing with your physical keyboard is faster for development.

### InputDecoration - Making TextFields Beautiful
The `decoration` property transforms plain TextFields into professional-looking inputs:

> **📖 See Also:** [InputDecoration examples in TextField Reference](../reference/input-forms/textfield-basics.md#inputdecoration---styling-textfields)

```dart
TextField(
  decoration: InputDecoration(
    label: Text('Enter your name'),
    hintText: 'John Doe',
    border: OutlineInputBorder(),
    contentPadding: EdgeInsets.all(20),
    filled: true,
    fillColor: Colors.blue[50],
    prefixIcon: Icon(Icons.person),
    suffixIcon: Icon(Icons.clear),
  ),
)
```

**Remember:** 
- `filled` must be `true` for `fillColor` to work
- `enabledBorder` styles the field when not focused
- `focusedBorder` styles the field when user is typing

### Keyboard Types & Navigation

We explored how to show appropriate keyboards for different data types:

```dart
// Numeric input only
TextField(
  keyboardType: TextInputType.number,
)

// Date/time input
TextField(
  keyboardType: TextInputType.datetime,
)

// Email with @ symbol prominent
TextField(
  keyboardType: TextInputType.emailAddress,
)
```

**Text Input Actions** for better form flow:
- `TextInputAction.next` - Shows arrow to go to next field
- `TextInputAction.previous` - Shows back arrow
- `TextInputAction.done` - Shows checkmark to complete

### TextEditingController - Power User Features
Controllers give you programmatic control over TextFields:

> **📖 See Also:** [Complete TextEditingController guide](../reference/input-forms/textfield-basics.md#using-texteditingcontroller-recommended)

```dart
// Create controller
final txtNameController = TextEditingController();

// Use in TextField
TextField(
  controller: txtNameController,
)

// Pre-fill text
@override
void initState() {
  super.initState();
  txtNameController.text = 'Default text';
}

// Clean up to prevent memory leaks
@override
void dispose() {
  txtNameController.dispose();
  super.dispose();
}

// Clear programmatically
IconButton(
  icon: Icon(Icons.clear),
  onPressed: () => txtNameController.clear(),
)
```

**Why Use Controllers?**
- Pre-fill fields with data
- Clear fields with a button tap
- Access text value anytime (not just on submit)
- Add listeners for real-time updates
- Required for form validation (coming next class)

## Key Concepts & Terminology

| Term | Definition |
|------|------------|
| DropdownMenuItem | Individual option in a dropdown list |
| onChanged | Callback fired when dropdown selection changes |
| InputDecoration | Styling configuration for TextField |
| TextInputType | Determines which keyboard appears |
| TextInputAction | Controls keyboard action button behavior |
| TextEditingController | Manages TextField state programmatically |
| initState | Lifecycle method that runs before widget builds |
| dispose | Lifecycle method for cleanup when widget is removed |

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| Dropdown UI doesn't update | Wrap `onChanged` callback in `setState()` |
| "String? can't be assigned to String" | Add question mark: `String?` for nullable dropdown values |
| Keyboard covers TextField | Wrap page in SingleChildScrollView |
| fillColor doesn't show | Set `filled: true` in InputDecoration |
| Controller text not updating UI | Use `addListener` with `setState` or just use `onChanged` |
| Memory leak warnings | Always dispose controllers in `dispose()` method |
| Can't clear TextField | Use a TextEditingController and call `.clear()` |

## Key Takeaways

1. **Always use setState** - Both DropdownButton and TextField need setState to update UI
2. **Controllers are powerful** - More setup but much more capability than simple strings
3. **Decoration matters** - Good InputDecoration makes fields intuitive and professional
4. **Match keyboards to data** - Use appropriate TextInputType for better UX
5. **Dispose controllers** - Prevent memory leaks by cleaning up in dispose()
