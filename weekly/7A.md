### Understanding API Authentication Patterns
Many APIs require authentication through POST requests that return access tokens.

**Example Flow:**
1. POST to login endpoint with credentials
2. Receive access token in response
3. Include token in subsequent requests as Bearer authorization header

**Example Authentication Request:**
```json
{
  "username": "emilys",
  "password": "emilyspass",
  "expiresInMins": 30
}
```

**Important:** Not all APIs require authentication, but understanding this pattern prepares you for APIs that do. Always check API documentation first.

### Asynchronous Programming in DartPad
We explored why async programming is necessary using DartPad before moving to Flutter.

**The Problem - What Doesn't Work:**
```dart
// This looks like it should work, but doesn't!
sumNums(int a, int b) {
  return Future.delayed(Duration(seconds: 2), () {
    return a + b;
  });
}

void main() {
  var result = sumNums(10, 20);
  print(result);  // Prints: Instance of 'Future<dynamic>'
}
```

**The Solution - async/await:**
```dart
Future<int> sumNums(int a, int b) async {
  return Future.delayed(Duration(seconds: 2), () {
    return a + b;
  });
}

void main() async {
  var result = await sumNums(10, 20);
  print(result);  // Prints: 30 (after 2 seconds)
}
```

**Key Concepts:**
- `Future<T>` represents data that will arrive later
- `async` marks a function that performs asynchronous operations
- `await` pauses execution until the Future completes
- Think of it like ordering delivery - you get a promise (Future) and wait for it to arrive

**For more examples and common mistakes:** See the [Async/Await Fundamentals Reference](../reference/network/async-await-fundamentals.md)

### Error Handling with Try-Catch
APIs fail for many reasons - network issues, bad credentials, server problems. Always handle errors gracefully.

```dart
try {
  var result = await somethingThatMightFail();
  print('Success: $result');
} catch (err) {
  print('Error: $err');
}
```

**Basic HTTP GET Request:**
```dart
Future<void> doTheThing() async {
  String url = 'https://dummyjson.com/carts';
  
  var response = await http.get(Uri.parse(url));
  
  if (response.statusCode == 200) {
    var jsonResponse = jsonDecode(response.body);
    print(jsonResponse);
  } else {
    print('Error: ${response.statusCode}');
  }
}
```

**Critical Points:**
- `http.get()` requires `Uri.parse()` - can't pass a plain string
- Status code 200 means success
- Response body is a string - use `jsonDecode()` to convert to Map/List
- Import `dart:convert` for JSON decoding

### Debugging and Inspecting JSON
We used breakpoints to understand the structure of API responses. This is essential before building your UI.

**What We Found:**
- The response is a Map with `total` and `carts` keys
- `carts` is a List of 30 cart objects
- Each cart has `id`, `total`, `userId`, and `products` properties
- `products` is another nested List

**Practice accessing nested data in debug console:**
```dart
jsonResponse['total']                    // Get total count
jsonResponse['carts'][0]['userId']       // Get first cart's userId
jsonResponse['carts'][0]['products'][0]['title']  // Get product name
```

### Processing API Data for Display
Rather than working with the raw API response, we extracted only the data we needed into a clean list structure.

```dart
class _MainPageState extends State<MainPage> {
  List<Map<String, dynamic>> cartsList = [];

  Future<void> doTheThing() async {
    String url = 'https://dummyjson.com/carts';
    var response = await http.get(Uri.parse(url));
    
    if (response.statusCode == 200) {
      var jsonResponse = jsonDecode(response.body);
      List<Map<String, dynamic>> tempList = [];
      
      for (final cart in jsonResponse['carts']) {
        tempList.add({
          'userId': cart['userId'],
          'total': cart['total'],
          'products': cart['products'],
        });
      }
      
      setState(() {
        cartsList = tempList;
      });
    }
  }
}
```

**Why This Approach:**
- Extract only what you need (cleaner code)
- Create a predictable data structure
- Easier to display in UI
- Separates API structure from app structure

#### Why bother building your own data structure?

You *can* technically just hand the raw decoded JSON straight to your widgets and dig into it inline. But once the data is even a little nested, that gets ugly fast.

Imagine an API where each item has a `types` list and a `stats` list (think Pokémon — each Pokémon has multiple types and multiple stats). If you try to render that directly in a `ListView.builder`, you end up with something like:

```dart
ListView.builder(
  itemCount: pokemonList.length,
  itemBuilder: (context, index) {
    final pokemon = pokemonList[index];
    return Card(
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        children: [
          Text(pokemon["name"], style: TextStyle(fontWeight: FontWeight.bold)),
          ...(pokemon["types"] as List).map((t) {
            return Text("• ${t["type"]["name"]}");
          }).toList(),
          ...(pokemon["stats"] as List).map((s) {
            return Text("${s["stat"]["name"]}: ${s["base_stat"]}");
          }).toList(),
        ],
      ),
    );
  },
)
```

That's already gnarly — casts, spread operators, nested `.map()` calls — and it's only two nested lists. Add abilities, moves, sprites, and it becomes unreadable. You also can't drop a `for` loop in there directly; you're forced into `.map()` and chaining.

**The cleaner approach:** do your data wrangling *before* you get to the widget tree — exactly like the carts example above. Loop through the raw response in your fetch function and build a new `List<Map<String, dynamic>>` shaped exactly the way your UI wants it:

```dart
List<Map<String, dynamic>> processedPokemon = [];

for (var pokemon in rawList) {
  processedPokemon.add({
    "name": pokemon["name"],
    "types": (pokemon["types"] as List)
        .map((t) => t["type"]["name"])
        .join(", "),
    "topStats": (pokemon["stats"] as List)
        .map((s) => "${s["stat"]["name"]}: ${s["base_stat"]}")
        .join(", "),
  });
}
```

Now your widget is dead simple:

```dart
ListView.builder(
  itemCount: processedPokemon.length,
  itemBuilder: (context, index) {
    final p = processedPokemon[index];
    return ListTile(
      title: Text(p["name"]),
      subtitle: Text("${p["types"]}\n${p["topStats"]}"),
    );
  },
)
```

**The principle:** the widget tree should be dumb. Yes, building a second list adds a tiny bit of overhead, but the readability win is huge — and it makes debugging way easier because you can `print(processedPokemon)` and see exactly what your UI is about to render. Once you're more comfortable, the natural next step is making a real model class with a `fromJson` factory so you stop doing bracket notation everywhere — but a tailored `Map` is a perfectly good starting point.

**Bonus reason — real-world resilience:** Even in a production app, APIs change. Fields get renamed, endpoints get versioned, responses get restructured. If every widget in your app reaches into the raw JSON directly, an API change means hunting through your whole UI to fix it. If you've got one function that maps the raw response into *your* shape, you fix it in one place and the rest of the app doesn't notice. Decoupling your UI from the API's structure is genuinely good engineering, not just a learning-exercise convenience.

### Displaying Data with ListView.builder
We replaced the empty container with a dynamic list that updates when data arrives.

```dart
Expanded(
  child: Container(
    color: Colors.blueGrey,
    child: ListView.builder(
      itemCount: cartsList.length,
      itemBuilder: (context, index) {
        return ListTile(
          tileColor: Colors.amber[50],
          minVerticalPadding: 5,
          title: Text('User ID: ${cartsList[index]['userId']}'),
          subtitle: Text('Products: ${cartsList[index]['products'].length}'),
          trailing: Text('\$${cartsList[index]['total']}'),
        );
      },
    ),
  ),
)
```

**The Pattern:**
1. Button press triggers async function
2. Function fetches data from API
3. Data is processed and stored in state
4. `setState()` triggers UI rebuild
5. ListView.builder creates tiles from the data

### Important: Chrome/Web vs Android (CORS)

If you're running your app in **Chrome** (Flutter web), you may see API calls fail with a `ClientException: Failed to fetch` error - even though your code is correct. This is caused by **CORS** (Cross-Origin Resource Sharing), a browser security restriction that blocks web pages from making requests to a different domain unless that domain explicitly allows it.

**This does NOT happen on Android or iOS** - mobile platforms make HTTP requests natively, not through a browser, so CORS doesn't apply.

**Why our DummyJSON examples work on Chrome:** DummyJSON is designed as a testing/learning API and has CORS enabled - it allows requests from any origin. But many real-world APIs (government APIs, some news APIs, etc.) do NOT have CORS headers, so they'll fail on Chrome but work perfectly on Android.

**What to do if your API fails on Chrome:**
- **Best option:** Run on an Android emulator instead of Chrome - this is how your app will actually be used
- **Quick workaround:** Prefix your URL with a CORS proxy like `https://corsproxy.io/?` (e.g., `'https://corsproxy.io/?https://some-api.com/data'`). This is fine for development but not for production apps.
- **Check first:** Some APIs support CORS and some don't - test your API URL in the browser first to see if you get blocked

> **For more details on CORS and other platform-specific issues,** see the [HTTP & API Integration Reference - CORS section](../reference/network/http-api-integration.md#cors-cross-origin-resource-sharing-web-only).

This is especially relevant when using `initState()` to load data on startup (below) - if it fails silently on Chrome, CORS is likely the reason.

### Loading Data on App Startup
Rather than requiring a button click, we can load data automatically when the app opens using `initState()`.

**The Challenge:** Can't make `initState()` async directly

**The Solution:** Call an async function from `initState()`

```dart
@override
void initState() {
  super.initState();
  doStartupStuff();
}

Future<void> doStartupStuff() async {
  await doTheThing();
}
```

## Key Concepts & Terminology

| Term | Definition |
|------|------------|
| Future | A promise of data that will arrive later (like a delivery receipt) |
| async | Marks a function that can perform asynchronous operations |
| await | Pauses execution until a Future completes |
| http.get() | Makes a GET request to a URL |
| Uri.parse() | Converts a string URL into a Uri object |
| jsonDecode() | Converts JSON string into Dart Map or List |
| setState() | Triggers UI rebuild when data changes |
| Status Code 200 | HTTP success response |
| Bearer Token | Authentication token passed in request headers |
| initState() | Lifecycle method that runs before widget builds |

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| UI doesn't update after API call | Wrap state changes in `setState()` |
| "Instance of Future" instead of data | Add `await` before the async call |
| "Cannot be assigned to type Uri" | Use `Uri.parse(url)` not just the string |
| JSON decode errors | Check response with breakpoint first, verify structure |
| Package not found after adding | Do hot restart, not just hot reload |
| Can't access nested data | Use debug console to inspect full structure |
| initState won't work with async | Call async function FROM initState, don't make it async |
| `ClientException: Failed to fetch` on Chrome | CORS issue - see [CORS section above](#important-chromeweb-vs-android-cors). Run on Android or use a CORS proxy |
