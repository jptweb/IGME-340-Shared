# Week 6B - Form Validation, Checkboxes & ListView

## First: Fix Trailing Comma Formatting (Dart 3.8+)

If the Dart formatter has been **forcing your code onto one line** (ignoring your trailing commas), this is a recent change in Dart 3.8+. The new default formatter decides line breaks for you, which removes the "trailing comma = new line" behavior we've relied on all semester.

**The Fix:** Add this to your project's `analysis_options.yaml` (in the root of your Flutter project):

```yaml
formatter:
  trailing_commas: preserve
```

This tells the formatter to **preserve** your trailing comma formatting choices - if you add a trailing comma, the formatter will keep each parameter on its own line (the behavior you're used to). Without this setting, the formatter may collapse short parameter lists onto one line regardless of trailing commas.

Do this for any new projects going forward, and update your existing projects if the formatting is bothering you.

### Form Widget & Validation
Building on our TextField knowledge from Week 6A, we learned how to validate user input before processing it. The Form widget acts as a container that can validate all its children at once.

**Key Points:**
- Form requires a GlobalKey to maintain state across rebuilds
- TextFormField replaces TextField when using forms
- Validator functions return `null` if input is valid (counterintuitive but standard!)
- One button press can validate entire form at once

**Basic Form Setup:**
```dart
class _MainPageState extends State<MainPage> {
  final _myFormId = GlobalKey<FormState>();

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Form(
        key: _myFormId,
        child: Column(
          children: [
            // Form fields go here
          ],
        ),
      ),
    );
  }
}
```

### Validation Functions
Every TextFormField can have a validator function that checks if input is acceptable:

```dart
TextFormField(
  validator: (value) {
    if (value == null || value.isEmpty) {
      return 'Please enter some text';
    } else if (value.length < 5) {
      return 'Not long enough';
    }
    return null; // null = valid!
  },
)
```

**Form Submission:**
```dart
ElevatedButton(
  onPressed: () {
    if (_myFormId.currentState!.validate()) {
      // All fields passed validation!
      ScaffoldMessenger.of(context).showSnackBar(
        SnackBar(content: Text('Processing data')),
      );
    }
  },
  child: Text('Submit'),
)
```

### Auto-Validation Mode
You can validate as users type, but consider the UX implications:

```dart
Form(
  key: _myFormId,
  autovalidateMode: AutovalidateMode.onUserInteraction,
  // ... children
)
```

**Trade-offs:**
- **Pros:** Immediate feedback helps users fix errors
- **Cons:** Can be annoying if validation happens before user finishes typing

### Using Validation Packages
Don't reinvent the wheel for complex validation like emails:

**Setup:**
```bash
flutter pub add email_validator
```

**Usage:**
```dart
import 'package:email_validator/email_validator.dart';

TextFormField(
  decoration: InputDecoration(labelText: 'Email'),
  keyboardType: TextInputType.emailAddress,
  validator: (value) {
    if (value != null && !EmailValidator.validate(value)) {
      return 'Please enter valid email';
    }
    return null;
  },
)
```

## Checkbox Widgets

### Basic Checkbox
Simple checkbox that requires manual state management:

```dart
// At top of State class:
bool? chk01 = false;

// In build method:
Checkbox(
  value: chk01,
  onChanged: (value) {
    setState(() {
      chk01 = value;
    });
  },
)
```

**⚠️ Important:** The boolean must be nullable (`bool?`) because checkboxes support tri-state mode.

### Tri-State Checkbox
Can cycle through true → false → null (indeterminate):

```dart
Checkbox(
  value: chk01,
  tristate: true,  // Enables three states
  activeColor: Colors.red,
  onChanged: (value) {
    print(value); // Outputs: true, false, or null
    setState(() {
      chk01 = value;
    });
  },
)
```

### CheckboxListTile - Better UX
Makes the entire row tappable, not just the tiny checkbox:

```dart
bool? chk02 = false;

CheckboxListTile(
  value: chk02,
  onChanged: (value) {
    setState(() {
      chk02 = value;
    });
  },
  title: Text('Check if cool'),
  subtitle: Text('Subtitle here'),
  controlAffinity: ListTileControlAffinity.leading, // Checkbox on left
  secondary: Icon(Icons.access_alarm),  // Extra icon on opposite side
  activeColor: Colors.green,
  checkColor: Colors.pink,
  shape: RoundedRectangleBorder(
    borderRadius: BorderRadius.circular(10),
  ),
)
```

## ListView for Scrollable Content

### Basic ListView
Simple vertical scrolling list:

```dart
Container(
  height: 200,  // Must have bounded height!
  child: ListView(
    padding: EdgeInsets.all(10),
    children: [
      Text('List Item 1'),
      Text('List Item 2'),
      Text('List Item 3'),
      // ... more items
    ],
  ),
)
```

**⚠️ Critical:** ListView MUST be in a bounded container or you'll get RenderBox errors!

### Horizontal ListView
Change scroll direction for horizontal scrolling:

```dart
Container(
  height: 200,
  child: ListView(
    scrollDirection: Axis.horizontal,
    reverse: false, // true to reverse order
    children: [
      Container(
        width: 150,
        color: Colors.amber,
        child: Center(child: Text('Item 01')),
      ),
      // ... more containers
    ],
  ),
)
```

### ListView.builder - Dynamic Lists

Unlike the basic ListView where you manually list out children, `ListView.builder` generates items from data. This is the pattern you'll use for Project 2 when displaying API results.

#### Step 1: Set Up Your Data

Add this at the top of your State class (alongside your other state variables):

```dart
List<Map<String, dynamic>> inventory = [
  {'name': 'Apple', 'price': 10},
  {'name': 'Banana', 'price': 20},
  {'name': 'Coconut', 'price': 30},
  {'name': 'Durian', 'price': 40},
  {'name': 'Fig', 'price': 10},
  {'name': 'Grape', 'price': 10},
  {'name': 'Honeydew', 'price': 20},
  {'name': 'Kiwi', 'price': 10},
];
```

**What's happening:** We're using a `List<Map<String, dynamic>>` - a list where each item is a map with string keys. This is similar to what you'd get back from an API call.

#### Step 2: Basic ListView.builder

Add this in your build method (still needs a bounded Container like before):

```dart
Container(
  height: 200,
  child: ListView.builder(
    itemCount: inventory.length,
    itemBuilder: (context, index) {
      return Text('${inventory[index]['name']}');
    },
  ),
)
```

**What's happening:**
- `itemCount` tells it how many items to build
- `itemBuilder` is a function that gets called for each item - it receives the `index` so you can look up the right data
- Right now each item is just a plain Text widget

#### Step 3: Upgrade to ListTile with Interactivity

Replace the simple `Text` with a styled `ListTile` that responds to taps:

```dart
Container(
  height: 200,
  child: ListView.builder(
    itemCount: inventory.length,
    itemBuilder: (context, index) {
      return ListTile(
        title: Text('${inventory[index]['name']}'),
        trailing: Text('\$${inventory[index]['price']}'),
        onTap: () {
          ScaffoldMessenger.of(context).showSnackBar(
            SnackBar(
              content: Text('Selected: ${inventory[index]['name']}'),
            ),
          );
        },
        tileColor: Colors.blueGrey,
        shape: RoundedRectangleBorder(
          borderRadius: BorderRadius.circular(10),
        ),
      );
    },
  ),
)
```

**What's happening:**
- `ListTile` gives us a pre-styled row with `title`, `trailing`, and tap handling built in
- `onTap` fires a SnackBar showing which item was selected
- `tileColor` and `shape` add visual styling

**Why ListView.builder?**
- Efficient for large lists (only builds visible items)
- Perfect for dynamic data (API responses, databases)
- Can be infinite if you don't set itemCount
- Essential for Project 2!

## Key Concepts & Terminology

| Term | Definition |
|------|------------|
| GlobalKey | Maintains widget identity and state across rebuilds |
| Form | Widget that groups and validates form fields together |
| TextFormField | TextField with built-in validation support |
| Validator | Function that returns error message or null if valid |
| AutovalidateMode | Controls when validation happens (on submit, on interaction, etc.) |
| Tri-state | Checkbox mode supporting true/false/null values |
| CheckboxListTile | Checkbox with text label and full-row tap area |
| ListView.builder | Efficient list creation for dynamic content |
| ListTile | Pre-styled row widget commonly used in lists |
| itemBuilder | Function that creates list items on demand |

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| Form won't validate | Check that you added `!` after currentState: `_myFormId.currentState!.validate()` |
| Validator not running | Make sure you're using TextFormField, not TextField |
| Checkbox won't update UI | Must wrap state change in `setState()` |
| RenderBox ListView error | Wrap ListView in Container with explicit height |
| ListView.builder empty | Verify itemCount matches your data length |
| Can't tap ListView items | Make sure ListTile has onTap callback |
