### Getting Started with Flame

We set up a Flame project from scratch, learning how to:
- Structure a game with `GameWidget` and `FlameGame`
- Load and display sprite images
- Use the component system to organize game objects
- Access game properties from components using mixins

### Movement Systems

We implemented three different control schemes:
1. **Pan Gestures** - Drag the sprite around directly
2. **Tap Movement** - Tap where you want the sprite to move smoothly
3. **Joystick Controls** - On-screen virtual joystick with rotation

## Key Concepts & Terminology

| Term | Definition |
|------|----------|
| **FlameGame** | Base class for your game - extends this to create your game logic |
| **GameWidget** | Flutter widget that renders a Flame game - can be used full-screen or embedded |
| **SpriteComponent** | A game object that displays an image - has built-in position, size, rotation |
| **Mixin** | Adds functionality to a class using `with` keyword (PanDetector, TapCallbacks, etc.) |
| **onLoad()** | Lifecycle method that runs once when a component is created - use for initialization |
| **update(dt)** | Lifecycle method that runs every frame (~60 FPS) - dt is time since last frame |
| **Vector2** | Flame's 2D coordinate class for positions, directions, and movement |
| **HasGameReference** | Mixin that gives components access to the game instance via `game.` |
| **Anchor** | The reference point of a sprite (center, topLeft, etc.) - affects rotation and positioning |
| **JoystickComponent** | Built-in Flame component for on-screen joystick controls |

## Step-by-Step: Building Your First Flame Game

### Part 1: Project Setup (Steps 1-2)

#### Step 1: Add Your Sprite Image

Create this folder structure in your Flutter project:
```
your_project/
  ├── assets/
  │   └── images/
  │       └── player.png
```

Update your `pubspec.yaml`:
```yaml
flutter:
  assets:
    - assets/images/
```

**💡 Tip:** The trailing slash (`/`) loads ALL images in that folder automatically.

#### Step 2: Install Flame Package

Run this in your terminal:
```bash
flutter pub add flame
```

This adds Flame to your project's dependencies.

> **📖 Reference:** See [GameWidget & FlameGame Basics](../reference/flame/gamewidget-basics.md) for more on project setup and configuration.

### Part 2: Display a Sprite (Steps 3-12)

#### Step 3-4: Replace main.dart with Game Structure

Start by replacing your entire `main.dart`:

```dart
import 'package:flutter/material.dart';
import 'package:flame/game.dart';

void main() {
  runApp(
    GameWidget(
      game: FlameDemoGame(),
    )
  );
}

class FlameDemoGame extends FlameGame {
  // Your game code will go here
}
```

**What's happening:**
- `GameWidget` is Flame's special widget that renders games
- `FlameDemoGame` is your custom game class
- When you run this, you'll see a black screen (this is correct!)

#### Step 5: Load Your Sprite Image

Add `onLoad()` to your `FlameDemoGame` class:

```dart
class FlameDemoGame extends FlameGame {
  
  @override
  Future<void> onLoad() async {
    await images.loadAll([
      "player.png"  // Just the filename - it knows to look in assets/images/
    ]);
  }
}
```

### Step 5a: make sure you have imported at top:
import 'dart:async';

**Key points:**
- `onLoad()` runs once when the game starts
- `images.loadAll()` preloads images so they're ready to use
- Notice the file path is just `"player.png"` - Flame automatically looks in `assets/images/`

> **⚠️ Watch the casing!** The method is `onLoad()` with a capital **L** - NOT `onload()`. Dart is case-sensitive, so `onload()` will compile without errors but it will **never be called** by Flame. Your screen will just stay black and nothing will load. Always add the `@override` annotation - if you misspell the method name, the compiler will warn you that you're not actually overriding anything.

> **💡 IDE Autocomplete Tip:** When you type `@override` in your class, the IDE will suggest `FutureOr<void> onLoad()` as the signature. This works fine! `FutureOr<void>` just means the method can return either a `Future<void>` or plain `void`. Writing `Future<void> onLoad() async` (like in the examples below) is equally valid since `Future` satisfies `FutureOr`. Either signature works - use whichever you prefer.

#### Steps 6-9: Create Player Class (Gradually)

Create a new file called `player.dart`:

**First, add the imports:**
```dart
import 'dart:async';
import 'package:flame/components.dart';
import 'main.dart';
```

- `dart:async` - Needed for `FutureOr` if using the autocomplete signature for `onLoad`
- `flame/components.dart` - Gives us `SpriteComponent`, `Vector2`, `Anchor`, `JoystickComponent`, etc.
- `main.dart` - So we can reference `FlameDemoGame` in the `HasGameReference` mixin

**Then create the class structure:**
```dart
class Player extends SpriteComponent with HasGameReference<FlameDemoGame> {
  // Code will go here
}
```

**What each part does:**
- `extends SpriteComponent` - Gives you sprite properties like `position`, `size`, `anchor`, `angle`
- `with HasGameReference<FlameDemoGame>` - Lets you access the game via `game.` (needed for screen size, loaded images, etc.)

#### Step 10: Initialize the Sprite

Add the `onLoad()` method to your `Player` class:

```dart
class Player extends SpriteComponent with HasGameReference<FlameDemoGame> {
  
  //Note the VS code auto complete WONT really help here!
  @override
  Future<void> onLoad() async {
    sprite = Sprite(game.images.fromCache("player.png"));
    anchor = Anchor.center;
    height = 100;
    width = 100;
    position = Vector2(game.size.x / 2, game.size.y - 100);
  }
}
```

**Breaking it down:**
- `sprite = Sprite(game.images.fromCache(...))` - Gets your preloaded image
- `anchor = Anchor.center` - Makes the sprite's center point be its "handle" (better for rotation!)
- `height` and `width` - Display size in pixels
- `position = Vector2(x, y)` - Screen coordinates (0,0 is top-left)
  - `game.size.x / 2` = horizontal center
  - `game.size.y - 100` = 100 pixels from bottom

#### Step 11: Add Update Method (For Later)

Add this to your `Player` class:

```dart
@override
void update(double dt) {
  super.update(dt);
  // We'll use this later for movement logic
}
```

**What is `dt`?**
- Stands for "delta time" - time since last frame in seconds
- On 60 FPS, `dt` is about 0.016 seconds
- Use it to make movement frame-rate independent

#### Step 12: Add Player to the Game

Update your `main.dart` to create and add the player:

```dart
import 'player.dart';  // Add this import at the top

class FlameDemoGame extends FlameGame {
  late Player player;  // Declare the player variable
  
  @override
  Future<void> onLoad() async {
    await images.loadAll(["player.png"]);
    
    player = Player();  // Create the player
    add(player);        // Add it to the game (makes it visible!)
  }
}
```

**🎉 Checkpoint:** You should now see your spaceship sprite on a black background!

> **📖 Reference:** See [Sprite Components](../reference/flame/sprite-components.md) for complete property reference and advanced patterns.

### Part 3: Add Drag Movement (Steps 13-16)

> **🎮 Game Design Note:** Drag movement is similar to how you'd control a paddle in Pong — the player directly follows your finger/cursor. This is great for games where you want tight, 1:1 control over an object's position.

#### Step 13-14: Add Pan Gesture Support

Update your game class to include the `PanDetector` mixin:

```dart
w  // Add this import

class FlameDemoGame extends FlameGame with PanDetector {
  late Player player;
  
  @override
  Future<void> onLoad() async {
    await images.loadAll(["player.png"]);
    player = Player();
    add(player);
  }
  
  @override 
  void onPanUpdate(DragUpdateInfo info) {
    player.move(info.delta.global);
  }
}
```

**What's new:**
- `with PanDetector` adds drag gesture detection
- `onPanUpdate` fires continuously while dragging
- `info.delta.global` is how much the drag moved since last frame

**⚠️ Important:** When you add/remove mixins, you need to do a **full restart**, not just hot reload!

#### Step 15: Create the Move Method

Add this method to your `Player` class:

```dart
void move(Vector2 delta) {
  position.add(delta);
}
```

This moves the sprite by adding the drag offset to its current position.

#### Step 16: Test It!

Save and **restart** (not hot reload). You should now be able to click and drag your sprite around!

**✅ Checkpoint:** Your sprite should move smoothly when you drag it.

> **📖 Reference:** See [Input Handling](../reference/flame/input-handling.md) for all available input mixins and advanced touch patterns.

### Part 4: Tap-to-Move (Steps 17-20)

Let's switch from dragging to tapping. First we'll make the sprite **jump** to where you tap, then we'll upgrade it to **smooth movement**.

#### Step 17: Create the moveTo Method in Player

**In player.dart,** add a simple `moveTo()` method that instantly moves the sprite:

```dart
void moveTo(Vector2 targetPosition) {
  position = targetPosition;
}
```

This just sets the position directly — the sprite will teleport to wherever you tap.

#### Step 18: Switch to Tap Detection in Main

**In main.dart,** replace `PanDetector` with `TapCallbacks`:

```dart
import 'package:flame/events.dart';

class FlameDemoGame extends FlameGame with TapCallbacks {  // Changed from PanDetector
  late Player player;

  @override
  Future<void> onLoad() async {
    await images.loadAll(["player.png"]);
    player = Player();
    add(player);
  }

  @override
  void onTapUp(TapUpEvent event) {
    player.moveTo(event.localPosition);
  }
}
```

**What changed:**
- `TapCallbacks` instead of `PanDetector`
- `onTapUp` fires when you release a tap
- `event.localPosition` is where you tapped on the screen

**🎉 Checkpoint:** Tap anywhere and your sprite should instantly jump to that position!

#### Steps 19-20: Upgrade to Smooth Movement

Now let's make the sprite glide to the tap position instead of teleporting.

**In player.dart,** add a target position variable at the top of your class:

```dart
class Player extends SpriteComponent with HasGameReference<FlameDemoGame> {
  late Vector2 moveTarget = Vector2.zero();  // Where the sprite is heading - starts at (0, 0)

  // Rest of your code...
}
```

**What is `Vector2.zero()`?** It creates a Vector2 with x=0 and y=0. We use `late` because we'll set the real initial value in `onLoad()` once we know the sprite's starting position.

**Update your `onLoad()` to initialize the target:**

```dart
@override
Future<void> onLoad() async {
  sprite = Sprite(game.images.fromCache("player.png"));
  anchor = Anchor.center;
  height = 100;
  width = 100;
  position = Vector2(game.size.x / 2, game.size.y - 100);
  moveTarget = position.clone();  // Start with target = current position
}
```

**Update `moveTo()` to set the target instead of jumping directly:**

```dart
void moveTo(Vector2 targetPosition) {
  moveTarget = targetPosition;
}
```

**Update your `update()` method with movement logic:**

```dart
@override
void update(double dt) {
  super.update(dt);

  // Only move if we're not at the target yet
  if (position.distanceTo(moveTarget) > 1) {
    Vector2 direction = (moveTarget - position).normalized();
    position.add(direction * 100 * dt);  // 100 = speed in pixels/second
  }
}
```

**How this works:**
1. Check if we're close enough to the target (within 1 pixel)
2. Calculate direction vector from current position to target
3. Normalize it (make length = 1) so we move at consistent speed
4. Move along that direction at 100 pixels/second

**The math:**
- `moveTarget - position` = vector pointing from current spot to target
- `.normalized()` = same direction but length of 1
- `* 100` = speed in pixels per second
- `* dt` = scale by frame time so speed is consistent regardless of frame rate

**Walking through it frame by frame:** Say your sprite is at `(50, 50)` and you tap at `(350, 50)`:

- Frame 1: `position = (50, 50)`, direction is `(1, 0)` (pointing right). `position.add(...)` adds ~1.6 pixels → position becomes `(51.6, 50)`
- Frame 2: `position = (51.6, 50)`, same direction, adds ~1.6 → `(53.2, 50)`
- Frame 3: `(54.8, 50)` ... and so on
- Hundreds of frames later: `position = (349.5, 50)`, distance to target is `0.5` which is less than `1`, so the `if` is false and it stops

The key is that `position.add(...)` is what actually moves the sprite each frame — it keeps nudging it a tiny bit toward the target. The `> 1` check is just telling it when to stop (close enough!).

**🎉 Checkpoint:** Tap anywhere and watch your sprite smoothly glide to that position!

### Part 5: On-Screen Joystick (Steps 21-26)

Let's add a mobile-friendly joystick control with rotation!

#### Steps 21-22: Update Player to Accept a Joystick

**In player.dart,** add a joystick field and a constructor that requires it:

```dart
class Player extends SpriteComponent with HasGameReference<FlameDemoGame> {
  final JoystickComponent joystick;

  Player({required this.joystick});  // Constructor requires joystick

  // Rest of your code stays the same...
}
```

**Replace your `update()` method to use the joystick for movement:**

```dart
@override
void update(double dt) {
  super.update(dt);

  // Only move if joystick is being touched
  if (!joystick.delta.isZero()) {
    position.add(joystick.relativeDelta * 300 * dt);
  }
}
```

**How this works:**
- `joystick.delta` = how far the knob is from center
- `.isZero()` checks if joystick is being used
- `joystick.relativeDelta` = normalized direction (-1 to 1 range)
- `300` = speed in pixels/second (faster than tap movement)

#### Step 23: Set Up main.dart for the Joystick

We need to make several changes to `main.dart`. Let's do them one at a time.

**Step 23a: Add new imports** at the top of `main.dart`:

```dart
import 'package:flame/components.dart';
import 'package:flame/palette.dart';
```

These give us `JoystickComponent`, `CircleComponent`, and `BasicPalette`.

**Step 23b: Remove tap controls.** Change your class declaration from `FlameGame with TapCallbacks` back to just `FlameGame`. Also delete the `onTapUp` method — the joystick handles its own touch input, so no mixin is needed:

```dart
class FlameDemoGame extends FlameGame {  // No mixin needed for joystick
```

**Step 23c: Add joystick variables** to your game class, right below `late Player player;`:

```dart
late Player player;
late JoystickComponent joystick;

// Visual styles for the joystick
final knobPaint = BasicPalette.red.withAlpha(200).paint();
final knobBgPaint = BasicPalette.red.withAlpha(100).paint();
```

#### Step 24: Create the Joystick and Wire It Up

**Replace your `onLoad()` method** with the joystick setup:

```dart
@override
Future<void> onLoad() async {
  await images.loadAll(["player.png"]);
   
  //STEP 1
  //**DO THIS - CREATE JOYSTICK!
  joystick = JoystickComponent(
    knob: CircleComponent(
      radius: 15,
      paint: knobPaint,
    ),
    background: CircleComponent(
      radius: 50,
      paint: knobBgPaint,
    ),
    margin: const EdgeInsets.only(left: 20, bottom: 20),
  );

  //STEP 2
  //**DO THIS - PASS JOYSTICK TO PLAYER!
  player = Player(joystick: joystick);  // Pass joystick to player
  
  add(player);
  
  //STEP 3
  //**DO THIS - ADD JOYSTICK!
  add(joystick);  // Don't forget to add joystick to the game!
}
```

**Breaking it down:**
- `JoystickComponent` is built into Flame
- `knob` = the small circle you drag
- `background` = the larger circle showing the joystick boundary
- `CircleComponent` draws circles without needing image files
- `BasicPalette.red.withAlpha(200)` = red color with transparency (0-255 scale)
- `margin` positions the joystick on screen (20px from left and bottom edges)

**🎉 Checkpoint:** You should see a semi-transparent red joystick in the bottom-left. Drag it to move your sprite!

> **📖 Reference:** See [JoystickComponent](../reference/flame/joystick-component.md) for styling options and complete joystick patterns.

#### Steps 25-26: Add Rotation

Add one line to your `update()` method:

```dart
@override
void update(double dt) {
  super.update(dt);
  
  if (!joystick.delta.isZero()) {
    position.add(joystick.relativeDelta * 300 * dt);
    angle = joystick.delta.screenAngle();  // Add this line!
  }
}
```

**🎉 Final Result:** Your sprite now rotates to face the direction you're moving!

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| Black screen but no sprite | Check your `pubspec.yaml` asset path and ensure image filename matches exactly (including `.png`). Also make sure `onLoad()` has a capital **L** - `onload()` will silently do nothing! |
| "Player not defined" error | Make sure `player.dart` exists and you've imported it in `main.dart` |
| Drag/tap doesn't work | Did you restart the app after adding/changing a mixin? (Hot reload doesn't work for mixin changes) |
| Sprite jumps around weirdly | Ensure `anchor = Anchor.center` is set in your player's `onLoad()` |
| Joystick not visible | Make sure you called `add(joystick)` in the game's `onLoad()` |
| Movement too fast/slow | Adjust the speed multiplier (the `100` or `300` values in your movement calculations) |
| Sprite doesn't rotate | Check that `anchor = Anchor.center` is set (rotates around anchor point) |

## Key Takeaways

1. **Game Loop Basics** - `update(dt)` runs every frame, `onLoad()` runs once at initialization
2. **Component System** - Sprites are components you `add()` to the game
3. **Mixins Are Powerful** - `with PanDetector`, `with TapCallbacks`, `with HasGameReference` add functionality without inheritance
4. **Delta Time Matters** - Always multiply movement by `dt` for frame-rate independence
5. **Vector Math** - `Vector2` handles positions and directions, `.normalized()` creates unit vectors
6. **Anchors Affect Everything** - Set `anchor = Anchor.center` for intuitive rotation and positioning

## Embedding Flame in a Flutter App (Bonus)

Want to add your game to a regular Flutter app with an AppBar? Replace your `main()`:

```dart
void main() {
  runApp(const MainApp());
}

class MainApp extends StatelessWidget {
  const MainApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(
          title: const Text("My Game"),
          backgroundColor: Colors.blue,
        ),
        body: GameWidget(
          game: FlameDemoGame(),
        ),
      ),
    );
  }
}
```

Now your game lives in the `body` and you can add drawers, navigation, etc.!
