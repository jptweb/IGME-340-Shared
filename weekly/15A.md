## II. Adding a New Package: Harder Than It Should Be

Flutter has thousands of packages on pub.dev — most are great. The frustrating part: many "examples" point at separate `example/` directories with their own dependencies and `main.dart` setups. You can't just copy-paste them into your app and run — you have to reverse-engineer what's load-bearing. It's easy to lose 30 minutes on this and give up.

**The fix for today:** I built a small showcase app where each package gets its own page with a working demo and a copy-pasteable code snippet. No wild goose chase.

> Clone it, run it, and steal whatever code you want for Project 3.

## III. Five Polish Packages Worth Knowing

These are all **drop-in** — none require architectural changes. Pick whatever fits your project.

| Package | What It Does | When to Reach for It |
|---|---|---|
| **[flutter_animate](https://pub.dev/packages/flutter_animate)** | Declarative animations: `myWidget.fadeIn().slide()` — chainable, no controllers | Any time you want widgets to enter, exit, or grab attention with a smooth transition |
| **[skeletonizer](https://pub.dev/packages/skeletonizer)** | Auto-generated skeleton loading states — wrap your widget, done | Any screen that loads data from an API. Replaces the "blank screen / spinner" awkward moment |
| **[lottie](https://pub.dev/packages/lottie)** | Plays JSON animations from After Effects (free files at [lottiefiles.com](https://lottiefiles.com)) | When you want a polished, designer-quality animation without building it yourself |
| **[confetti](https://pub.dev/packages/confetti)** | Drops confetti on screen | Celebration moments — completed tasks, high scores, "you did it!" beats |
| **[share_plus](https://pub.dev/packages/share_plus)** | Native share sheet — `Share.share('text')` opens the iOS/Android system share UI | Any time you want users to send content somewhere (Messages, Mail, Slack, etc.) |

**See them all working:** clone and run [flutter-polish-sample-app](https://github.com/jptweb/flutter-polish-sample-app) — each package has its own page with the minimal code needed.

## IV. What's Beyond This Class

Things we couldn't fit, but you'll meet in the wild. Search any of these names when you're ready:

- **State management beyond Provider** — [Riverpod](https://riverpod.dev/) (modern successor to Provider) and [Bloc](https://bloclibrary.dev/) (pattern-heavy, common at larger companies)
- **Backends as a service** — [Firebase](https://firebase.google.com/): auth, real-time database, file storage, hosting, cloud functions. Big enough to be its own course.
- **Testing** — `flutter_test` (built-in), `mockito` for mocking, `integration_test` for full app flows. You'll start writing these on day one of any team
- **CI/CD** — [GitHub Actions for Flutter](https://github.com/marketplace/actions/flutter-action) auto-builds APKs, web bundles, etc. on every push
- **Crash reporting** — Firebase Crashlytics, [Sentry](https://sentry.io/for/flutter/) — production telemetry
