# Week 11A - TabBar and BottomNavigationBar

## Overview
Today we covered two advanced navigation patterns in Flutter:
- **TabBar Navigation** - tabs at the top of your app
- **BottomNavigationBar** - navigation at the bottom of your app

> **📖 Quick Reference:** See [TabBar & TabBarView Reference](../reference/navigation/tabbar-tabbarview.md) and [BottomNavigationBar Reference](../reference/navigation/bottomnavigationbar.md) for code examples and properties.

### STEPS 5 AND 6: Pages in Their Own Files (already in the starter)

Nothing to type. In past semesters we built each page as a `Container` and then moved it into its own file. Your starter already has that done. Open `page_home.dart` to see the pattern:

```dart
class _PageHomeState extends State<PageHome> {
  @override
  Widget build(BuildContext context) {
    return Container(
      width: double.infinity,
      height: double.infinity,
      color: Colors.red[50],
      child: Center(child: Text("Home Page")),
    );
  }
}
```

Using a StatefulWidget even for a static page leaves room to add interactivity later. That's what `page_search.dart` does.

**Tip:** when you create a new file, type `stfu` and press Tab to generate a StatefulWidget with the material import already included. You'll use this in Step 10.

### STEP 8: The Reset (already in the starter)

Nothing to type. Tap Increment a few times, switch to Settings, then come back to Search.

**The counter is back to 0.** TabBarView throws away the pages you aren't looking at. When you come back, it builds a brand new one, so the state is gone. Step 9 fixes that.

### STEP 9: Keep the Search Page Alive

All three changes are in `page_search.dart`.

**9a. Where:** the State class line, under `TODO Step 9`. **Change** it:

```dart
class _PageSearchState extends State<PageSearch> with AutomaticKeepAliveClientMixin {
// was: class _PageSearchState extends State<PageSearch> {
```

**9b. Where:** under `int counter = 0;`.

```dart
int counter = 0;   // already there

@override
bool get wantKeepAlive => true;
```

**9c. Where:** the first line inside `build`, above `return Container(`.

```dart
super.build(context);
```

**Test it:** hot restart. Increment, switch tabs, and come back. The count stays.

The mixin is the page asking not to be thrown away, and `wantKeepAlive` returning `true` is the yes.

**Note on `super.build(context)`:** in modern Flutter (3.24+), the mixin also registers keep-alive in `initState()`, so the counter works even without this line. Keep it anyway: the method is marked `@mustCallSuper`, so VS Code warns you if it's missing, and it covers cases this demo doesn't hit.

## PART 2: BOTTOM NAVIGATION BAR

### STEP 10: Start Fresh with a New File

TabBar and BottomNavigationBar are different patterns, so the bottom nav gets its own file. Both reuse the same pages.

**10a. Where:** a new file, `lib/demo_11a_bottomnav.dart`. Type `stfu`, press Tab, and name the class `Demo11aBottomNav`. Add the page imports under the material import:

```dart
import 'package:flutter/material.dart';   // already there
import 'page_home.dart';
import 'page_search.dart';
import 'page_settings.dart';
```

Then make `build` return a Scaffold:

```dart
return Scaffold(
  appBar: AppBar(title: Text("Bottom Nav Demo")),
  body: Center(child: Text("Body goes here")),
);
```

Until Step 11, the three page imports show `unused_import` warnings. That's expected. Step 11 uses them.

**10b. Where:** the top of `main.dart`, under the page imports.

```dart
import 'page_settings.dart';   // already there
import 'demo_11a_bottomnav.dart';
```

**10c. Where:** `MainApp`'s `build`, under `TODO Step 10`. Comment out the `Demo11a` line and add the new one:

```dart
//return const MaterialApp(home: Demo11a());   // was the live line
return MaterialApp(home: Demo11aBottomNav());
```

**Test it:** hot restart. You see "Bottom Nav Demo" and "Body goes here."

**Tip:** `home:` is just which widget starts the app. To go back to the tabs, swap which line is commented out.

**Note on Dart imports:** `demo_11a_bottomnav.dart` has to import the pages even though `main.dart` already does. In Dart, each file has its own scope, and imports don't carry over from file to file. That's like ES6 modules in JavaScript (each file imports what it needs), and unlike PHP's `include`/`require`, which pastes files into one big scope.

### STEP 11: The Current Tab and the List of Screens

**Where:** `demo_11a_bottomnav.dart`, inside `_Demo11aBottomNavState`, above `@override Widget build`.

```dart
int currentBottomTab = 0;

final List<Widget> bottomNavScreens = [
  PageHome(),
  PageSearch(),
  PageSettings(),
];
```

- `currentBottomTab` tracks which screen to show. It starts at 0, the first screen.
- `bottomNavScreens` is the list of pages we switch between.

The three import warnings are gone now.

---

### STEP 12: Show the Current Screen

**Where:** the `body:` line. **Change** it:

```dart
body: bottomNavScreens[currentBottomTab],   // was: body: Center(child: Text("Body goes here")),
```

**Test it:** you see the red Home page. `currentBottomTab` is 0, so the list gives you the first page.

### STEP 13: Add the Bar

**13a. Where:** under the `body:` line, still inside the Scaffold.

```dart
bottomNavigationBar: BottomNavigationBar(
  currentIndex: currentBottomTab,
  items: [
    BottomNavigationBarItem(icon: Icon(Icons.home), label: "Home"),
    BottomNavigationBarItem(icon: Icon(Icons.search), label: "Search"),
    BottomNavigationBarItem(icon: Icon(Icons.settings), label: "Settings"),
  ],
),
```

**Test it:** the bar shows up. Tap Search. **Nothing happens.** Unlike TabBar, a BottomNavigationBar doesn't switch anything by itself. We own the index, so we have to change it.

**13b. Where:** under the `items` list's closing `],`.

```dart
],   // already there (end of items)
onTap: (value) {
  setState(() {
    currentBottomTab = value;
  });
},
```

**Test it:** tapping switches pages, and the highlight moves.

- `currentIndex` tells the bar which item to highlight.
- `onTap` gets the index of the tapped item (0, 1, 2).
- `setState()` changes `currentBottomTab`, which rebuilds the screen with the new page.
- The number of `items` must match the number of screens in `bottomNavScreens`, and you need at least 2.

---

### STEP 14: Same Bug, Different Fix (IndexedStack)

Increment on Search, go to Home, and come back. **The counter is 0 again**, even though `page_search.dart` still has the mixin from Step 9.

The mixin only works inside a TabBarView. Here, we swap the whole widget out, so it's gone.

**Where:** the `body:` line. **Change** it:

```dart
body: IndexedStack(   // was: body: bottomNavScreens[currentBottomTab],
  index: currentBottomTab,
  children: bottomNavScreens,
),
```

**Test it:** hot restart. The count survives.

IndexedStack builds all of the pages and only shows one, so nothing gets thrown away.

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| State resets when switching tabs | AutomaticKeepAliveClientMixin for TabBar (Step 9), IndexedStack for BottomNavigationBar (Step 14) |
| "Controller's length property (3) does not match the number of tabs (4)" | Update DefaultTabController `length` to match the number of tabs |
| Red underlines on `PageHome` and the other pages | The imports in `main.dart` are still commented out (Step 7a) |
| "The method 'Demo11aBottomNav' isn't defined" | Add `import 'demo_11a_bottomnav.dart';` to `main.dart` (Step 10b) |
| Mixin added, but the count still resets in the tabs | Put `with AutomaticKeepAliveClientMixin` on the **State** class, return `true` from `wantKeepAlive`, then hot restart |
| Bottom nav icons are invisible with 4 items | Add `type: BottomNavigationBarType.fixed` (Step 16) |
| Shifting type shows no colors | Add `backgroundColor` to each BottomNavigationBarItem (Step 17) |
| Weird errors after adding a page | Hot restart instead of hot reload |
| The project won't run at all | Open the folder that contains `pubspec.yaml`, not the folder above it |

---

## Key Takeaways

1. **TabBar uses DefaultTabController** - it handles the current tab for you
2. **BottomNavigationBar needs you to track the index** - `currentIndex`, `onTap`, and `setState()`
3. **Same bug, two fixes** - AutomaticKeepAliveClientMixin for TabBar, IndexedStack for BottomNavigationBar
4. **4+ items need a type** - use `BottomNavigationBarType.fixed`, or `shifting` with colors
5. **Pages in separate files** - the same pages work in both navigation patterns

**For Project 3:** you need one navigation method. TabBar and BottomNavigationBar both count, and so do named routes.
