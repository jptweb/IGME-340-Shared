# Week 11A - TabBar and BottomNavigationBar

## Overview
Today we covered two advanced navigation patterns in Flutter:
- **TabBar Navigation** - tabs at the top of your app
- **BottomNavigationBar** - navigation at the bottom of your app

> **📖 Quick Reference:** See [TabBar & TabBarView Reference](../reference/navigation/tabbar-tabbarview.md) and [BottomNavigationBar Reference](../reference/navigation/bottomnavigationbar.md) for code examples and properties.

---

## PART 1: TABBAR NAVIGATION

### STEP 1: Setup TabBar with DefaultTabController
Wrap the entire Scaffold in a DefaultTabController widget:

```dart
return DefaultTabController(
  length: 3,  // Number of tabs
  child: Scaffold(
    // existing scaffold code
  ),
);
```

**Important:** The `length` must match the number of tabs you create.

---

### STEP 2: Add TabBar to AppBar
Add a `bottom` property to AppBar with TabBar widget:

```dart
appBar: AppBar(
  title: Text("My App"),
  bottom: TabBar(
    tabs: [
      Tab(icon: Icon(Icons.home), text: "Home"),
      Tab(icon: Icon(Icons.search), text: "Search"),
      Tab(icon: Icon(Icons.settings), text: "Settings"),
    ],
  ),
),
```

**Note:** TabBar goes in the `bottom` property of AppBar, not as a child.

---

### STEP 3: Style the TabBar (Optional)
Add backgroundColor to AppBar to style tabs:

```dart
appBar: AppBar(
  title: Text("My App"),
  backgroundColor: Colors.amber[700],  // Custom color
  bottom: TabBar(
    // tabs...
  ),
),
```

Create separate page files: `page_home.dart`, `page_search.dart`, `page_settings.dart`

### STEP 8: Add Interactivity to Search Page
Create a counter with increment button in PageSearch:

**Code for page_search.dart:**
```dart
import 'package:flutter/material.dart';

class PageSearch extends StatefulWidget {
  const PageSearch({super.key});

  @override
  State<PageSearch> createState() => _PageSearchState();
}

class _PageSearchState extends State<PageSearch> {
  int counter = 0;

  @override
  Widget build(BuildContext context) {
    return Container(
      width: double.infinity,
      height: double.infinity,
      color: Colors.orange[50],
      child: Column(
        mainAxisAlignment: MainAxisAlignment.center,
        children: [
          Text("Search Page - Counter: $counter"),
          ElevatedButton(
            onPressed: () {
              setState(() {
                counter++;
              });
            },
            child: Text("Increment"),
          ),
        ],
      ),
    );
  }
}
```

**Test it:** Click increment, switch tabs, come back - counter resets! We'll fix this next.

---

### STEP 9: Preserve State with AutomaticKeepAliveClientMixin
Add mixin to maintain state across tab switches:

```dart
class _PageSearchState extends State<PageSearch> with AutomaticKeepAliveClientMixin {
  int counter = 0;

  @override
  bool get wantKeepAlive => true;

  @override
  Widget build(BuildContext context) {
    super.build(context);  // Required by @mustCallSuper annotation

    return Container(
      width: double.infinity,
      height: double.infinity,
      color: Colors.orange[50],
      child: Column(
        mainAxisAlignment: MainAxisAlignment.center,
        children: [
          Text("Search Page - Counter: $counter"),
          ElevatedButton(
            onPressed: () {
              setState(() {
                counter++;
              });
            },
            child: Text("Increment"),
          ),
        ],
      ),
    );
  }
}
```

**Important:** Must override `wantKeepAlive` to return `true` and call `super.build(context)` at the start of build method.

**Result:** Counter now persists when switching between tabs.

**Note on `super.build(context)`:** In older Flutter versions, this was the *only* place the keep-alive handle was registered, so forgetting it would silently break state preservation. In modern Flutter (3.24+), the mixin also registers keep-alive in `initState()`, so the call is no longer strictly required at runtime. You should still include it because the method is marked `@mustCallSuper` and the official docs say to call it.

## PART 2: BOTTOM NAVIGATION BAR

### STEP 10: Start Fresh with BottomNavigationBar
Create a new demo file to explore a different navigation pattern.

**Why start fresh?**
- TabBar and BottomNavigationBar are different navigation patterns
- Easier to see each pattern clearly
- Both can reuse the same page files

**Create new file: demo_11a_bottomnav.dart**

```dart
import 'package:flutter/material.dart';

import 'page_home.dart';
import 'page_search.dart';
import 'page_settings.dart';

class Demo11aBottomNav extends StatefulWidget {
  const Demo11aBottomNav({super.key});

  @override
  State<Demo11aBottomNav> createState() => _Demo11aBottomNavState();
}

class _Demo11aBottomNavState extends State<Demo11aBottomNav> {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: Text("Bottom Nav Demo"),
      ),
      body: Center(
        child: Text("Body goes here"),
      ),
    );
  }
}
```

**Update main.dart:**
```dart
void main() {
  runApp(const MainApp());
}

class MainApp extends StatelessWidget {
  const MainApp({super.key});

  @override
  Widget build(BuildContext context) {
    //return const MaterialApp(home: Demo11a());  // Comment out TabBar version
    return MaterialApp(home: Demo11aBottomNav());  // Swap to BottomNav demo
  }
}
```

**Tip:** By commenting out the old `home:` line and swapping in the new one, you can easily toggle between the TabBar and BottomNavigationBar demos. `MaterialApp(home:)` is just a widget entry point  - you can swap the entire navigation pattern by changing one line.

**Note:** We're using StatefulWidget because BottomNavigationBar requires manual state management.

**Note on Dart imports:** Notice that `demo_11a_bottomnav.dart` must import `page_home.dart`, `page_search.dart`, etc. even though `main.dart` already imports them. In Dart, each file has its own scope  - imports don't cascade from file to file. This is similar to ES6 modules in JavaScript (each file explicitly imports what it needs) and different from something like PHP's `include`/`require`, which essentially concatenates files into one big scope.

---

### STEP 11: Add State Variables for Navigation

Add these two variables at the top of your `_Demo11aBottomNavState` class, before the build method:

```dart
int currentBottomTab = 0;

final List<Widget> bottomNavScreens = [
  PageHome(),
  PageSearch(),
  PageSettings(),
];
```

**What these do:**
- `currentBottomTab` tracks which screen to display. It starts at 0 (the first screen).
- `bottomNavScreens` is a list of all our page widgets that we'll switch between.

Your class should now look like:
```dart
class _Demo11aBottomNavState extends State<Demo11aBottomNav> {
  int currentBottomTab = 0;
  
  final List<Widget> bottomNavScreens = [
    PageHome(),
    PageSearch(),
    PageSettings(),
  ];

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: Text("Bottom Nav Demo"),
      ),
      body: Center(
        child: Text("Body goes here"),
      ),
    );
  }
}
```

---

### STEP 12: Display Current Screen in Body

Replace the placeholder text with the current screen from our list:

```dart
// Change from:
body: Center(
  child: Text("Body goes here"),
),

// To:
body: bottomNavScreens[currentBottomTab],
```

This uses the `currentBottomTab` index to pick which widget from `bottomNavScreens` to display. Since `currentBottomTab` starts at 0, you'll see PageHome by default.

---

### STEP 13: Add BottomNavigationBar to Scaffold

Add the bottomNavigationBar property after the body (still inside Scaffold):

```dart
bottomNavigationBar: BottomNavigationBar(
  currentIndex: currentBottomTab,
  items: [
    BottomNavigationBarItem(
      icon: Icon(Icons.home),
      label: "Home",
    ),
    BottomNavigationBarItem(
      icon: Icon(Icons.search),
      label: "Search",
    ),
    BottomNavigationBarItem(
      icon: Icon(Icons.settings),
      label: "Settings",
    ),
  ],
  onTap: (value) {
    setState(() {
      currentBottomTab = value;
    });
  },
),
```

**Key points:**
- `currentIndex: currentBottomTab` highlights which tab is currently active
- `onTap: (value)` receives the index of the tapped tab (0, 1, 2, etc.)
- `setState()` updates `currentBottomTab` which triggers a rebuild, showing the new screen
- The number of `items` must match the number of screens in `bottomNavScreens`

**Note:** You need at least 2 items or Flutter will throw an error (makes sense - you can't have navigation with only one option!).

**Result:** You'll now see a navigation bar at the bottom of your app with working tab switching!

### STEP 15: Fix BottomNavigationBar Type for 4+ Items

**Add type property as FIRST property in BottomNavigationBar:**
```dart
bottomNavigationBar: BottomNavigationBar(
  type: BottomNavigationBarType.fixed,  // Add this line
  currentIndex: currentBottomTab,
  items: [
    // all items...
  ],
  onTap: (value) {
    setState(() {
      currentBottomTab = value;
    });
  },
),
```

**Important:** Without `type: fixed`, 4+ items will cause visual issues.

### STEP 17: Preserve State with IndexedStack

**Why we need this:** Click Search tab, increment counter, switch tabs, come back - counter resets!

**Replace body:**
```dart
// Change from:
body: bottomNavScreens[currentBottomTab],

// To:
body: IndexedStack(
  index: currentBottomTab,
  children: bottomNavScreens,
),
```

**Result:** Counter on PageSearch now persists when switching tabs!

**Important:** AutomaticKeepAliveClientMixin (which worked for TabBar) does NOT work with BottomNavigationBar - use IndexedStack instead.

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| State resets when switching tabs | Use AutomaticKeepAliveClientMixin for TabBar or IndexedStack for BottomNavigationBar |
| "Expected to find 3 tabs but found 4" | Update DefaultTabController length to match number of tabs |
| BottomNavigationBar breaks with 4+ items | Add `type: BottomNavigationBarType.fixed` |
| Forgot super.build(context) with mixin | Still include it (`@mustCallSuper`), but in modern Flutter (3.24+) keep-alive is also registered in `initState()` so it won't silently break |
| Type errors after adding pages | Restart app instead of hot reload |
| Shifting type shows no colors | Add backgroundColor to each BottomNavigationBarItem |

---

## Key Takeaways

1. **TabBar uses DefaultTabController** - Handles state automatically
2. **BottomNavigationBar requires manual state** - You track currentIndex with setState()
3. **State preservation differs** - AutomaticKeepAliveClientMixin for TabBar, IndexedStack for BottomNavigationBar
4. **4+ items need type specified** - Use `BottomNavigationBarType.fixed`
5. **Organize pages in separate files** - Can reuse across different navigation patterns

**Important for Projects:** Use TabBar or BottomNavigationBar in your projects to demonstrate understanding of advanced navigation patterns. Don't rely only on buttons and dialogs!
