### Part 1: Adding Clear Buttons to TextFields

Building on our Week 6A TextField knowledge, we added clear buttons (the "X" icon) to let users quickly erase field content:

```dart
TextField(
  controller: nameController,
  decoration: InputDecoration(
    labelText: 'Name',
    suffixIcon: IconButton(
      onPressed: () {
        nameController.clear();  // Wipes the field
      },
      icon: Icon(Icons.clear),
    ),
  ),
)
```

**Critical:** You MUST use a `TextEditingController` for this to work.

#### The Problem This Created

Adding the clear button broke our keyboard navigation! When you pressed "next" on the keyboard, it jumped to the clear button instead of the next TextField.

**Why?** The IconButton became part of the focus order - it's now a focusable widget in the tab sequence.

### Part 2: Focus Nodes - Taking Control of Navigation

> **Quick Reference:** See the [Focus Management Reference](../reference/input-forms/focus-management.md) for complete focus control patterns and keyboard dismissal techniques.

To fix the broken navigation, we learned about **Focus Nodes** - objects that let you programmatically control which field has focus.

#### Step 1: Create Focus Nodes

```dart
class _MainPageState extends State<MainPage> {
  // Define them at the top
  late FocusNode nameFocusNode;
  // Repeat for additional form fields here!

  @override
  void initState() {
    super.initState();
    // Initialize them
    nameFocusNode = FocusNode();
    // Repeat for additional form fields!
  }

  @override
  void dispose() {
    // CRITICAL: Clean up to prevent memory leaks
    nameFocusNode.dispose();
    // Repeat for additional form fields!

    // Also dispose controllers
    nameController.dispose();
    // Repeat for additional form fields!
    super.dispose();
  }
}
```

**Critical:** Always use `late` keyword and initialize in `initState()`, then dispose in `dispose()`.

#### Step 2: Assign Focus Nodes and Control Navigation

```dart
TextField(
  controller: nameController,
  focusNode: nameFocusNode,  // Assign the node
  decoration: InputDecoration(
    labelText: 'Name',
    suffixIcon: IconButton(
      onPressed: () => nameController.clear(),
      icon: Icon(Icons.clear),
    ),
  ),
  textInputAction: TextInputAction.next,
  onEditingComplete: () {
    emailFocusNode.requestFocus();  // Jump to email field
  },
)
```

**What Changed:**
- `focusNode` property assigns the Focus Node
- `onEditingComplete` fires when user presses "next" on keyboard
- `requestFocus()` manually moves focus to the next field

**For the Last Field:**

```dart
TextField(
  controller: pwdController,
  focusNode: pwdFocusNode,
  decoration: InputDecoration(labelText: 'Password'),
  textInputAction: TextInputAction.done,
  onEditingComplete: () {
    pwdFocusNode.unfocus();  // Dismiss keyboard
  },
)
```

### Part 3: Dismissing the Keyboard

We learned THREE ways to dismiss the keyboard:

#### Method 1: Focus Manager (On Button Press)

```dart
ElevatedButton(
  onPressed: () {
    FocusManager.instance.primaryFocus?.unfocus();
    // Process form submission...
  },
  child: Text('Submit'),
)
```

**When to use:** On submit buttons or any action that should hide the keyboard.

#### Method 2: onTapOutside (Per-Field Basis)

```dart
TextField(
  controller: nameController,
  focusNode: nameFocusNode,
  decoration: InputDecoration(labelText: 'Name'),
  onTapOutside: (event) {
    nameFocusNode.unfocus();
  },
)
```

**When to use:** If you want each field to handle its own tap-outside behavior.
**Downside:** Must add to every field.

#### Method 3: GestureDetector (App-Wide Solution)

```dart
@override
Widget build(BuildContext context) {
  return GestureDetector(
    onTap: () {
      FocusManager.instance.primaryFocus?.unfocus();
    },
    child: Scaffold(
      appBar: AppBar(/* ... */),
      body: /* ... */,
    ),
  );
}
```

**When to use:** Best practice for forms - handles tap-anywhere-to-dismiss.
**Result:** Tapping anywhere outside the keyboard dismisses it (standard mobile UX).

### Part 4: Preventing Keyboard from Covering Fields

When the keyboard appears, it can cover bottom fields. We fixed this with `SingleChildScrollView`:

```dart
body: SingleChildScrollView(  // Wrap your entire body
  child: Container(
    child: Column(
      children: [
        // All your layout widgets...
      ],
    ),
  ),
)
```
> Note: this gets a little wonky and sometimes seems to crash my emulator. Adding the singleScrollListener seems to work but occasionally the
> app will "pause" for debugging, and appear to lock up. Be sure to look at the debug logs while doing this, and make sure the app isn't set to pause
> in the Debugging options (the pause / play button you see at top of VS code when running an app when debugging).

**What it does:** When keyboard appears, the screen automatically scrolls to show the active field.

### Part 5: Icon Placement Options (Quick Demo)

We clarified the difference between icon properties in `InputDecoration`:

| Property | Location | When Visible |
|----------|----------|--------------|
| `icon` | Outside field border (left side) | Always |
| `prefixIcon` | Inside field border (left side) | Always |
| `prefix` | Inside field border (left side) | Only when field is focused |

```dart
// Icon OUTSIDE the border
TextField(
  decoration: InputDecoration(
    labelText: 'Name',
    icon: Icon(Icons.person),  // Outside on left
    border: OutlineInputBorder(),
  ),
)

// prefixIcon INSIDE the border
TextField(
  decoration: InputDecoration(
    labelText: 'Email',
    prefixIcon: Icon(Icons.email),  // Inside on left
    border: OutlineInputBorder(),
  ),
)
```

### Part 6: The Bridge — Connecting a TextField to an API

This is the piece that ties everything together for GIF Finder and Project 2. We took the value from a TextField, plugged it into an API URL, and made an async request.

```dart
import 'dart:convert';
import 'package:http/http.dart' as http;
```

```dart
Future<void> doSearch(String query) async {
  final url = 'https://dummyjson.com/products/search?q=$query';
  print('Searching for: $url');

  final response = await http.get(Uri.parse(url));

  if (response.statusCode == 200) {
    final data = jsonDecode(response.body);
    print('Found ${data['total']} results!');

    for (var product in data['products']) {
      print(' - ${product['title']}');
    }
  } else {
    print('Error: ${response.statusCode}');
  }
}
```

Then in the Submit button:

```dart
ElevatedButton(
  onPressed: () {
    FocusManager.instance.primaryFocus?.unfocus();
    doSearch(nameController.text);  // Use the field value!
  },
  child: Text("Submit"),
),
```

**The full pattern for GIF Finder / Project 2:**
1. User types a search term in a TextField
2. You grab `controller.text` and string-interpolate it into your API URL
3. Make an async HTTP request (just like Week 7A)
4. Parse the JSON into a data class (just like we did with Carts)
5. Store results in state with `setState`
6. Display in a `GridView.builder` (just like Week 7B)

We did steps 1-3 in class. Steps 4-6 use skills you already have — now it's your turn to connect the dots!

## Key Concepts & Terminology

| Term | Definition |
|------|------------|
| **FocusNode** | Object that represents keyboard focus for a specific widget |
| **FocusManager** | Global controller for managing focus across the app |
| **onEditingComplete** | Callback fired when user presses action button on keyboard |
| **onTapOutside** | Callback fired when user taps outside a TextField |
| **requestFocus()** | Method to programmatically move focus to a field |
| **unfocus()** | Method to remove focus and dismiss keyboard |
| **SingleChildScrollView** | Widget that makes content scrollable (prevents keyboard overlap) |
| **String interpolation** | Using `$variable` or `${expression}` inside a string to build URLs |

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| "Next" goes to clear button instead of next field | Add FocusNode with `onEditingComplete` |
| Keyboard covers bottom fields | Wrap body in `SingleChildScrollView` |
| Focus Nodes cause crashes | Always initialize in `initState()` and dispose in `dispose()` |
| Can't dismiss keyboard with tap | Wrap Scaffold in GestureDetector with FocusManager.unfocus() |
| API call not firing | Make sure you're calling the function, not just defining it |
| Empty search results | Check the URL in debug console — is the query actually in there? |

## Key Takeaways

1. **Focus Nodes = Control** - Take charge of navigation flow in forms
2. **Always Dispose** - Focus Nodes and Controllers must be cleaned up
3. **Three Dismissal Methods** - Choose based on your needs (button, per-field, or app-wide)
4. **SingleChildScrollView** - Prevents keyboard from covering fields
5. **TextField → URL → API** - The pattern you'll use in every app that searches for data
