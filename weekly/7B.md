### Quick Recovery: Loading Data on Startup (initState)

In 7A we fetched data via button press. But what if we want data to load automatically when the app opens?

**The Problem:** You can't make `initState()` async directly — Flutter won't allow it.

```dart
// THIS WON'T WORK
@override
void initState() async {   // ERROR!
  super.initState();
  await doTheThing();
}
```

**The Solution:** Call an async function from `initState()`:

```dart
@override
void initState() {
  super.initState();
  doStartupStuff();
}

Future<void> doStartupStuff() async {
  await doTheThing();
}
```

`initState()` runs before the widget builds — it's where you do setup work. Since it can't be async, you create a helper function that IS async and call it from there. Data loads as soon as the app opens, no button click needed.

We'll use this pattern again below with the Giphy categories.

### HTTP Package for API Calls

We integrated the `http` package to make external API requests. Unlike web development where fetch is built-in, Flutter requires adding this package explicitly.

> In previous classes we ran `flutter pub add` but let's also go through the manual process — importing the package first and then running `flutter pub get`.

**Setup Process:**
1. Add to `pubspec.yaml` dependencies:
   ```yaml
   http: ^1.1.0  # or latest version
   ```
2. Run `flutter pub get`
3. Import in your Dart file:
   ```dart
   import 'package:http/http.dart' as http;
   import 'dart:convert';
   ```

**Key Point:** The `as http` part creates a namespace to avoid naming conflicts with other packages.

### Making Your First API Request

(OK maybe your second, since we used DummyJSON last class.) We built a function to fetch Giphy categories. The pattern is: make request -> check status -> decode JSON. Same pattern as 7A, different API.

**Basic Structure of getCategories — an async function to fetch data:**
```dart
Future<void> getCategories() async {
  var response = await http.get(Uri.parse(catUrl));

  if (response.statusCode == 200) {
    var jsonResponse = jsonDecode(response.body);
    print(jsonResponse);
  } else {
    print("Error ${response.statusCode}");
  }
}
```

**Important Concepts:**
- `Future<void>` - returns a Future with no value
- `async` keyword enables use of `await`
- `Uri.parse()` converts String to Uri (required by http.get)
- Status code 200 = success, 404 = not found, 500 = server error
- `jsonDecode()` transforms JSON string into Dart Map/List

### Need a little more code?

Here is the basic structure using the same `getCategories()` function but connecting it to our interface with an ElevatedButton, and using `initState()` to load categories automatically on startup:

```dart
class _MainPageState extends State<MainPage> {

  String catUrl = "https://api.giphy.com/v1/gifs/categories?api_key=YOUR_API_KEY";

  Future<void> getCategories() async {
    var response = await http.get(Uri.parse(catUrl));

    if (response.statusCode == 200) {
      var jsonResponse = jsonDecode(response.body);
      print(jsonResponse);
    } else {
      print("Error ${response.statusCode}");
    }
  }

  @override
  void initState() {
    super.initState();
    doStartupStuff();
  }

  Future<void> doStartupStuff() async {
    await getCategories();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text("Giphy")),
      body: Column(
        children: [
          Center(
            child: Text('Hello World!'),
          ),
          ElevatedButton(
            onPressed: () async {
              await getCategories();
            },
            child: Text("Get Categories"),
          ),
        ],
      ),
    );
  }
}
```

Notice that with `initState()`, the categories print to the debug console as soon as the app launches — you don't need to click the button. The button still works too if you want to refresh manually.

### macOS Network Permission Issue — Bonus Content

> I may create today's demo as a macOS desktop app since this is multiplatform development after all. You aren't required to do this, and you can skip this part if you'd like.

When testing on macOS desktop, you'll encounter a network permission error. This is due to macOS App Sandbox security.

**The Error:**
```
ClientException with SocketException: Connection failed
(OS Error: Operation not permitted, errno = 1)
```

**The Fix (Mac users only):**

Add network client permissions to two files:

**File 1:** `macos/Runner/DebugProfile.entitlements`
```xml
<key>com.apple.security.network.client</key>
<true/>
```

**File 2:** `macos/Runner/Release.entitlements`
```xml
<key>com.apple.security.network.client</key>
<true/>
```

Place these lines just before `</dict>` in each file. After adding, do a **hot restart** (not just hot reload).

**Why This Matters:** Platform-specific issues are common in multiplatform development. Android/Windows don't need this — only macOS desktop builds.

### Debugging JSON Responses

We used the debugger to understand the Giphy API response structure before writing code to parse it. This is a crucial skill — especially for Project 2 where you'll be working with an API of your choice.

**Process:**
1. Set breakpoint after `jsonDecode()` line
2. Run app in debug mode
3. Click button (or let initState fire) to trigger API call
4. When paused, examine variables in debug console

**Navigating JSON in Debug Console:**
```dart
// Type these in debug console to explore:
jsonResponse                        // Shows top-level keys
jsonResponse['data']                // Shows array of categories
jsonResponse['data'][2]             // Third category object
jsonResponse['data'][2]['name']     // "anime"
jsonResponse['data'][2]['subcategories']    // Nested subcategories
jsonResponse['data'][2]['subcategories'][1]['name']  // A subcategory name
```

**Key Insight:** Giphy wraps everything in a `data` key. DummyJSON used `carts`. Every API structures differently — always investigate first!

### Understanding Nested JSON

The Giphy categories response has multiple levels:
- Top level: `data`, `meta`, `pagination`
- Inside `data`: Array of 28+ category objects
- Each category: `name`, `name_encoded`, `subcategories`
- Each subcategory: Another array of objects with their own names

**Why This Matters:** Before you can display data, you need to know the path to access it. Spend time exploring with the debugger before coding. For Project 2, whatever API you decide to use, I recommend doing this exploration first so you understand how to extract the data you need.

> **Reminder from 7A:** This is exactly why we built that `tempList` of cleaned-up cart Maps in 7A instead of handing the raw `jsonResponse` to the widget tree. When you have nested lists (like Giphy results, where each GIF has nested `images`, `user`, etc.), the same principle applies — preprocess into a data structure shaped for your UI so the widget tree stays dumb. See the ["Why bother building your own data structure?" section in 7A](7A.md) for the full breakdown with a Pokémon example.

### A Note on Dynamic Dropdowns

You might notice that these categories could be used to dynamically populate a dropdown — and you'd be right. You could store the category names in a state list and build DropdownMenuItems from them using `.map().toList()`.
```dart
GridView.count(
  crossAxisCount: 2,  // 2 columns
  crossAxisSpacing: 8.0,
  mainAxisSpacing: 8.0,
  children: [
    Container(color: Colors.pink.shade50, child: Center(child: Text('Item 1'))),
    Container(color: Colors.pink.shade100, child: Center(child: Text('Item 2'))),
    // ... more items
  ],
)
```

**Properties:**
- `crossAxisCount` — number of columns
- `crossAxisSpacing` — horizontal space between items
- `mainAxisSpacing` — vertical space between items

**Important:** GridView must be inside a bounded container like `Expanded`, otherwise you'll get RenderBox errors. An Expanded widget tells the GridView how much vertical space it has to work with.

**Limitation:** Must manually list all children — not ideal for API data.

### GridView.builder — Dynamic Content

For displaying API results, we need GridView.builder which creates items on demand — same concept as ListView.builder.

**Setup:**
```dart
GridView.builder(
  gridDelegate: SliverGridDelegateWithFixedCrossAxisCount(
    crossAxisCount: 3,
    crossAxisSpacing: 5.0,
    mainAxisSpacing: 10.0,
  ),
  itemCount: 10,
  itemBuilder: (context, index) {
    return Container(
      color: Colors.green,
      child: Center(child: Text('$index')),
    );
  },
)
```

**Critical Component: SliverGridDelegate**

Yes, it's a mouthful. Here's what it means:
- **Sliver** — Flutter's term for anything scrollable
- **GridDelegate** — Controls how grid lays out items
- **WithFixedCrossAxisCount** — Fixed number of columns (as opposed to fixed item width)

Think of it as: "A scrollable grid controller with fixed column count"

**Key Points:**
- Without `itemCount`, the grid scrolls infinitely — always set it to your data length
- The itemBuilder returns whatever widget you want for each cell
- You can adjust `crossAxisCount` to change columns (try 2 vs 3 vs 4)
- `physics: NeverScrollableScrollPhysics()` locks scrolling if you ever need that

### GridTile for Structured Items

GridTile provides header, body, and footer sections for grid items — useful for displaying content with labels.

```dart
itemBuilder: (context, index) {
  return GridTile(
    header: Text('Header $index'),
    footer: Text('Footer $index'),
    child: Container(
      color: Colors.amber.shade200,
      child: Center(child: Text('$index')),
    ),
  );
}
```

**Structure:**
- **header** — Floats at top of tile
- **child** — Main content area
- **footer** — Floats at bottom of tile

**Styling Tip:** Use `textAlign: TextAlign.center` to center text within each section.

**Think ahead to GIF Finder:** You could replace `Center(child: Text('$index'))` with a network image of a GIF. The header or footer could show the GIF's title. That's basically the structure you're building toward for the lab.

## Common Issues & Solutions

| Problem | Solution |
|---------|----------|
| "Operation not permitted" on Mac | Add network entitlements to both .entitlements files |
| Can't import http package | Run `flutter pub get` after adding to pubspec.yaml |
| "Uri can't be assigned from String" | Wrap URL in `Uri.parse()` |
| Response is just a string | Use `jsonDecode()` to convert JSON string to Map |
| GridView overflows screen | Wrap in `Expanded` widget |
| itemBuilder errors | Check that you're returning a widget |
| Items display but no data | Verify `itemCount` matches your data length |
| initState won't compile as async | Call an async helper function from initState — don't make initState async |
| UI doesn't update after API call | Wrap state changes in `setState()` |

### API Key Management

> **GIPHY API Setup:** See the complete [GIPHY API Setup Guide](../reference/network/giphy-api-setup.md) for detailed instructions on getting your API key, security best practices, and understanding available endpoints.

**Quick reminders:**

- **Never share API keys** — each student needs their own
- Choose "API" not "SDK" when creating app
- Select "Other" as platform (works for multiplatform Flutter)

### JSON Exploration Strategy

1. Make the API call first
2. Use debugger to examine response structure
3. Navigate the JSON in debug console
4. Plan your data extraction
5. Then write the parsing code

**Don't guess at JSON structure** — always investigate first! This applies to the GIF Finder lab AND Project 2.

### Widget Building Approach

For complex widgets like GridTiles:
1. Build and style a single item first
2. Get it looking perfect
3. Then integrate into GridView.builder
4. Extract to method if it gets too nested

**Why:** Debugging is much easier when you can see one item, not 50. If you build the entire GridView with API data all at once and something breaks, you won't know if it's a layout problem or a data problem.

### Commenting Your Code

This is a good time to remind everyone: **comment your code.** The widget tree gets deeply nested and messy — that's just the nature of Flutter. Comments help you (and anyone reading your code) understand what each section does without having to drill into every child widget.

Check the [commenting guide](../commenting_guide.md) for the expected format. You will lose points if your code isn't commented.

### Filtering Debug Output

The debug console gets noisy. Filter it:
- Type `I/flutter` in console filter box
- Shows only your `print()` statements
- Reduces clutter from Flutter framework messages
