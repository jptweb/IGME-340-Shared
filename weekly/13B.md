### STEP 4: Replace Android Icons

**Action:** Replace the default Android icons with your custom ones

**Location in your project:**
```
your_project/
└── android/
    └── app/
        └── src/
            └── main/
                └── res/    ← We're working here!
                    ├── mipmap-hdpi/
                    ├── mipmap-mdpi/
                    ├── mipmap-xhdpi/
                    ├── mipmap-xxhdpi/
                    └── mipmap-xxxhdpi/
```

**Steps:**

1. **Open your project's android/app/src/main/res folder in Finder/Explorer**
   - In VS Code, right-click `android/app/src/main/res` → "Reveal in Finder/Explorer"

2. **Open the downloaded android folder** (from easyappicon.com)

3. **Drag and drop ALL mipmap folders** from the download into your project's `res/` folder
   - You should be replacing: mipmap-hdpi, mipmap-mdpi, mipmap-xhdpi, mipmap-xxhdpi, mipmap-xxxhdpi
   - When asked "Replace?" → Say YES to all

4. **Verify:** Open one of the mipmap folders - you should see your custom icon files

**Important Notes:**
- **Copy ALL mipmap folders** including `mipmap-anydpi-v26` if it was generated
- Make sure all 5 resolution folders (hdpi, mdpi, xhdpi, xxhdpi, xxxhdpi) are copied
- **DO NOT copy the `values/` folder** from the easyappicon download into your project's `res/` folder. It contains an `ic_launcher_background.xml` that will collide with the `colors.xml` you create in Step 5 and cause a duplicate resource build error. We only want the mipmap folders.

**⚠️ Heads up about easyappicon changes:**
easyappicon.com recently started including a `values/ic_launcher_background.xml` file in its download to support newer Android v26 adaptive icons. If you drag the whole `android/` folder over and choose "Replace" in Finder, it will add this extra XML file **without** overwriting the `colors.xml` you create in the next step (they have different filenames, so Finder keeps both). The result is two files declaring the same color resource, and your build will fail with a duplicate resource error. Safest move: only copy the `mipmap-*` folders, not the `values/` folder.

**Understanding the icon files:**
- `ic_launcher.png` - Standard square icon (fallback)
- `ic_launcher_round.png` - Round icon (Android 7-11)
- `ic_launcher_foreground.png` - Foreground layer for adaptive icons (Android 8+)
- `mipmap-anydpi-v26/ic_launcher.xml` - Adaptive icon configuration for modern Android

### STEP 5: Create colors.xml for Adaptive Icons

**Action:** Define the background color for adaptive icons (required for modern Android)

**The Reality of App Icons:**
This step highlights an important lesson: despite best efforts, getting your app icon to look beautiful on every OS is **a lot of work**. The approach we're using (easyappicon.com + manual setup) is one way, but there are others:
- **flutter_launcher_icons package** - More automated but requires command-line configuration
- **Professional design services** - For production apps at large companies, hours are spent perfecting every variation
- **Each platform has different requirements** - This is just how mobile development works!

**Why this step matters:**
The `mipmap-anydpi-v26` folder enables **adaptive icons** (Android 8+), which look noticeably better than the fallback icons. It's worth the extra effort!

**Create new file:** `android/app/src/main/res/values/colors.xml`

**File content:**
```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <color name="ic_launcher_background">#FFFFFF</color>
</resources>
```

**What this does:**
- Defines the background color for your adaptive icon (Android 8+)
- Adaptive icons = foreground image + background color/image
- Android automatically masks the icon to the launcher's preferred shape

**⚠️ Use the same color you picked in Step 3:**
Whatever background color you chose in easyappicon.com (white or RIT orange), use the **same hex value here** so the adaptive icon matches the rest of your icon files:
- Picked **white** in Step 3? → keep `#FFFFFF`
- Picked **RIT orange** in Step 3? → change to `#F76902`

**Other color options** (if you're using a custom design):
- `#000000` - Black
- `#42A5F5` - Blue
- `#4CAF50` - Green
- Pick whatever complements your foreground icon

**What happens without this step:**
If you skip copying `mipmap-anydpi-v26`, your icons will still work but won't look as polished on modern Android devices (8+). It's a trade-off between time invested and visual quality.

### STEP 6: Update AndroidManifest.xml for Round Icons

**Action:** Tell Android about the round icon option (mainly for Android 7.1-11)

**File:** `android/app/src/main/AndroidManifest.xml`

**Find this section (around line 7-10):**
```xml
<application
    android:label="icon_splash_demo"
    android:name="${applicationName}"
    android:icon="@mipmap/ic_launcher">
```

**Add the round icon reference:**
```xml
<application
    android:label="icon_splash_demo"
    android:name="${applicationName}"
    android:icon="@mipmap/ic_launcher"
    android:roundIcon="@mipmap/ic_launcher_round">
```

**What this does:**
- `android:icon` - Points to the standard icon (used on most devices)
- `android:roundIcon` - Points to the round icon (used on some launchers, particularly Android 7.1-11)
- Android automatically picks which one to use based on the device's launcher

**Note:** On modern Android (8+), many launchers use adaptive icons instead. The round icon mainly appears on specific launchers and older Android versions. Don't worry if you don't see a perfectly circular icon - the standard icon works great!

**Bonus - Change App Name:**
While you're here, you can change the app name that appears under the icon:

## PART 2: Splash Screens

### Understanding Splash Screens

**What is a splash screen?**
The screen shown briefly when your app launches, before the main UI loads.

**Why Splash Screens Matter:**

**They're Not Flutter Screens:**
- Splash screens are **native iOS and Android screens**
- Built outside of the Flutter environment
- When a Flutter app launches, it takes a moment for the Flutter framework to load
- **During this loading time, Flutter screens cannot be shown yet**
- Native splash screens can display immediately, without delay
- This is why we can't just use a Flutter widget as the first screen

**Apple Requires Them:**
- iOS apps **must** have a launch screen (Apple requirement)
- Android doesn't strictly require them, but users expect them
- Professional apps always have splash screens

**User Experience:**
- Without a splash screen, users see a **blank white screen** while Flutter loads
- With a splash screen, users see your branding immediately
- Creates a polished, professional first impression

**Platform Differences (Important!):**

| Platform | Background Image? | Image in Center? | Branding Image? |
|----------|-------------------|------------------|-----------------|
| **Android 11 and below** | ✅ Yes | ✅ Yes | ✅ Yes |
| **Android 12+** | ❌ No (color only) | ✅ Yes | ✅ Yes |
| **iOS** | ✅ Yes | ✅ Yes | ✅ Yes |

**Why the Android 12+ change?**
Google changed splash screen requirements to create a more consistent user experience. Background images are no longer allowed, only solid colors.

**What we'll create:**
- Background image (for iOS and Android 11-)
- Solid color background (for Android 12+)
- Center logo/image
- Branding image at bottom

### STEP 15: Understanding Image Masking (Android 12+)

**Important concept:** The center image on Android 12+ gets masked to a circle.

**What this means:**
- Your 960x960 image is displayed
- Android draws a circular mask over it
- Only the center 640x640 circular area is visible
- Corners get cut off!

**Example:**
- **Square icon:** Corners will be cut off
- **Circle icon:** Fits perfectly
- **Text/logo:** Keep it in the center 640x640 area

**Why our RIT tiger works well:**
The `rit_tiger.png` you downloaded is pre-sized so the tiger sits inside the 640x640 safe zone. That's why circular masking on Android 12+ doesn't cut anything important off — the tiger head fits cleanly inside the circle.

**Designing your own splash logo (for Project 3):**
- Keep the meaningful content in the center 640x640 area
- Anything in the corners of a 960x960 image will be masked off on Android 12+
- When in doubt, design inside a circle, not a square

### STEP 16: Optional - Control Splash Screen Duration

**Action:** Keep splash screen on screen longer (optional)

**By default:** Splash screen disappears as soon as Flutter is ready.

**To keep it longer:**

**1. Import the package in your main.dart:**
```dart
import 'package:flutter_native_splash/flutter_native_splash.dart';
```

**2. Preserve the splash screen at app startup:**
```dart
void main() {
  WidgetsBinding widgetsBinding = WidgetsFlutterBinding.ensureInitialized();
  FlutterNativeSplash.preserve(widgetsBinding: widgetsBinding);

  runApp(const MyApp());
}
```

**3. Remove it when ready (e.g., after loading data):**
```dart
// In your app, after initialization is done:
FlutterNativeSplash.remove();
```

**Example - Show splash for 3 seconds:**
```dart
void main() {
  WidgetsBinding widgetsBinding = WidgetsFlutterBinding.ensureInitialized();
  FlutterNativeSplash.preserve(widgetsBinding: widgetsBinding);

  // Remove after 3 seconds
  Future.delayed(const Duration(seconds: 3), () {
    FlutterNativeSplash.remove();
  });

  runApp(const MyApp());
}
```

**⚠️ CRITICAL:** You MUST call `FlutterNativeSplash.remove()` at some point, or the splash screen will stay forever and block your app!

**When to use this:**
- Loading data from API
- Initializing databases
- Preloading assets
- **Don't** use it just to show off your splash screen longer - users hate delays!

## Key Concepts

### App Icon Requirements

| Platform | Format | Sizes Needed | Notes |
|----------|--------|--------------|-------|
| **Android** | PNG | 5 mipmap folders | Round icons for Android 12+ |
| **iOS** | PNG | 10+ sizes | Rounded square shape |
| **Web** | PNG/ICO | 192x192, 512x512 | Separate process |

### Splash Screen Platform Differences

| Feature | Android 11- | Android 12+ | iOS |
|---------|-------------|-------------|-----|
| **Background Image** | ✅ Supported | ❌ Color only | ✅ Supported |
| **Center Image** | ✅ Any shape | ✅ Circular mask | ✅ Any shape |
| **Branding Image** | ✅ Supported | ✅ Supported | ✅ Supported |

### Important Files

**Android:**
- `android/app/src/main/AndroidManifest.xml` - Icon config, app name
- `android/app/src/main/res/mipmap-*/` - Icon files (all resolutions)
- `android/app/src/main/res/mipmap-anydpi-v26/` - Adaptive icon XML config
- `android/app/src/main/res/values/colors.xml` - Icon background color
- `android/app/src/main/res/drawable/` - Splash screen assets (generated)

**iOS:**
- `ios/Runner/Assets.xcassets/AppIcon.appiconset/` - Icon files
- `ios/Runner/Base.lproj/LaunchScreen.storyboard` - Splash screen (generated)

## Troubleshooting

| Problem | Solution |
|---------|----------|
| **Icons not changing** | Did you rebuild the app? (`flutter run` again) |
| **Build error: ic_launcher_background not found** | You copied mipmap-anydpi-v26 but forgot to create colors.xml (Step 5) |
| **Android emulator stuck installing** | Use Chrome instead! Press F5, select Chrome from device list. Android emulators can be slow. |
| **Round icon not showing as circular** | Modern Android (8+) uses adaptive icons, not round icons. Your icon is working correctly! The shape depends on the launcher. |
| **Splash screen not showing** | Close app completely, launch fresh from home screen |
| **Android 12+ shows wrong background** | Check `android_12:` section in YAML has `color`, not `background_image` |
| **Image looks wrong on Android 12+** | Remember circular masking! Keep content in center 640x640 circle |
| **"You're ready to go!" not showing** | Check YAML syntax, verify image paths are correct |
| **Splash screen stays forever** | Did you call `FlutterNativeSplash.remove()`? Must call it! |
| **Icon blurry on some devices** | Use higher resolution source image (1024x1024 minimum) |
| **Bottom branding not showing** | Check `branding` path in YAML, verify image exists |
