## II. The Pattern You'll Use All Semester

Nearly every project this semester starts the same way: a `MainApp` holding the `MaterialApp`, pointing at a stateful page widget.

### Step 1: Scaffold a StatefulWidget

At the bottom of `main.dart`, type:

```
stfu
```

and press Enter. A full `StatefulWidget` and `State` pair scaffolds out. Name it `HomePage`.

Two classes, because a stateful widget is a two-piece thing. The widget itself is immutable. The `State` object next to it is what actually changes and survives rebuilds.

### Step 2: The Placeholder

The generated `build` returns a `Placeholder`, which draws a big X.

`Placeholder` is a real widget. It exists so your app compiles before you've decided what goes there. You'll use it more than you expect.

### Step 3: Replace it with something real

```dart
return Scaffold(
  body: Center(
    child: Text('Week 2B'),
  ),
);
```

### Step 4: Point MainApp at it

```dart
home: const HomePage(),
```

Run it. That's the pattern: `MainApp` holds the `MaterialApp`, and `home` points at your stateful page.

## III. Shortcuts

### `Cmd + .` / `Ctrl + .` - the important one

Put your cursor **on the widget name** and press it.

- **Wrap with widget** - wrap a `Text` in a `Column`
- **Wrap with Column / Row / Padding** - the common ones have dedicated entries
- **Remove this widget** - pull a `Center` out and watch its child jump to the corner

You will use this more than any other shortcut in this class. It's the difference between fighting the brackets and moving fast.

> ⚠️ **The menu only appears when your cursor is on the widget *name*.** If you're inside the parentheses you get nothing, or the wrong menu. This is the number one reason it "doesn't work."

### Adding a second child

```dart
children: const [
  Text('Week 2B'),
  Text('Second line'),
],
```

`children` takes a `List<Widget>`. Same list syntax from the Dart exercises, holding widgets.

### `Ctrl + Space` - see what a widget can do

Put your cursor inside `Scaffold(` and press it. You get every property the widget accepts: `appBar`, `backgroundColor`, `bottomNavigationBar`, `drawer`, and the rest.

**You don't memorise widget APIs. You ask the editor.** This is the shortcut that makes you self-sufficient.

### Adding an AppBar

`appBar` was in that completion list, so let's use it. It's the bar across the top of the screen with your title in it, and almost every app you build this semester will have one.

```dart
return Scaffold(
  appBar: AppBar(
    title: const Text('Week 2B'),
    backgroundColor: Colors.deepPurple,
    foregroundColor: Colors.white,
  ),
  body: Center(
    child: Column(
      children: const [
        Text('Week 2B'),
        Text('Second line'),
      ],
    ),
  ),
);
```

Save and hot reload. The bar appears at the top without restarting the app.

Two things to notice:

`title:` takes a **widget**, not a string. `title: 'Week 2B'` will not compile. You need `Text('Week 2B')`. This trips up almost everyone once, and it is worth getting wrong on purpose right now so you recognise the error later. Almost everything in Flutter takes a widget, which is the whole idea behind the widget tree.

`backgroundColor:` sets the bar, `foregroundColor:` sets the title and icon color on top of it. Set only the background and you get dark text on a dark bar, which looks broken.

`centerTitle: true` centers the title if you prefer that look.

Right now you are setting these colors by hand, on one widget, on one screen. That gets old fast once you have five screens. Week 3B is where we set colors once in the app theme and let every widget pick them up.

### Formatting and trailing commas

Format the document with `Alt + Shift + F` (Windows) or `Option + Shift + F` (Mac).

Trailing commas are how you tell the formatter to put each item on its own line. In Flutter you almost always want that, because the nesting gets deep fast.

**Before that works, you need a one-time setting.** Dart 3.8 changed the formatter so it picks the line breaks for you. On a short widget it will collapse everything onto one line no matter where you put your commas.

Open `analysis_options.yaml` in the root of your project, the same folder as `pubspec.yaml`, and add these two lines at the root level of the file (not indented under `linter:` or anything else):

```yaml
formatter:
  trailing_commas: preserve
```

Save it, then format again. Now a trailing comma means "keep each item on its own line," which is the behavior you want all semester.

Do this in every new project you create, including the ones you hand in. It takes about five seconds.

Once the setting is in place, try it: delete the trailing comma after the last item in a list, reformat, and watch it collapse. Put the comma back, reformat, and it splits again.

> Full write-up, including what to do if your `analysis_options.yaml` already has content in it: [VS Code + Flutter workflow guide](../reference/setup/vs-code-flutter-workflow.md#fixing-the-formatter-dart-38)

### Extract Widget

Cursor on a widget, then `Cmd/Ctrl + .` gives you three extract options:

| Option | Produces | Use when |
|--------|----------|----------|
| Extract Method | A function in the same class | Quick tidy-up |
| Extract Local Variable | A variable in `build` | Rarely |
| **Extract Widget** | A new widget class | **Reusable components. This is the one** |

Extract Widget is the one that matters. When your build method is 200 lines and you can't find anything, this is the fix. We lean on it hard in Project 1.

## IV. Flutter on Your PATH

There are two places you can type `flutter` commands, and they don't always both work.

**VS Code's built-in terminal** (Terminal → New Terminal) almost always works. The Flutter extension hands the SDK straight to that terminal, whether or not your operating system knows where Flutter lives.

**Any terminal outside VS Code** (Command Prompt, PowerShell, macOS Terminal) only works if Flutter is on your system PATH. PATH is the list of folders your OS searches when you type a command name.

Try `flutter --version` in both. If it works inside VS Code and fails outside it, your PATH isn't set.

### The fix

With a Flutter project open, run the command palette and choose **Flutter: Add Flutter SDK to PATH**.

It reports one of three things: the SDK was already there, it just added it, or it couldn't and here are manual instructions. Restart your terminal afterward.

> That command only appears when a Flutter project is open.

### On the lab machines, expect to redo this

The lab PCs restore the C: drive every time you log out. Your Flutter install is on `D:\Profiles\YOUR_USERNAME\` and survives, but the PATH entry pointing at it lives in your Windows user profile on C:, so it gets wiped.

**Your PATH will be gone next time you sit down.** That's normal. Re-run the palette command, which takes five seconds, or just use VS Code's terminal, which works either way. On your own machine you do this once and it sticks.

### If you end up with two SDKs

Install Flutter more than once and VS Code and your terminal can end up on different copies. Then `flutter doctor` reports different things in different windows.

VS Code looks for the SDK in this order:

1. The `dart.flutterSdkPath` setting
2. The project folder
3. The `FLUTTER_ROOT` environment variable
4. Your PATH

**How to check:** the Flutter version in the VS Code status bar is the editor's SDK. Run `flutter --version` in an outside terminal to see the other one. If they disagree, that's your problem.

## V. Build Your Own Stateful App

This is the part that matters most. You're rebuilding the counter yourself, in the empty app, without the starter template's help.

### Step 1: Add state

Inside the `State` class:

```dart
int count = 0;
```

### Step 2: Add a button

```dart
ElevatedButton(
  onPressed: () {},
  child: const Text('Add one'),
),
```

### Step 3: Display the count

```dart
Text('Count: $count'),
```

### Step 4: Make it work

```dart
onPressed: () {
  setState(() {
    count++;
  });
},
```

Run it. Tap it.

### Step 5: Break it on purpose

Remove the `setState` wrapper and try again. Same thing as Tuesday's breakpoint demo: the number is changing, Flutter just doesn't know to repaint.

**That's the whole loop:** state, a widget that reads it, an event that changes it inside `setState`.

> ⚠️ **You will hit a `const` error** the moment you add a property to a widget marked `const`. The fix is to remove the `const` from the parent widget. This is Tuesday's `const` rule biting for the first time, and it won't be the last.

## VII. Debugging Essentials

- **Breakpoint:** click in the gutter left of a line number, run, then trigger the code
- **Hover a variable** while paused to see its value
- **A frozen app is usually a paused app.** Check the status bar
- **Hot reload** (just save) keeps your state
- **Hot restart** (`Cmd/Ctrl + Shift + F5`) drops state and starts over
- Changes to `main()`, global variables, or static fields need a **restart**, not a reload

## IX. Troubleshooting

| Problem | Fix |
|---------|-----|
| `Cmd + .` menu doesn't appear | Cursor is inside the parentheses. Click the widget name |
| `stfu` doesn't expand | Check the Flutter extension is installed and the file is `.dart` |
| Formatter won't split lines | Add a trailing comma after the last argument |
| `const` error after adding a property | Remove `const` from the parent widget |
| Button does nothing visible | You forgot `setState` |
| App looks frozen | Probably paused at a breakpoint |
| Phone is open but the app never appears | You didn't click **Start Debugging** |
| Emulator out of storage | Virtual Device Manager → **Wipe Data** |
| `flutter` works in VS Code but not Command Prompt | PATH isn't set. See section IV |
| PATH worked last week, not today | Expected on lab machines. Re-run the palette command |

## X. Key Takeaways

1. **Use Empty Application** from now on
2. **`stfu` then wire up `home:`** is how nearly every project starts
3. **`Cmd/Ctrl + .` with the cursor on the widget name** is the shortcut you'll use most
4. **`Ctrl + Space`** means you never have to memorise a widget's properties
5. **Trailing commas** control how the formatter lays out your code
6. **Extract Widget** keeps long build methods manageable
7. **No `setState`, no repaint**
