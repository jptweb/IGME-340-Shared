## II. The Pattern You'll Use All Semester

Nearly every project this semester starts the same way: a `MainApp` holding the `MaterialApp`, pointing at a stateful page widget.

### Step 1: Scaffold a StatefulWidget

At the bottom of `main.dart`, type:

```
stfu
```

and press Enter. VS Code expands it into a full `StatefulWidget` plus its `State` class.

Name it `HomePage`.

**What's happening:** a stateful widget is always two classes. The widget itself never changes. The separate `State` object holds the data that does change, and survives rebuilds.

*(`stless` does the same for a StatelessWidget.)*

### Step 2: The Placeholder

The generated `build` method returns a `Placeholder`, which draws a big X on screen.

`Placeholder` is a real widget that exists so your app compiles before you've decided what goes there. You'll use it more than you'd expect.

### Step 3: Replace it with something real

```dart
return Scaffold(
  body: Center(
    child: Text('Week 2B'),
  ),
);
```

### Step 4: Point MainApp at it

```dart
home: const HomePage(),
```

Run it. That's the pattern.

## III. Shortcuts

These are worth learning properly. They're the difference between fighting brackets and moving quickly.

### `Cmd + .` / `Ctrl + .` - the important one

Put your cursor **on the widget name** and press it. You get a menu of things you can do to that widget.

| Action | What it does |
|--------|-------------|
| **Wrap with widget** | Wraps it in something you name |
| **Wrap with Column / Row / Padding / Center / Container** | Shortcuts for the common ones |
| **Remove this widget** | Pulls one layer out of the tree |
| **Extract Widget** | Pulls it out into its own widget class |
| Extract Method | Pulls it into a function in the same class |
| Extract Local Variable | Pulls it into a variable in `build` |

**The most common reason this "doesn't work":** your cursor is inside the parentheses instead of on the widget name. Click directly on the word `Center` or `Column`, not on its properties.

Try it: wrap your `Text` in a `Column`, then add a second child.

```dart
children: const [
  Text('Week 2B'),
  Text('Second line'),
],
```

`children` takes a `List<Widget>`, the same list syntax from dart-02.

### `Ctrl + Space` - see what a widget can do

Put your cursor inside a widget's parentheses and press `Ctrl + Space`. You get every property that widget accepts.

Try it inside `Scaffold(`. You'll see `appBar`, `backgroundColor`, `bottomNavigationBar`, `drawer`, and a long list of others.

**You do not memorize widget APIs.** You ask the editor. This is probably the most useful shortcut in the whole list.

### Formatting and trailing commas

Format with `Option + Shift + F` (Mac) or `Alt + Shift + F` (Windows).

Flutter code nests deeply, so you almost always want each property on its own line. The way you get that is a **trailing comma** after the last item:

```dart
Column(
  children: [
    Text('One'),
    Text('Two'),
  ],          // <- this comma
)
```

Try removing that comma and reformatting to see the difference.

*Note: recent versions of the Dart formatter changed some of this behavior, so it may not always split exactly as described.*

### Extract Widget

Of the three extract options, **Extract Widget** is the one that matters. It pulls a chunk of your tree out into its own widget class.

When your `build` method is two hundred lines and you can't find anything, this is the fix. We lean on it heavily in Project 1.

## IV. Properties Worth Knowing Now

### Kill the debug banner

```dart
MaterialApp(
  debugShowCheckedModeBanner: false,
  // ...
)
```

Removes the DEBUG ribbon from the corner. Do this in every project. Your submission screenshots will look better.

### Add an AppBar

```dart
appBar: AppBar(
  title: const Text('Week 2B'),
  backgroundColor: Colors.amber,
),
```

### Set a theme

```dart
theme: ThemeData(
  colorScheme: ColorScheme.fromSeed(seedColor: Colors.teal),
),
```

Theming gets a proper session later. For now, know it exists.

### Expect `const` errors here

The moment you add a changing property to a widget marked `const`, you'll get an error.

**The fix is almost always: remove `const` from the parent widget.**

This is the `const` rule from Week 1B showing up for real. A `const` widget promises nothing about it can change, so it can't hold something that does.

## V. Build Your Own Stateful App

Now you do it, without the starter template's help.

### Step 1: Add state

Inside your `State` class, above `build`:

```dart
int count = 0;
```

### Step 2: Add a button

Inside your `Column`'s children:

```dart
ElevatedButton(
  onPressed: () {},
  child: const Text('Add one'),
),
```

### Step 3: Display the count

```dart
Text('Count: $count'),
```

### Step 4: Make it work

```dart
onPressed: () {
  setState(() {
    count++;
  });
},
```

Run it. Tap it.

### Step 5: Break it on purpose

Remove the `setState` wrapper so only `count++` remains. Run it again.

The number stops moving, even though `count` is still incrementing. Same thing you saw at the breakpoint last class.

**Put it back.**

You've now built a stateful Flutter app from an empty template. That's the whole loop:

1. State lives in the `State` class
2. A widget reads it
3. An event changes it **inside `setState`**
4. Flutter rebuilds

> **Quick Reference:** [setState Basics](../reference/state-management/setstate-basics.md)

## VI. Debugging Essentials

- **Breakpoint:** click in the gutter left of a line number, run, then trigger the code
- **Hover a variable** while paused to see its value
- **A frozen app is usually a paused app.** Check the status bar
- **Hot reload** (just save) keeps your state
- **Hot restart** (`Cmd/Ctrl + Shift + F5`) drops state and starts over
- Changes to `main()`, global variables, or static fields need a **restart**, not a reload

## VII. Shortcut Reference

Mac first, Windows in parentheses.

| Shortcut | Does |
|----------|------|
| `Cmd + .` (`Ctrl + .`) | Widget actions menu. **Cursor on the widget name** |
| `Ctrl + Space` | Show available properties |
| `Cmd + Shift + P` (`Ctrl + Shift + P`) | Command palette |
| `Opt + Shift + F` (`Alt + Shift + F`) | Format document |
| `F5` | Start debugging |
| `Cmd + Shift + F5` (`Ctrl + Shift + F5`) | Hot restart |
| `Shift + F5` | Stop |
| `F9` | Toggle breakpoint |
| Save | Hot reload |

| Snippet | Gives you |
|---------|-----------|
| `stfu` | StatefulWidget + State |
| `stless` | StatelessWidget |
| `mate` | MaterialApp |

| Command | Does |
|---------|------|
| `flutter doctor` | What's missing from your install |
| `flutter clean` | Strips build output before submitting |
| `flutter pub get` | Restores packages after a clean |
| `flutter pub add <package>` | Adds a package and writes it into `pubspec.yaml` |

## VIII. Troubleshooting

| Problem | Fix |
|---------|-----|
| `Cmd + .` menu doesn't appear | Cursor is inside the parentheses. Click the widget name |
| `stfu` doesn't expand | Check the Flutter extension is installed and the file is `.dart` |
| Formatter won't split lines | Add a trailing comma after the last argument |
| `const` error after adding a property | Remove `const` from the parent widget |
| Emulator out of storage | Android Studio → Virtual Device Manager → **Wipe Data** |
| App looks frozen | Probably paused at a breakpoint |
| Button does nothing visible | You forgot `setState` |

## IX. Key Takeaways

1. **Use Empty Application** from now on
2. **`stfu` then wire up `home:`** is how nearly every project starts
3. **`Cmd/Ctrl + .` with the cursor on the widget name** is the shortcut you'll use most
4. **`Ctrl + Space`** means you never have to memorize a widget's properties
5. **Trailing commas** control how the formatter lays out your code
6. **Extract Widget** keeps long build methods manageable
7. **No `setState`, no repaint**
